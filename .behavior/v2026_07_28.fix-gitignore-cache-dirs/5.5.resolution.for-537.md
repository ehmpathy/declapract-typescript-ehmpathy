# 5.5 — #537 resolved: the `git` ↔ `expo` oscillation

**status: fixed and clamped, 2026-07-30.** #537 asked to *"verify by run, first"* before any fix.
this is that run, plus the fix it justified.

---

## what #537 suspected

`src/practices/cicd-app-react-native-expo/best-practice/.gitignore.declapract.ts` declared the
repo-root `.gitignore`, the same file `git` declares, and sorted **every** line with no ordered
tail. both practices sit in the `app-react-native-expo` use case (`src/useCases.yml`), so both
would apply to the same file.

the suspicion was oscillation: each rewrites the file into a shape the other rejects, forever.

the issue was explicit that this was **inferred from a read, never observed**. it named the
rhachet ↔ git pair as the control to compare against.

## what the run showed

the suspicion was correct, and the defect is **worse than oscillation alone**.

`!` is 0x21 in ascii, below every alphanumeric. so a declaration that sorts every line puts both
negations at the **top** of the file, above `node_modules`. git honors a negation only when it
follows the pattern it negates — so both negations were **inert**.

measured directly, with the pre-fix algorithm restored by hand:

```
✕ should keep the node_modules negations BELOW node_modules
    Expected: < 0
    Received:   21
```

`node_modules` at index 21; its negation at index 0. every test-fixture `node_modules` the tail
exists to protect was silently re-ignored, and **the file still read as correct**.

## the cause: staleness, not disagreement

this is the part the issue could not have known, and it changes what the fix should be.

| what | when |
|---|---|
| expo's declaration authored (`d72788c`) | **2024-09-11** |
| git gained its ordered tail (`7902d41`, #404) | **2026-01-31** |

expo was cloned from git's shape **~17 months before git had an ordered tail**, and never caught
up. so nobody ever decided to sort the negations — the declaration simply predated the concept.

that reframes the fix. it is not a reconciliation between two designs; it is one declaration
brought current.

## the fix

expo now imports the shared algorithm rather than re-derives it:

```ts
import { defineExpectedGitignoreContents } from '../../../utils/defineExpectedGitignoreContents';

const ignoresSortable: readonly string[] = ['android/', 'ios/'];

export const check: FileCheckFunction = (contents) => {
  expect(contents).toEqual(defineExpectedGitignoreContents({ contents, ignoresSortable }));
};

export const fix: FileFixFunction = (contents) => {
  return { contents: defineExpectedGitignoreContents({ contents, ignoresSortable }) };
};
```

all three declarers of the repo-root `.gitignore` — `git`, `rhachet`, `expo` — now route through
one source. each declares only its own `ignoresSortable`, the part they legitimately differ on.

**consumers see no content change.** an expo repo already received the ordered tail from `git`;
what changes is that expo no longer **hoists** it.

### the split in what stayed green is itself the result worth the record

under the injected defect:

| assertion | verdict |
|---|---|
| `should be a fixed point` — `fix(fix(x)) == fix(x)` | 🟢 **green** |
| `should satisfy its own check` | 🟢 **green** |
| all 9 cross-declarer convergence assertions | 🔴 red |
| `should keep the node_modules negations BELOW node_modules` | 🔴 red |
| the declared-shape snapshot | 🔴 red |

**the defective declaration is a perfect fixed point.** it converges with itself and passes its
own check on its own output. it simply cannot converge with any other declarer.

that is a reproducible demonstration that **idempotency and convergence are distinct properties**
— the claim `term=convergence._.choice.reason.md` was coined to make. it was argued from a wild
instance; it is now measured on demand.

it is also the practical caution for the next author: **a green per-declaration suite is not
evidence of convergence.** it does not exercise the property at all.

## an error worth the record

my first draft of the clamp copied rhachet's assertion `git's fix output should satisfy expo's
check`. 3 of 14 failed — **the test was wrong, not the code.**

the two pairs are not symmetric:

| pair | relation of declared sets | consequence |
|---|---|---|
| rhachet ↔ git | rhachet's `.agent/.cache/` is a **subset** of git's | git's output alone satisfies rhachet's check |
| expo ↔ git | `android/`, `ios/` are **disjoint** from git's | neither output alone satisfies the other |

convergence never claimed one declarer alone suffices. it claims the file **settles** once both
have run, and stays settled in either order. the assertions were rewritten to that claim.

recorded as a `.note` in both suites, so the next author does not copy an assertion across
without the check.

## what stays open

**#537 is resolvable.** its hypothesis is verified, its cause diagnosed, its fix shipped, its
clamp proven to bite.

one durable gap it named is **not** closed by this work, and should carry forward rather than
close with it:

> no build step stops a fourth declaration from a re-derivation.

the cross-declarer clamps catch it once the declaration exists and someone runs the suite. a lint
rule or a single-owner registry would catch it at author time. that is the durable guard, and it
is its own wish.
