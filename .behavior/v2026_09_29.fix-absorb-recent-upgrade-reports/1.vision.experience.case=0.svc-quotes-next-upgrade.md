## .narrative

an agent in svc-quotes runs the upgrade route on the release this round ships. the repo carries
uni-time imports, one `simple-leveled-log-methods` wrapper, 9 `withDatabaseConnection` ops, a stray
`it.only` from a debug session, an enrolled actor under `.agent/.actors/`, and lambda handlers on
`sdk-aws-lambda@0.6`.

it runs `plan`. files are red that used to be silent: the logs wrapper, and each
`withDatabaseConnection` importer. it runs `apply`. the uni-time imports now read `iso-time` and
`iso-time` sits in `dependencies`. above each flagged import sits a `// @declapract:review:` line —
one names `sdk-logs` `genLogMethods`, the others name the move of `dbConnection` from input to
context. it moves the logs wrapper and the 9 ops by hand, as the markers say — a known list, not a
hunt through tsc errors.

`pnpm fix` touches none of the templates. a second `apply` changes zero files: no file has two
owners any more, and no declared fix is left unapplied.

`tsc` passes; `jest.integration.env.db.ts` no longer trips `strictest`. `test:lint` goes red once,
at the `it.only`, which names `noFocusedTests` and the line; the agent removes it. depcheck and jest
ignore `.agent/.actors/`, so the laptop run matches ci. the integration suite sources keyrack once,
and the box's ec2 instance role cannot stand in for a keyrack credential.

the lambda handlers move too: the practice floors at `sdk-aws-lambda@0.7.1`, so apply rewrites each
pre-0.7 handler to `.forApiGateway(` / `.forAsk(` with `{ payload }`, and drops a leftover
`sdk-aws-lambda@0.7.0` patch and its `patchedDependencies` key. the uni-time `Uni*` identifiers
became their `Iso*` twins in the same apply that swapped the import. the full handler walk is case=8.
