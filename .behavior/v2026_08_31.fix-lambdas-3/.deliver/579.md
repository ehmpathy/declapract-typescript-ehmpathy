## the fix — replace the dead serviceClientStage with the ancient/contemp target helper

`environments/best-practice/src/utils/environment.ts` exported `serviceClientStage`, a dead value
(a grep of a real consumer finds zero `src/` usages). #579 asked to replace it with an `access`-aware
peer-target helper. the corrected name (per the 2026-08-31 decision, which supersedes #579's original
`sdkLambda{Ancient,Contemp}EnvAccess`) is `sdkAwsLambdaEnvAccess{Ancient|Contemp}` — noun-adj order
(`rule.require.order.noun_adj`), `sdkAwsLambda` prefix aligned with the `sdk-aws-lambda` package.

**landed shape** (`environments/best-practice/src/access/sdks/sdkAwsLambdaEnvAccess.ts`):
- `type LambdaEnvSlug = EnvironmentAccessTier | 'dev'` — a first-class `dev` member, so the legacy
  slug flows with a compiler-tracked type. NO `as`-cast that would lie a `dev` value through a type
  that forbids it — the exact silent fault this transition exists to kill (vision case=4).
- `sdkAwsLambdaEnvAccessAncient()` → `access === 'prod' ? 'prod' : 'dev'` — addresses a peer that
  emits `-dev-` only (the legacy slug below prod).
- `sdkAwsLambdaEnvAccessContemp()` → `access` direct — addresses a `-prep-` peer, or self.

**the helper choice IS the migration ledger:** `grep AccessAncient` lists every peer still on `-dev-`;
a per-peer migration is a one-line `Ancient → Contemp` flip; `grep → 0` org-wide is the endpoint that
retires the ancient branch + the divergent `stage` together.

alongside it, `environment.ts` itself collapsed: `serviceClientStage` is gone and
`export const stage = envStatic.access` (no divergent slug). so the value-tier of the north-star
(the `stage`→`access` collapse in code) is complete for this practice.
