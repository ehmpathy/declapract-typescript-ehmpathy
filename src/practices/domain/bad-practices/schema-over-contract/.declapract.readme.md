a published contract (`src/contract/**`) that refers to a domain object via `X.schema`, or via a
bare `X.contract` with no call.

- `X.schema` validates the data but emits no dobj identity into the json-schema a consumer reads.
  `X.contract()` is the same schema stamped with the dobj's name and keys, and it composes the same
  way: `z.array(X.contract())`, `X.contract().nullable()`
- since domain-objects@0.34.0, `contract` is a getter that returns a function to CALL on the class,
  so a bare `X.contract` is a type error. a detached receiver (`const c = X.contract; c()`) is a
  compile error by design, too

the fix rewrites each such member of a name imported from a `domain.objects` path to
`X.contract()`. it leaves `X.schema.parse(…)` (internal validation) and `typeof X.schema` alone.
