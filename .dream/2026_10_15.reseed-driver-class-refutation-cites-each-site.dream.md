# 🌙 dream: a driver's class refutation must cite each site's file:line

kind: reseed · owner: ehmpathy/rhachet-roles-bhrain (role=driver) · caught 2026-10-15

## .the cue that fired

a `.taken` refuted ten decode-friction blockers as one class ("these are those names"). a foreman
read each site and found one that was not behind a name, and it gated a security fix (the ec2
metadata bar in a shipped `useKeyrack` template). a per-site re-check then found four more of the
ten that sat inline in a `fix` or `defineExpected*` body.

## .the gap, precisely

`rule.always.converge-with-reviewers.via-a-taken-per-point` requires a `.taken` per POINT, and a
`[REFUTE]` with cited evidence. it does not say that a refutation which groups several points must
cite each point's own file:line. a class refutation satisfies the letter (one refutation, evidence
named) while it hides the one site that differs, and the reviewer cannot re-run to catch it once
its budget is spent.

## .the shape of the fix

a cue row in `rule.always.converge-with-reviewers.via-a-taken-per-point` (or a peer
`rule.forbid.class-refutations-without-sites`):

| when… | then… |
|---|---|
| you would refute several points as one class | cite each site's file:line and what sits there; a class claim the sites do not each bear out is a hidden concession |

blocker: a grouped `[REFUTE]` with no per-site file:line.

worked case: `declapract-typescript-ehmpathy` route `v2026_09_29.fix-absorb-recent-upgrade-reports`,
stone 5.1 round i004, lane `mech-decode-friction-slice-nz` (r010), blocker 5.

## .why it is not done in this round

the rule lives in `rhachet-roles-bhrain`; this route may not work in other repos (S5).
