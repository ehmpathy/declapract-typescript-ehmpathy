# 🌙 dream: raise the typescript floor to 7 in typescript-expo once an expo sdk expects it

kind: feat · owner: declapract-typescript-ehmpathy · caught 2026-11-20

## .the cue that fired
the ts7 probe moves the floor in typescript-node only, because expo sdk 56–58 `expo install --check` expects `typescript ~6.0.3`.

## .the gap, precisely
expo repos stay on typescript 6 and miss the ts7 typecheck speedup. expo tracks ts7 support (expo/expo#47627; require-utils "support typescript 7.1 for transpilation").

## .the shape of the fix
when an expo sdk's `expo install --check` expects `typescript` 7.x: raise the floor in `typescript-expo/best-practice/package.json`, bump the expo sdk floor alongside it, and cover both with `typescript-expo/package.json.declapract.integration.test.ts`.

the `typescript-expo/best-practice/tsconfig.json` template still sets `"baseUrl": "."` with bare `paths` (`"src/*"`). typescript 6.0 already rejects `baseUrl` (TS5101, an error unless `"ignoreDeprecations": "6.0"`), and 7.0 removes it (TS5102). drop `baseUrl`, prefix each `paths` value with `./`, and lift `typescript-node/bad-practices/tsconfig-options-removed-in-ts7` to `typescript-any` so expo adopters get the same automatic fold. both shapes are valid on 5.4.5 and 6.0.3, so this half need not wait for an expo sdk.

the lift moves seven jsonc utils (~380 lines) to `typescript-any`; take two reshapes with it, since the move touches each file anyway:
- read tsconfig spans with `ts.parseJsonText` from `@typescript/typescript6` in place of the hand lexer (`asJsoncView`, `getOneJsoncDirectMatch`, `getIndexOfJsoncObjectClose`, `getOneJsoncObjectSpan`, `getJsoncCompilerOptionsSpan`). each property comes back with exact `start`/`end`, so `asSplicesToRemoveEntry` folds to neighbor spans: cut `[prev.end, prop.end)` when a prior property exists, else `[prop.start, next.start)`. `asTextSpliced` stays. the extant fold suites prove no output moved
- the three typecheck clamps (`persist-with-rds/database-client`, `persist-with-rds/database-wrappers-typecheck`, `tests-node/catch-cause-narrowed`) hold their options twice: `COMPILER_OPTIONS` as api enums, `TSCONFIG_OPTIONS` as strings. derive the enums with `ts.convertCompilerOptionsFromJson(TSCONFIG_OPTIONS, dir)`; then drop the 6.0 `[t0]` run where no 6.0 adopter takes the practice (all three sit in node usecases), so the 7 binary `[t1]` alone grades each fixture

## .why it is not done in this round
no stable expo sdk accepts typescript 7 today; a floor raise now fails every expo repo's `expo install --check`. the two reshapes swap the reader under every ts7 fold and every typecheck clamp; each is its own reviewed change, cheapest at the lift that already moves those files.
