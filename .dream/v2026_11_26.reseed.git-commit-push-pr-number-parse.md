# 🌙 dream: git.commit.push reads the pr number and the push state right

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy, role=mechanic, skills git.commit.set + git.commit.push
- caught 2026-11-26

## .the cue that fired

`rhx git.commit.push --mode apply --auth as-human` opened pr 843, then printed `pr: pr #843` and `1 (created)` on two lines. its own watch step refused: `--which must be a pr number; got '843\n1'`.

before that, `rhx git.commit.set --push` with an absent ehmpath token printed `your commit is pushed`, but its own tree said `push: held`. `git status` showed the branch still only on the local side, ahead of `origin/main`.

## .the gap, precisely

1. the as-human pr-open path captures a second line (likely a count or exit echo) into the pr number var
2. the absent-token hint claims a push that never ran

## .the shape of the fix

1. take only the first numeric token from the pr-open output (or read `.number` from `gh pr view --json number`); add a clamp test on the as-human path
2. word the absent-token hint by the real push state: `your commit is local; to push and open its pr, either:`

## .why it is not done in this round

the skills live in another repo; this pr only fixes the timestamp hook.
