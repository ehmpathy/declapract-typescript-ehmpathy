# environments

a critical part of an application's environment is its `access` — which deployment's resources
the runtime may reach, and with what weight.

ehmpathy recognizes three standard tiers in which applications run throughout their development cycle
- `prod` — a deployed production stack the business depends on, which serves real customers
- `prep` — a deployed pre-production stack where applications interact for cross-service tests
- `test` — an ephemeral, primarily local, developer-only tier for local code

`access` is the one canonical axis (`test | prep | prod`). the runtime reads it via
`getEnvironment.static().access` (sdk-environment), which derives it from the `ACCESS` env var, then
the aws account, then `NODE_ENV`.

# the access axis, and how a caller reaches a peer lambda

one fact — which deployment a runtime reaches — is named by `access` (`test | prep | prod`).
below prod the deployed resource names carry a legacy `dev` label, so an `access=prep` runtime must
reach resources named `-dev-`. that mismatch (`access=prep` ⟺ deployed name `dev`) is a
compiler-invisible fault: both are `string`, so a wrong reference is green at build and red only at
runtime, against a deployed resource.

`src/access/sdks/` holds the transitional bridge that lets a caller reach a peer lambda by the slug
the peer actually publishes at, per callee — one procedure per file (`rule.require.single-responsibility`):

- `sdkAwsLambdaEnvAccessAncient.ts` → `sdkAwsLambdaEnvAccessAncient()` — emits the legacy `dev` slug
  below prod. for a peer still published under `-dev-` only. carries the shared `LambdaEnvSlug` type.
- `sdkAwsLambdaEnvAccessContemp.ts` → `sdkAwsLambdaEnvAccessContemp()` — emits the access direct.
  for a `-prep-` peer, or self.

## the migration ledger

the helper choice IS the ledger: `grep AccessAncient` across a repo lists every peer still on the
ancient (`-dev-` only) slug. a per-peer migration is a one-line `Ancient → Contemp` flip. once the
org's last `Ancient` import is gone, the ancient branch, the `-dev-` publish, and the divergent
`dev` slug retire together — the helper is scaffold built to be torn down.

`ancient`/`contemp` is `sdk-aws-lambda`'s own vocabulary (it names the payload-format axis there);
the `EnvAccess` qualifier disambiguates this slug-axis sense from that homograph.

## the helper is a shared primitive

the helper is a pure, shared target-resolution primitive that a consumer wires when it migrates a
peer, so a fresh consumer holds it with no call site yet. the caller-side wire-up and the helper's
retirement both land at the north-star endpoint.

the full transition design (dual-publish, the ledger, the deletion endpoint) is the north-star of
the fix-lambdas wish — see `.behavior/v2026_08_31.fix-lambdas-3/1.vision.yield.md` in this repo.
