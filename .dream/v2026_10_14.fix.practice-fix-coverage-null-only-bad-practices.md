# 🌙 dream: the fix-coverage harness proves naught for a bad-practice with no template

- kind = fix
- owner = ehmpathy/declapract-typescript-ehmpathy
- caught 2026-10-14

## .the cue that fired

a census of the 63 declarations changed by `v2026_09_29.fix-absorb-recent-upgrade-reports` marked
each fix as "covered by the global harness". read closer, ~25 of those marks are hollow.

## .the gap, precisely

`src/practiceFixCoverage.declapract.integration.test.ts` case2 feeds each fix a candidate list:
best-practice `[null, template]`, bad-practice `[template]`, where `template` is the plain file
beside the declaration or `null`. most bad-practices ship no template, so the harness runs
`fix(null)` alone, which returns `{ contents: null }` or `{}` at once. the `fix(fix(x)) === fix(x)`
and `check(fix(x))` assertions then hold trivially. same for best-practice declarations with no
template whose `fix(null)` is a no-op (`keyrack.yml`, `tests-expo/package.json`,
`package-json-order/package.json`).

evidence: the rds-jobs bad-practice fix threw on its own output (`fix(fix(x))` → "could not find
the rds-jobs anchor") and the harness stayed green, since it never fed that fix a real input.

## .the shape of the fix

give each fix a real sample input the harness can read:
- a convention: `<declaration>.sample` (or `.test/sample/<target>`) beside each declaration with a
  fix — the BEFORE shape the fix repairs
- the harness adds the sample to the candidate list; a declaration with a fix and no sample fails
  case1-style, onto an allowlist ledger that may only shrink (the `parsePackageJSONAdoption` ratchet
  shape)
- seed the ledger with today's sample-less set, then drain it practice by practice

## .why it is not done in this round

safe, but not clean: a sample per declaration touches ~25 practices this route did not open, plus a
new harness convention. the route closed the gap for every declaration it touched with per-file
twice-applied tests instead. fulcrum F96 records the deferral.
