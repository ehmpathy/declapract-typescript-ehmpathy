# simple-lambda-client

## what

detects and transforms simple-lambda-client usage to sdk-aws-lambda.

## why

sdk-aws-lambda provides modern lambda client patterns:
- context-based configuration
- trail.exid auto-propagation through call chain
- better cache support

## transforms

| old | new |
|-----|-----|
| `import { invokeLambdaFunction } from 'simple-lambda-client'` | `import { sdkAwsLambdaAskAncient } from '@src/access/sdks/sdkAwsLambdaAskAncient'` |
| `invokeLambdaFunction({ service, function, stage, event, cache })` | `sdkAwsLambdaAskAncient({ which: { service, function }, event }, { log, cache: { response: cache } })` |

`sdkAwsLambdaAskAncient` (shipped by node-service) sends what simple-lambda-client sent: a flat
event, to the peer's `-dev-` name below prod. it binds the ancient address and the ancient payload
together, so neither can be set alone (#631). once a peer publishes contemp, swap the call for
`askLambdaEndpoint` with `env.access: sdkAwsLambdaEnvAccessContemp()`.

## limitations

- a call whose argument is not an object literal is renamed only; tsc names the shape to fix
- `logDebug` is dropped — the logger rides in the context

## example

before:
```ts
import { invokeLambdaFunction } from 'simple-lambda-client';

const result = await invokeLambdaFunction({
  service: 'svc-users',
  function: 'getUser',
  stage: 'prod',
  event: { userId: '123' },
});
```

after:
```ts
import { sdkAwsLambdaAskAncient } from '@src/access/sdks/sdkAwsLambdaAskAncient';
import { log } from '@src/utils/logger';

const result = await sdkAwsLambdaAskAncient(
  {
    which: { service: 'svc-users', function: 'getUser' },
    event: { userId: '123' },
  },
  { log },
);
```
