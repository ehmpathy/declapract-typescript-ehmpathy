# tests-any dev-tool-in-dependencies bad practice

## what

detects a test tool that tests-any declares in `devDependencies` (`jest`, `@jest/globals`,
`@types/jest`, `test-fns`, `tsx`, `esbuild-register`) when it also, or only, sits in
`dependencies`.

## why

the tests-any best-practice floor raises the `devDependencies` entry alone. a stale duplicate in
`dependencies` wins the install, so plan reports the floor met while the old release lands. jest
then fails to load a reporter or setup that the old release predates.

## fix

removes each such tool from `dependencies`. where `devDependencies` lacks it, the version moves
there; where `devDependencies` already holds it, that entry wins and the best-practice floor
raises it.
