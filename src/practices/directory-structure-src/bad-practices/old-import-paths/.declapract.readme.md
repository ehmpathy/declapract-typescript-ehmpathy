imports referencing old directory structure paths should be updated

old → new:
- `src/data/dao` → `src/access/daos`
- `src/data/clients` → `src/access/sdks`
- `src/data/` → `src/access/`
- `src/domain/objects` → `src/domain.objects`
- `src/domain/` → `src/domain.objects/`
- `src/logic/` → `src/domain.operations/`

this bad practice checks all source files for imports using the old paths and fixes them.

## two-pass migration

a file still under a deprecated src dir is **deferred** this pass — the import rewrite is held to
the next `declapract fix` pass. that is because the peer `old-*-dir` bad-practices RELOCATE the file
this pass; a relocate plus an in-place rewrite of one file in one apply throws ENOENT on the unlinked
source. so a consumer who migrates a repo that still holds `logic/` / `data/` / etc. must **run
`declapract fix` twice**: pass 1 relocates the files, pass 2 rewrites their imports at the new path.
the guard is shared with `typescript-any/relative-imports` via
`src/utils/isDeferredToDeprecatedDirMove.ts`, so the two rewriters defer the same files.
