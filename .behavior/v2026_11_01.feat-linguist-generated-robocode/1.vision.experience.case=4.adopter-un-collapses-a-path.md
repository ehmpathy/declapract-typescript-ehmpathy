# case=4: adopter un-collapses a path

cells: ad13 · ad14 · ad15 (sharp · critipath) · rv11 (the reviewer side: happy · critipath)

## .narrative

`svc-jobs` hand-tunes its generated query functions in `src/access/daos/.generated/`. reviewers must read those. mira adds one line to `.gitattributes`:

```
src/access/daos/.generated/** -linguist-generated
```

git takes the last line that matches a path. so this line must sit below the practice's `src/access/daos/**/.generated/** linguist-generated`.

the trap: the git practice's fix puts repo-own lines FIRST, then the managed block. under that order the practice line lands last and wins. mira's override goes inert, and no tool says so.

the fail-safe is prevention, not a message: the silent loss cannot occur, since no layout the util emits puts a repo-own line above a managed one. the clamp asks git (`check-attr`), not the line order, so a regression goes red even where the file still looks right.

after: the shared algorithm puts managed sections first and repo-own lines last. her override sits at the bottom, wins, and stays there across every re-apply and upgrade. `git check-attr linguist-generated src/access/daos/.generated/queryFunctions.ts` reports `unset`.

## .bdd sketch

