# case=12 — an rds service connects over verified tls and provisions its params

critipath · feel: happy, with a sharp stop at params absent from the derived names · cells: A=adopter × B1/B3/B7 × C1/C2/C3 × D1, A=maintainer × B1 · issues: #652, #637, #638, #683, #686 (and the older #562, #539, #519, #523, which close with #638)

## .narrative

before: svc-chat's config named the tunnel bastion and cluster as strings, while its own schema
demanded objects, and the cluster value was the database name, not the cluster. no test parsed the
config against the schema, so the mismatch shipped twice. the config read ssm params at the derived
path, but `resources.parameters.ts` still declared the old dotted names with a `dev` slug, so the
provision declared one set of names and the app read another. and the pg client connected with no
tls at all.

after: the config names `bastion: { exid }` and `cluster: { name }`, with the cluster name derived
from the cluster host (an optional variable overrides it), and apply merges it deep, so the repo's
own keys survive. this repo parses every emitted config against the emitted schema. the provision
declares the three derived param names under `/{org}/{project}/{config}/`, the same names the config
reads. every pg client connects with `ssl` that verifies the rds CA and the host.

the sharp stop: the plan and apply roles already hold the grant for the derived names, but an
adopter whose params still sit only at the old dotted names has no value at the new ones. its
`provision` fails loud at the absent param, and the readme plus a review marker on
`resources.parameters.ts` name the copy step. where the roles were also renamed, the readme carries
the map — `cicd/for-plan` ← `admin`, `cicd/for-apply` ← `admin`, `crud` ← `service` — and each
`removed{}` forget of an admin/service param names its target (#686). the copy is a manual
`aws ssm` step until the paved skill (ghlitch#129) ships.

prep stays as the template's own provision makes it: `deploy.database.sh` creates prep users with
`__CHANG3_ME__`, so the old-dev-config-location fix keeps that placeholder, and prep.json accepts
either the placeholder or `$.at(aws::param)` at each password, so an adopter who seeded real prep
secrets keeps them (#683).
