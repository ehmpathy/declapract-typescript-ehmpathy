# case=5 — the-fix-cannot-create-a-violation

**actor** practice-maintainer · **feel** SHARP · **care** critipath · D51, the one-way door

## narrative

D51: the `domain` practice requires `src/domain/objects/index.ts`; the kin `directory-structure-src`
practice forbids every file under `src/**/domain/**`. both ship in `typescript-project`. today
`domain-dir` carries a rename `fix` — so on a pre-migration repo, `declapract apply` MOVES the file,
which turns a `domain` violation into a `domain-dir` violation. the end state is terminal: no fix has
content to re-create the file at a non-forbidden path, and a hand-repair lands it back in the
forbidden directory, which the next `apply` moves straight back.

after this wish, two things change. first, the `domain` practice is migrated to the
`src/domain.objects/` layout its kin enforces, so the contradiction is gone. second — the durable
half — declapract gains a guard: **a `fix`'s output path is checked against every kin practice in
the use case, and a fix that lands the file in a forbidden state is refused, not applied.** the
one-way door is bolted shut.

the aha: **a fix that turns one violation into another is a one-way door.** the guard makes the door
impossible to build, so no future practice pair can ship the same trap.

## bdd

```
given a pre-migration repo in typescript-project
  and `domain` requires src/domain/objects/index.ts                                            # ✅ D51 evidence
  and `directory-structure-src` forbids src/**/domain/**
  and domain-dir carries a rename fix (/domain/ → /domain.objects/)

when [t0] the pre-wish `declapract apply` runs
  then domain-dir MOVES the file                                                               # today
  and post-move: domain 🔴 (file absent), domain-dir ✅ — a terminal, unrepairable state
  and a hand re-create lands back in the forbidden dir; the next apply moves it back

when [t1] the post-wish `domain` practice (migrated to src/domain.objects/) is applied
  then domain requires src/domain.objects/index.ts (the kin-enforced layout)
  and domain ✅ and domain-dir ✅ can hold simultaneously — no contradiction

when [t2] a maintainer authors a NEW fix whose output another kin practice forbids
  then declapract evaluates the fix's OUTPUT path against every kin declaration
  and it REFUSES the fix (or warns), and states the kin practice that would be violated
  and the repo is never walked into the forbidden state

when [t3] a lint runs over the practice set itself (no repo needed)
  then a `best-practice/` path matched by any `bad-practices/` glob in the same use case → 1 blocker
  and D51's contradiction would have been caught before it ever shipped
```

## the fail-safe

the sharp edge — a repo walked into a terminal, unrepairable state — is prevented, not merely
reported. `[t2]` is the runtime guard (a fix cannot create a violation); `[t3]` is the author-time
guard (the contradiction is detectable from the declarations alone, no repo required). together they
show the two-layer pit-of-success the wish's durable guards yield (#574): make the bad state
impossible to reach, and detect the source-level contradiction before it ships.
