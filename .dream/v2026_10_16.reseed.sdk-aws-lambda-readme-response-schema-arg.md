# 🌙 dream: sdk-aws-lambda readme names the wrong argument of `asApiGatewayResponseSchema`

- kind = reseed
- owner = ehmpathy/sdk-aws-lambda
- caught 2026-10-16

## .the cue that fired

the #650 real-use clamp copied the readme's `forApiGateway` example and failed at load with
`TypeError: Cannot read properties of undefined (reading 'optional')`.

## .the gap, precisely

- the 0.7.2 readme shows `asApiGatewayResponseSchema({ body: z.object(...) })`, in the
  `forApiGateway` example and in the body-less response section
- the shipped function reads `input.payload`
  (`dist/domain.operations/genLambdaEndpoint/genLambdaEndpoint.forApiGateway/asApiGatewayResponseSchema.js:62`),
  and its jsdoc says `payload` is the name on purpose
- so every reader who copies the readme gets a runtime throw at module load. the types did not
  catch it in a ts-jest run here

## .the shape of the fix

in the sdk-aws-lambda readme, replace `asApiGatewayResponseSchema({ body: ... })` with
`asApiGatewayResponseSchema({ payload: ... })` in each example. also check the `{ body: x }` row of
the wire-response table, which names the return key of `invoke`, against `ApiGatewayResponse`.
add a doc test that compiles the readme examples, so the drift cannot return.
