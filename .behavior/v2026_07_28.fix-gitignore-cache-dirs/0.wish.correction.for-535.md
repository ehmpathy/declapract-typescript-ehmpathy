### 2. the third acceptance criterion is false as written

> an upgrade run against a repo that already carries a line leaves the file byte-identical
> (idempotent — prove it, do not assert it)

the main clause and the parenthetical name **two different properties**, and only one is true:

| | claim | true? |
|---|---|---|
| **A** | carries the line ⇒ untouched — `fix(x) == x` | ❌ **false** |
| **B** | the fixed point — `fix(fix(x)) == fix(x)` | ✅ true, and provable |

**why A is false.** `defineExpectedContents` always sorts, and always relocates the `node_modules`
negations to the end. so a `.gitignore` of:

```
node_modules
.cache/
*.log
```

**already carries `.cache/`** — the criterion's stated precondition — yet `fix` rewrites it to the
full sorted set with negations last. not byte-identical. A holds only for a file already in
canonical form, which is a much narrower claim than "carries a line".

**why this matters practically.** a clamp written against A fails on every realistic input, and the
natural response to that failure is to weaken the assertion until it passes — which is how a test
that proves nothing gets born.

**the amended criterion:**

> an upgrade run against an already-conformant repo leaves the file byte-identical — i.e. `fix` is
> a **fixed point**: `fix(fix(x)) == fix(x)`. and `check` must **pass** on `fix`'s own output, so
> `declapract fix` settles instead of re-flagging the file on every run.

that second sentence is the half most easily dropped: idempotency here has **two** clauses, and the
loop is governed by `check`, not by `fix`. a perfect fixed point still re-flags forever if `check`
keeps throwing on it.
