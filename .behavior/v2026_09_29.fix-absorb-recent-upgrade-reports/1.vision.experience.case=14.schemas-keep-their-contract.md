# case=14 — schemas keep the contract they had, on the zod the repo actually resolves

critipath · feel: happy · cells: A=adopter × B2/B3 × C3 × D1 · issues: #624, #629, #654

## .narrative

before: svc-chat's `dependencies.zod` read 4.0.0, so the practice check passed — but a
`pnpm.overrides.zod` of 3.23.8 meant pnpm installed 3.23.8. and the joi migration had turned
`Joi.string().uuid()` into `z.string().uuid()`, which on zod 4 is the strict rfc check. ids the old
joi contract accepted, such as `beefbeef-beef-beef-beef-beefbeefbeef`, were now rejected at runtime.

after: a pnpm bad-practice flags any override below the dependency it shadows and raises it, so the
zod the check reads is the zod pnpm installs. the joi migration maps `.uuid()` to `z.guid()`, which
accepts what joi accepted; a uuid version option maps to `z.uuidv4()`. files that still carry the joi
review marker get the same fix on the next apply; a schema an author chose strict later is left alone.

## .[tn] sketch

```
given('[case1] a repo with dependencies.zod 4.0.0 and pnpm.overrides.zod 3.23.8')
  when('[t0] declapract apply')
    then('pnpm.overrides.zod is 4.0.0')
  when('[t1] declapract apply again')
    then('zero files change')

given('[case2] a joi schema Joi.string().uuid().required()')
  when('[t0] declapract apply')
    then('the zod schema is z.guid()')
    then('beefbeef-beef-beef-beef-beefbeefbeef parses')

given('[case3] a zod schema z.uuid() in a file with no joi review marker')
  when('[t0] declapract apply')
    then('the schema is untouched')

given('[case4] a joi repo on sdk-aws-lambda 0.7.1, which pins zod 4.4.3 (#654)')
  when('[t0] declapract apply')
    then('dependencies.zod is 4.4.3, so one zod identity resolves, never a ^3 beside a 4')
```

## .the aha

a floor check must read what the package manager resolves, not what the manifest hopes.
