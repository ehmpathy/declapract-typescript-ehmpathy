## FULCRUM 1 — `.npmrc` forced-hoist-as-default: forced findsert vs opt-in offer

**status:** OPEN — awaits an explicit wisher decision. best-guessed + clean-rework flagged.

**the decision.** should an expo consumer's `.npmrc` get `node-linker=hoisted` FORCED by default
(the current behavior), or should the hoist be OFFERED only when a repo hits a native-module-lookup
failure (isolated-first, pnpm's own modern default)?

**the best-guess in place (why it is defensible).** the current default is `node-linker=hoisted`,
forced as an append-only findsert unless the repo holds an explicit `node-linker=isolated` opt-out.
- it matches `create-expo-app`'s OWN default for pnpm — the least-surprise choice for a fresh expo
  repo (`howto.pnpm-expo-hoisted-linker.md`).
- it is the documented, prod-proven fallback for the metro/EAS native-lookup errors an isolated
  install can still cause (`ahbode/app-hometools-native` PR #55 shipped exactly this).
- the opt-out is already built (`src/utils/defineExpectedNpmrcContents.ts` — `hasOptedOutLinker` /
  `wantsHoist`): a repo that prefers pnpm's isolated default sets `node-linker=isolated` and the
  hoist block is skipped, no rival directive emitted. so an isolated-first consumer is ALREADY
  served today; only the DEFAULT is the open question.

**why it is NOT flipped here.** a flip of the default (force → opt-in) is a POLICY choice above the
blueprint's authority — a wisher decision, per `rule.always.defer-fulcrums-to-last`. the vision
records it as assumption #1 (the key external assumption), and the brief states "the forced findsert
stands until the wisher rules." every concrete BUG on this surface (double directive, absent opt-out)
is fixed and clamped; only the policy is reserved.

**the clean rework, if the wisher selects isolated-first.** a one-line swap in
`defineExpectedNpmrcContents.ts`: drop `wantsHoist`'s default-true, gate the hoist block on an
explicit opt-IN instead (`node-linker=hoisted` present → emit; else skip). no downstream teardown,
no consumer file poisoned — the declaration is an append-only findsert that never strips a line, so
the reversal is a clean re-scope, not a migration. the block + the `howto.pnpm-expo-hoisted-linker.md`
brief stay for the repos that opt in.

**the ask of the wisher:** a yes/no —
- **KEEP forced-hoist default** (current) — least surprise for a fresh expo repo, prod-proven fallback; OR
- **FLIP to isolated-first** (opt-in hoist) — aligns with pnpm's SDK 54+ default, hoist offered only on native-lookup failure.

either way the opt-out/opt-in mechanism already exists; this is purely which way the default points.
