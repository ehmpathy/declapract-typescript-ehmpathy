## .narrative

svc-quotes runs its upgrade. it still imports `@ehmpathy/uni-time` in seven files and
`simple-leveled-log-methods` in one wrapper.

before: `apply` rewrites the seven imports to `iso-time`, deletes `@ehmpathy/uni-time` from
`package.json`, adds no `iso-time`, and drops `simple-leveled-log-methods` while the wrapper still
imports it. `tsc` fails twice: `Cannot find module 'iso-time'`, `Cannot find module
'simple-leveled-log-methods'`. the agent spends a stone to rediscover what svc-chat already reported.

after: the uni-time fix writes `iso-time` into the same section `@ehmpathy/uni-time` held. the
leveled-term practice now owns a `src/**/*.ts` check, so `plan` lists the wrapper by path before any
dep leaves. the agent reads one red line, moves the import, and `tsc` passes.

two older reports ride the same class. the joi→zod fixer emits plain `z.number()` where joi coerced
a string, so a db-hydrated number fails validation at runtime (#548); its review marker now names
`z.coerce.number()` beside the date bullet it already carried. and a repo that never ran the joi
fixer keeps a zod copy beside sdk-aws-lambda's exact 4.4.3, so `tsc` runs out of memory on two
type graphs (#545); `pnpm.overrides.zod` now pins the one copy.

#644's walk: svc-chat's `apply` bumped `with-simple-cache` to `0.17.3` and every cached handler
failed tsc, with no pointer. after: `plan` lists the handler by path in the same run that bumps the
floor, and the marker names both contract changes — the options rename and the async `get()` — so
the agent fixes the two tsc errors it is about to see, in the file it was told to open.

sharp edge, fail-safe: the old wrapper put `dbConnection` in the **input**
(`findById({ id, dbConnection })`); `withDatabaseContext` takes it in the **context**. every op
body and every call site changes shape, so a mechanical rewrite would break the build — the exact
failure #626 reports. the practice stops loud and names the move; it never half-migrates.

why a marker, not a message: declapract core reads a practice's `.declapract.readme.md` but no
output path prints it, and a bad-practice check signals detection by return, with no text. so
`plan` can name the practice and the file, never the replacement. the paved answer is the
idempotent `// @declapract:review:` line the `environments/old-stage-enum` fixer already stamps —
the instruction lands in the file, beside the line tsc will name.

#659's walk: #605 renamed the connection template, so svc-notifications' upgrade wrote
`getOneDatabaseConnection.ts` beside the old file, and the old file's importers kept the old name.
after: a bad-practice retires the old file only when its body still matches the old template, and
rewrites its importers. a hand-edited copy is flagged, never deleted.
