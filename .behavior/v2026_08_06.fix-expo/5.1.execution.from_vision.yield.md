  FIRST try one usecase-aware `.npmrc` declaration before a fork.

## FULCRUM (flagged for wisher) — the `pnpm` practice's exact `packageManager` pin

CONFIRMED (code read of declapract internals): the `pnpm` practice pins
`"packageManager": "pnpm@10.24.0"` with a **CONTAINS-exact** check, and a true `minVersion` CANNOT
replace it:

- `CHECK_MIN_VERSION_REGEX` is ANCHORED — `/^@declapract\{check\.minVersion\('([0-9.]+)'\)...\}$/`.
  the whole JSON value must BE the expression; `"pnpm@@declapract{...}"` (version behind a `pnpm@`
  prefix) does not match.
- `checkDoesFoundValuePassesMinVersionCheck` runs `valid(foundValue)` = `/^v?\d+\.\d+\.\d+.../`,
  which requires a PURE semver. a consumer's `pnpm@10.32.1` is not one → the check would fail even
  if the expression parsed.

so a `minVersion` on `packageManager` is impossible with declapract's built-in checks; the only
real fix is a custom `FileCheckFunction` in `pnpm/best-practice/package.json.declapract.ts` that
strips the `pnpm@` prefix and does a semver `>=` compare.

**best-guess = leave as-is for this wish** (per rule.always.defer-fulcrums-to-last). the exact pin
is CORRECT for our migration target: app-protools is on npm with no `packageManager`, so the
CONTAINS fix ADDS `pnpm@10.24.0` (the desired pin). the drift/downgrade bug only bites a repo
already on a higher pnpm — not our target, and not expo-specific. the custom-check enhancement is a
self-contained, reversible later rework (clean), so it is FLAGGED, not halted on. surfaced to the
wisher at close alongside the typescript/tests fulcrum.
