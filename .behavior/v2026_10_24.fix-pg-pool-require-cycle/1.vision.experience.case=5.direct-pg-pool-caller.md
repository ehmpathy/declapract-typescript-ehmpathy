# case=5: an adopter whose code calls pg-pool directly (alterpath)

covers inventory #10–#15, #34, #35.

## narrative

lee's service predates the rds practice. one module does `import Pool from 'pg-pool'` and `new Pool({ host, ... })`,
with no `Client`. lee upgrades the practice; the apply ships the pg-pool patch, and `pnpm install` applies it. lint is
green. the first integration test that opens that pool throws `this.Client is not a constructor` from
`pg-pool/index.js`. lee greps the repo for pg-pool, finds `patches/pg-pool.patch`, and its header names the case: a
direct caller must pass its client, `new Pool({ ..., Client: require('pg').Client })`. lee adds one option, and the
test passes. no other code in lee's repo changes.

the outcome is the same whatever lee's patch map holds, and whether pg-pool is the latest release or an older one the
hunk fits at an offset. where lee's own exact pg-pool patch already applied (#12, #15), the throw predates this upgrade.

## bdd sketch

```
given('[case5] an rds repo with code that calls new Pool() from pg-pool with no Client; the patch applies')
  when('[t0] declapract apply, then pnpm install')
    then('the install exits 0; node_modules/pg-pool/index.js holds no require(\'pg\')')
  when('[t1] the pool opens its first connection')
    then('it throws from pg-pool/index.js: this.Client is not a constructor')
  when('[t2] lee opens patches/pg-pool.patch')
    then('its header names the remedy: pass { Client: require(\'pg\').Client }')
  when('[t3] lee passes Client')
    then('the pool holds pg\'s Client again')                          // [case2] [t1], per release
```

the clamp stops at the pool's `Client`: a real connect needs a live database, which the patch clamp does not stand
up. with pg's `Client` in place, the pool is the one pg itself builds, so its connect path is pg's own.
