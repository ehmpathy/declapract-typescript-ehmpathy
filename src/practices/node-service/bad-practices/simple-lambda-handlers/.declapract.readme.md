# simple-lambda-handlers

## what

detects and transforms simple-lambda-handlers usage to sdk-aws-lambda, at the `sdk-aws-lambda@0.7.1`
floor the node-service practice declares.

## why

sdk-aws-lambda provides modern lambda handler patterns:
- better schema validation with zod (input + output)
- log context passed to invoke function
- trail.exid auto-propagation

## transforms

| old | new |
|-----|-----|
| `import { createStandardHandler } from 'simple-lambda-handlers'` | `import { genLambdaEndpoint } from 'sdk-aws-lambda'` |
| `import { createApiGatewayHandler } from 'simple-lambda-handlers'` | `import { genLambdaEndpoint } from 'sdk-aws-lambda'` |
| `createStandardHandler(...)` | `genLambdaEndpoint.forAsk(...)` |
| `createApiGatewayHandler(...)` | `genLambdaEndpoint.forApiGateway(...)` |

## the invoke input — `{ headers, payload, event }`

in `sdk-aws-lambda@0.7.1`, `invoke` receives one input with three keys:

| key | holds |
|-----|-------|
| `payload` | the validated body — what the input schema describes |
| `headers` | the request headers, keys lowercased (api gateway only) |
| `event` | the reconciled wire event — method, params, codec (api gateway only) |

two renames apply to a guide written against an earlier release, and they fail differently:

| earlier guide | 0.7.1 | how a migrator meets it |
|---|---|---|
| `rawEvent.headers[k]` | `headers[k]` | loud — `rawEvent` is absent at the destructure |
| `event` for the body | `payload` | quiet — `event` still exists, so the error lands at the use site |

## limitations

these patterns require manual migration:

- `schema` (single joi) → `schema: { input, output }` (split zod)
- `logic: (event) => O` → `invoke: async ({ payload }, { log }) => O`
- `log` passed at creation → `log` also received in invoke context

the contract differs in a way a regex cannot get right: the prior framework's schema described the
WHOLE event, while sdk-aws-lambda's input schema describes the request BODY. a rename-only rewrite
answers 400 to every request yet typechecks. so a handler CALL carries a `@declapract:review` marker
that names the manual edits (unwrap the `body` key into the input schema; read the body as
`payload` and the headers as `headers`). the codemod does NOT guess the contract — it flags it loud,
and the consumer deletes the marker once the call is restructured (#594).

## the payload is frozen — readonly sinks

`invoke`'s input is deep-frozen (`FrozenDeep<T>`). a domain input typed with a mutable array no
longer accepts it. the repair is a readonly sink: `z.array(…).readonly()` in the zod schema plus a
`readonly T[]` field on the domain input. `FrozenDeep<…>` on a handler signature is the wrong repair:
it spreads the sdk type through consumer code.

## example

before:
```ts
import { createStandardHandler } from 'simple-lambda-handlers';

export const handler = createStandardHandler({
  log,
  schema,
  logic: async (event) => doStuff(event),
});
```

after (requires manual refinement):
```ts
import { genLambdaEndpoint } from 'sdk-aws-lambda';

export const handler = genLambdaEndpoint.forAsk(
  {
    schema: { input: inputSchema, output: outputSchema },
    invoke: async ({ payload }, { log }) => doStuff(payload, { log }),
  },
  { log },
);
```

an api-gateway handler, after:
```ts
export const handler = genLambdaEndpoint.forApiGateway({
  schema: {
    input: z.object({ headers: headersSchema, payload: bodySchema }),
    output: asApiGatewayResponseSchema({ body: outputSchema }),
  },
  invoke: async ({ headers, payload }, context) => ({
    body: await doStuff({ payload, authorization: headers.authorization }, context),
  }),
});
```

## a repo already on sdk-aws-lambda below 0.7

the `sdk-aws-lambda-pre-v07` bad-practice owns that move: `genLambdaEndpoint(` → `.forAsk(`,
`.for.apiGateway(` → `.forApiGateway(`, `({ event })` → `({ payload })`.
