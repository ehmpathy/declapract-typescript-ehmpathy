## the defect — a regex maps a stage value to an access value, blind

`old-stage-enum`'s transform rewrote `Stage.DEVELOPMENT` → `'prep'`, but the member's value was
`'dev'` and it was overloaded across TWO axes (the access tier and the deploy-stage slug). any
occurrence that meant the STAGE was silently corrupted: a prep deploy (stage=dev) then grants IAM on
`infrastructure-dev-…` while the code requests `infrastructure-prep-…` — no permission, no table,
surfaced as latency. silent twice: an IAM denial reads as latency, and a prod smoke test cannot see
it (at prod, access = stage). the worst shape of all — an enum→string-literal rewrite DESTROYS the
type-check that would have caught a wrong axis, in the same edit.

## what landed — the marker + leave-in-violation, via the TS parser

the 5.1 execution landed the transform #572 proposed, and stronger:

- **`Stage.PRODUCTION` → `'prod'`, `Stage.TEST` → `'test'`** — the two UNAMBIGUOUS members migrate,
  spliced into the original at the TypeScript parser's node offsets (a `PropertyAccessExpression`
  walk). so a `Stage.PRODUCTION` inside a comment, string, template-static span, or REGEX literal is
  that token's own text — never a property-access node — and is preserved byte-for-byte. the whole
  "a value spliced into a non-code span" corruption class is foreclosed BY CONSTRUCTION, where a
  hand-rolled character mask could only chase one token position at a time.
- **`Stage.DEVELOPMENT` — LEFT IN PLACE, never guessed.** the fix inserts a
  `// @declapract:review: Stage.DEVELOPMENT is axis-ambiguous — pick by hand …` comment above each
  occurrence (idempotent — a line already marked is skipped). the real property access is UNTOUCHED,
  so `check` still detects it and `declapract plan` stays RED until a human decides the axis. the
  comment names WHERE (it rides the line) and WHAT (an access tier, or the deploy-stage slug) — the
  loud, plan-visible "leave the file in violation" signal the wish's guard #3 demands.
- the `Stage` import is dropped ONLY when no real reference remains (a leftover `DEVELOPMENT` keeps
  it, so the file still compiles).

this is deliberately UNLIKE an earlier value-splice shape (`Stage.DEVELOPMENT` → `'prep' /* marker */`)
that both GUESSED `'prep'` AND cleared the check (so `plan` read CLEAN with a possibly-wrong value —
the exact silent-break class this wish retires). the comment marker forecloses both: no value emitted
(no guess), and the still-red plan cannot hide the unsettled axis.

## note — stronger than the vision's call, on purpose

the vision (settled design) reasoned that the north-star COLLAPSE gives that enum one answer (`'prep'`
uniformly), so #572 would be an OPTIONAL guard for OTHER rewrites, not D27 itself. the 5.1 execution
chose the SAFER path instead: it does NOT rely on a completed collapse — it leaves `DEVELOPMENT` in
violation with a marker REGARDLESS, so the transform is correct whether or not the axis has yet
collapsed. that is the right call: a transform that cannot know must say so, today, not on the
assumption a later migration lands.

## the general rule it yields — offered for declapract itself

> a rewrite whose output lands in a type-constrained position is compile-loud; a rewrite whose output
> lands in an unconstrained position is compile-silent — so a transform that emits an IDENTIFIER may
> guess (`tsc` is the backstop), but a transform that emits a VALUE must not.

this is the wish's durable guard #3. the `@declapract:review` marker is the concrete mechanism for the
value-emit case; a lift of it into a declapract-native capability (`ehmpathy/declapract`) is a
follow-on, out of scope for this practice-fix wish.
