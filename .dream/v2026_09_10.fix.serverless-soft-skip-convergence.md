## .the default-timeout half — RESOLVED via a diagnostic marker (2026-09-13)

**`withDefaultTimeout`** no longer bare-soft-skips on a non-default provider timeout. its three
branches now cover the arrival shapes:
- `timeout: 60` already present → no-op (idempotent);
- `timeout: 10` (the old literal) → rewritten to `timeout: 60` byte-identically, as before;
- any OTHER provider `timeout: N` → emits a `@declapract:review` marker via
  `withProviderTimeoutReviewMarker` (`serverless.yml.declapract.ts`), so a still-red CONTAINS plan
  carries an actionable diagnostic that names the `timeout: 60` line to hand-converge.
- evidence: the three `then`s under `given: a legacy serverless.yml whose provider timeout is a
  non-default value` in `serverless.yml.declapract.test.ts` — non-default emits the marker + preserves
  `timeout: 30`; the marker is idempotent; a 4-space function-level `timeout: 100` is NOT clobbered.

the provider-vs-function disambiguation that once made this DIRTY is now closed: the branches are
line-anchored `/^ {2}timeout:/m` (2-space indent = provider-level), so a per-function 4-space
`    timeout: N` is invisible to the anchor. the utc half was resolved the same way earlier this
round (§.the utc-timezone half above).

## .the one genuine leftover — a wisher fulcrum (force vs relax)

what remains is NOT a silent red and NOT a ripple — it is a single design call the marker defers to
the wisher rather than a guess:

- **force** — rewrite a consumer's explicit `timeout: 30` to `timeout: 60`. this overrides a
  deliberate operational choice (the meta-lesson's "a practice that emits a value" hazard).
- **relax** — drop the CONTAINS requirement that a provider timeout be exactly `60`, so a non-60
  value is simply accepted.

the two are opposite, equally-valid resolutions, so neither is a mechanical widen. the marker path
ships today as the neutral terminus: it makes the divergence VISIBLE and ACTIONABLE without a pick of
either arm.
