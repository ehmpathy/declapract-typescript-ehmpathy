# 🌙 dream: declastruct-github models a review bypass for one actor

kind: reseed · owner: ehmpathy/declastruct-github · caught 2026-11-15

## .the cue that fired
the require-main-review practice wants an option to exempt the rhelease app's release prs from
main's review rule, and found no field to declare it with.

## .the gap, precisely
declastruct-github 1.4.0:
- `DeclaredGithubBranchProtection.requiredPullRequestReviews` has no `bypassPullRequestAllowances`
  (github rest: `required_pull_request_reviews.bypass_pull_request_allowances.{users,teams,apps}`)
- `DeclaredGithubRepoRuleset.rules` carries no `pull_request` rule type
  (github rest: `{ type: 'pull_request', parameters: { required_approving_review_count, ... } }`),
  which with `bypassActors` would exempt one app
- no `requireLastPushApproval` either (github rest: `require_last_push_approval`)

## .the shape of the fix
add `bypassPullRequestAllowances?: { users?, teams?, apps? }` and `requireLastPushApproval?: boolean`
to the protection's review literal, with get/set mappers and an integration test; or add a
`pull_request` rule type to the ruleset literal. then the provision-github practice can declare
`apps: ['rhelease']` in one line.

## .why it is not done in this round
it lives in another repo, and the commander has not yet chosen to exempt release prs (fulcrum F1).
