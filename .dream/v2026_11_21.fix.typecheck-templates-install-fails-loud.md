# 🌙 dream: the typecheck-templates harness halts on an incomplete install, never reports it as a compile fault

- kind: fix
- owner: ehmpathy/declapract-typescript-ehmpathy (`src/typecheckBestPracticeTemplates.declapract.integration.test.ts`)
- caught: 2026-11-21

## .the cue that fired
a whole-suite run on a loaded host failed `rhachet-roles-package` [t1] twice. the "diagnostics" were node's `Cannot find module '<tempdir>/node_modules/.pnpm/typescript@5.4.5/node_modules/typescript/bin/tsc'`. the same case reran alone green.

## .the gap, precisely
the harness installs the emitted deps into a temp repo, then runs tsc. when the install leaves the store without `typescript/bin/tsc`, the harness runs on, and the absent binary reaches the reader as a template compile failure with the hint "a template the usecase ships does not compile".

## .the shape of the fix
after the install, check that the tsc entrypoint exists. if absent, throw a `MalfunctionError` that names the install (status, the last lines of its output), so a host fault reads as one and never as a template defect.

## .why it is not done in this round
the absorb pr is pushed and green; this harness change is a separate fix with its own bite proof, outside the queued tasks.
