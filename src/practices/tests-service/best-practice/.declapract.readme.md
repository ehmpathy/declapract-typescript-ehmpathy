# tests-service

the acceptance-test layer for a lambda service — blackbox tests that invoke a deployed (or local)
lambda fleet through its real contract.

## acceptance targets the contemp fleet

a service that dual-publishes (see the `serverless` + `environments` practices) ships its fleet
under BOTH slugs through the ancient→contemp transition: `-dev-` (ancient) and `-prep-`/`-prod-`
(contemp) — the SAME artifact under two names. so its own acceptance suite proves ONE fleet, the
contemp one: a run against contemp proves the deployed code, and the ancient slug is an alias for
inbound callers still on the old name, never a second target for the self-acceptance gate.

contemp is the service's own access-tier slug — `-prep-` at prep, `-prod-` at prod — so a single
access-keyed run covers every tier the deploy job ships. there is no per-fleet fan-out and no
per-tier skip.

the reusable primitive lives in the `environments` practice, one procedure per file:
`src/access/sdks/sdkAwsLambdaEnvAccessContemp.ts` — `sdkAwsLambdaEnvAccessContemp()` emits the
access direct (`-prep-` at prep, `-prod-` at prod). its ancient sibling
`sdkAwsLambdaEnvAccessAncient()` (emits the `-dev-` slug below prod) serves OUTBOUND calls to
unmigrated peers, not the self-acceptance suite.

the composition atop that primitive is per-service (a service wraps `invokeLambdaForTesting` once,
at a local seam, so the contemp-slug target lands in one place rather than at every call site):

```ts
// blackbox/lambdaTestMethods.ts — a per-service seam onto simple-lambda-testing-methods
import { invokeLambdaForTesting as invokeLambdaForTestingRaw } from 'simple-lambda-testing-methods';
import { sdkAwsLambdaEnvAccessContemp } from '../src/access/sdks/sdkAwsLambdaEnvAccessContemp';

export const invokeLambdaForTesting: typeof invokeLambdaForTestingRaw = (input) =>
  invokeLambdaForTestingRaw({ ...input, stage: sdkAwsLambdaEnvAccessContemp() });
```

each blackbox test imports `invokeLambdaForTesting` from that seam, and one package command runs the
suite against the contemp fleet:

```jsonc
"test:acceptance": "set -eu && npm run test:acceptance:jest"
```

## why the seam is per-service, not a shipped template

the seam is composition, not a primitive: a given service re-exports its own extra test operations
through it (an apigateway-event builder, a graphql event builder), and its blackbox tree shape
varies. so the practice ships the reusable primitive (the `EnvAccess` helper) and documents this
composition, rather than a one-shape-fits-all seam file. lift the seam to a shipped template only
once two or more services share the identical composition (`rule.prefer.wet-over-dry`).

## the PR acceptance gate runs in-process; the deployed-fleet run is post-deploy

the shared `.test.yml` PR gate (cicd-common) runs its acceptance shards IN-PROCESS (`LOCALLY=true`),
because a PR has no deployed lambda to invoke. a service that publishes only dev/prep (no `test`
fleet) would otherwise target `svc-<name>-test-*` — a slug that does not exist — and 404 on every
call, so the PR gate would regress to all-404 the moment the suite is non-empty. the in-process
default lets a fleetless service inherit a green PR gate out of the box, with no hand-patch. the
acceptance run against a DEPLOYED fleet is a separate post-deploy grain (`.deploy-sls.yml`'s
`assure` job), which invokes the real deployed lambda.

## the CI acceptance gate runs contemp only

`.deploy-sls.yml`'s `assure` job runs `ACCESS=${{ inputs.access }} npm run test:acceptance` ONCE —
against the contemp fleet the same job just deployed. contemp maps to the deployed access at
both prep and prod, so one run covers every tier this job ships. the ancient slug is proven by
identity: dual-publish deploys the SAME artifact under the `-dev-` name, so a green contemp run is
a green ancient run. the self-acceptance gate never invokes the ancient fleet — that slug exists
for inbound callers still on the old name, an alias, never a second target to test.
