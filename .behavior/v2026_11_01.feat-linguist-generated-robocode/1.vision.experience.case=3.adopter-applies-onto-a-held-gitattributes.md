# case=3: adopter applies onto a held .gitattributes

cells: ad5 · ad6 · ad9 · ad10 · dd1 — happy · critipath; clamps inv1

## .narrative

mira maintains `svc-jobs`. its `.gitattributes` holds the git practice's lock-file block as the prior version shipped it: untagged headers, a merge header worded the old way. above it sits one repo-own line, `*.png binary`.

she bumps `declapract-typescript-ehmpathy` and runs `npx declapract apply`. four practices declare `.gitattributes` now: git (lock files), tests-any (tests), rhachet (routes), persist-with-rds (dao output). one shared algorithm (`defineExpectedGitattributesContents`, peer of the gitignore one) emits the whole file, so all four agree on one output.

the diff she sees:

- each git header gains its `# [git] ` tag, which names the practice that owns the section
- the old merge header is retired, and its current text takes its place; the entries stay as they were
- three new sections appear, each under its own tagged header
- her `*.png binary` line is kept, and moves to the bottom, where a repo line wins over every managed line

she runs `apply` again: zero bytes change. `plan` reports clean.

a repo whose file carries the legacy header with its typo, or only that header, or a section that lacks one entry, lands on the same file.
