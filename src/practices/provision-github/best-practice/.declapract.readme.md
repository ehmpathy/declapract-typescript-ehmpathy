| variable | description | example |

| `reviewers.users` | github usernames for production deployment reviewers | `['whodisio', 'ehmpathy']` |

## repo visibility fails closed

- the repo provisions **private** unless `package.json` declares `"private": false`. an absent key,
  a `null`, a string, or any other value provisions it private
- `package.json` always declares `private` as an explicit boolean. where it is absent or not a
  boolean, the `implicit-package-privacy` fix backfills `"private": true`. an explicit `true` or
  `false` is never touched
- a repo meant to be public declares `"private": false`, by hand, when its owner is ready to
  publish that domain. no practice sets it on the owner's behalf
- `"private": true` also makes `npm publish` refuse. a package published to npm declares
  `"private": false`
