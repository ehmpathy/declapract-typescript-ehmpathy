## .the gap, precisely
- a stopped container from an older compose project name passes `clear` ("available"), then `up` fails on docker's raw "container name already in use"; the `docker rm -f` hint prints only for a live holder
- a second clone of one repo shares the compose project name, so its `clear` takes down the first clone's testdb
- a non-docker process on the port is invisible to `docker ps`
- depcheck lists `.agent/` dirs by name, while jest skips all of `.agent/` but `repo=.this`

## .the shape of the fix
- derive the compose project name per clone (a hash of the checkout path), and on `clear` name a stopped container that holds this checkout's container name
- after `clear`, probe the port itself (a bind test), so a non-docker holder halts with its fix
- depcheck: `.agent/*` plus `!.agent/repo=.this`, with the merge fix updated and each pattern clamped
