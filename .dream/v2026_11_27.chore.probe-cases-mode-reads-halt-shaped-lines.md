# 🌙 dream: the probe's cases mode reads a candidate line that looks like a halt

- kind: chore
- owner: this repo, `.agent/repo=.this/role=any/skills/check.timestamps.probe.sh`
- caught 2026-11-27

## .the cue that fired

`rhx check.timestamps.probe --cases <a test source>` exited with `💥 MalfunctionError: could not
match the hook's halt line to a staged file`. the candidate line itself held text shaped as a halt
detail (`snapshot.json:1:{ ... }`), and the probe parsed that text, not the case file it staged.

## .the gap, precisely

1. cases mode maps the hook's halt line back to a case by a prefix parse; a candidate whose own
   text holds `<name>:<n>:` confuses the parse
2. there is no mode that lists every halted line in a file; the hook names only the first, so a
   maintainer who must clear a whole file needs a scratch copy of the hook

## .the shape of the fix

1. match the halt line on the known staged name (`case.NNNN.md:1:`) as an exact prefix, never a
   free parse
2. add `--show every`: run a copy of the hook that prints each match, for a whole-file read

## .why it is not done in this round

#845 is a p0 on the hook; the probe is a dev tool, and the scratch-hook route cleared this round.
