## .what

author `rule.forbid.root-test-dir.md` in the ehmpathy mechanic role, under
`code.test/pitofsuccess.portability/` (beside `rule.forbid.test-assets-dunder` and
`rule.prefer.dot-dirs`). the rule: a repo-root `test/` dir is FORBIDDEN. test assets live under a
`.test` dot-dir.

## .the rule

- **forbidden:** a `test/` dir at the repo root (e.g. `test/assets/…`).
- **allowed:** `src/.test/assets/…` (a `.test` dot-dir under `src`), or co-located
  `src/practices/<p>/.test/assets/…` beside the code it serves.
- **why the dot-dir:** tsconfig / jest globs exclude dot-dirs, so fixture `.ts` / `.declapract.ts`
  under `.test` are not double-compiled or collected — the concern that historically drove
  root-`test/` placement is met by `.test`.

## .severity

`forbid` → **blocker**. a root `test/` dir is a structural defect: it escapes the dot-dir exclusion,
pollutes the repo root, and (for declapract fixtures) its relative symlinks re-parent on any move.

## .enforcement

- a tracked path under a repo-root `test/` dir = blocker.
- fix: move to `src/.test/assets/…` (or co-locate under `src/**/.test/assets/…`), then repoint every
  reference and recompute any relative symlink with the `symlink --mode relative` skill.
