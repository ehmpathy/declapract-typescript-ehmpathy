withDatabaseConnection -> withDatabaseContext, per procedure-fns pattern

`withDatabaseConnection` took `dbConnection` in the input. `withDatabaseContext`
(`src/utils/database/withDatabaseContext.ts`, shipped by the best-practice) takes it in the context:
each op becomes `(input, context) => …`, and each caller passes the context as the 2nd arg.

the move changes each op and each caller, so the fix does not rewrite code. it stamps a
`// @declapract:review:` line above each import or definition of `withDatabaseConnection` that names
the move, and leaves the extant wrapper in place so the tree still builds. delete the marker, and
then the wrapper, once its last caller moves.
