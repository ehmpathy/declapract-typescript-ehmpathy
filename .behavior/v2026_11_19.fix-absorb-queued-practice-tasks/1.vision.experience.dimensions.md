# experience dimensions

the experience = an adopter repo takes the next practice version, then lives with it. each queued task is a defect that bit at one cell of this space.

## .dimensions

| dim | axis | values | orthogonal because |
|---|---|---|---|
| D0 | actor | adopter (the clone or human that applies, tests, commits, pushes) · reviewer (the human who reads and merges the pr) · sender (the clone that filed the task) | who meets the step; each actor meets a different subset of D1 (see `.collapses`) |
| D1 | step | local apply · local test · local lint · local commit hook · pr ci · main ci (post-merge) · deploy | the step of the adopter's day; each value runs a different tool, whatever the repo |
| D2 | host | actor host (`.agent/.actors`, `.agent/.cache`, `.temp` present) · clean ci clone | which machine runs the step; set by where it runs, not by the repo or the step |
| D3 | suite location | suites in `src/` only · suites also in `.agent/repo=.this/` | where a repo keeps its own tests; any platform may keep suites in either place |
| D4 | repo platform | service (with or without rds) · expo app · package | which practices the repo takes (`tests-node` vs `tests-expo`; `cicd-service` vs `cicd-app-react-native-expo` vs `cicd-package`); independent of where its suites sit |
| D5 | upgrade phase | first upgrade · steady state | when in the repo's history the step runs; any platform, any host, meets both |
| D6 | input state | clean · fault (git error, broken tool, skipped suite, held port, lost cache reserve) · hostile (a secret, a timestamp, a hand-edited hook) | what the step is handed; any step on any repo can be handed any of the three |
| D7 | triage outcome | fixed in this release · already fixed in 0.50.0 · partly fixed · left open with reason | the release's answer to one task; independent of where that task's defect bit |
| D8 | protection shape | names `suite / test-*` (since #257, 2025-12) · bare pre-#257 names (`test-commits`, …) · `test-passed` (after this release's first post-merge apply) | what the repo's live branch protection requires; set by its upgrade history, not by its platform or this pr |
| D9 | commits a data store | no · yes (a tool commits a plaintext store with clock rows, e.g. bhuild `.eco/*`) | a choice of the repo's own tools; any platform may make it |
| D10 | tenancy | sole tenant · shared with concurrent peers (other clones or repos on one host; other jobs on one cache key; parallel suites on one cpu) | how many actors contend for one resource at once; set by the host and the run's fan-out, not by the repo, step, or input |

## .collapses
- **D0 × D1**: the adopter meets every step. the reviewer meets only pr ci (reads checks, the red gate, then merges) and main ci (protection moves, or it would hand-edit it). the sender meets no step; it meets D7, via the radio
- **D1 × D2**: a host-local defect (actor dirs, trash) bites only on an actor host; ci clones never hold those dirs. so D2 = ci clone pairs with pr ci, main ci, deploy; D2 = actor host pairs with local apply, test, lint, commit hook
- **D1 × D5**: only branch protection reads a check name, and only pr ci and main ci meet protection. so `first upgrade` collapses into `steady` for every local step and for deploy
- **D5 × D8**: D8 matters only at `first upgrade` × pr ci / main ci. at `steady`, protection already names what the workflow reports
- **D3 × D1**: suite location changes only which files a tool walks, so it varies only local test and local lint. a ci clone has no host-local dirs, so `.agent/repo=.this/` suites run in ci today as they will after; no ci cell changes
- **D9 × D1**: a committed store meets only the commit hook (the timestamp scan); every other step ignores what a file holds
- **D0 × D7**: only the sender meets a triage outcome; adopter and reviewer meet the release, not its verdict on a task. so D7 varies only at D0 = sender
- **D10 × the shared resources**: tenancy matters only where actors share a resource. on a shared host: the testdb port (two repos declare 7821) and the cpu (parallel suites stall a spawn). in ci: a cache key that several `.install` jobs miss at once. never shared: the git index and the husky hooks, since each clone holds its own worktree, so those cells are sole-tenant by construction
- **D6 = clean**: on every step, `clean` is the happy path each fix must leave unchanged. the walk verdicts it per step below, rather than drop it

## .cells ruled out
- local apply · test · lint · commit hook × ci clone: impossible (nature) — a ci clone holds no actor dirs, so no host-local defect can reach it
- first upgrade × any local step, or × deploy: impossible (nature) — no local step reads a check name, and protection gates the merge, not the deploy; these cells are the `steady` cells above
- D8 × steady: impossible (nature) — at steady, protection already names what the workflow reports
- deploy × suite location: impossible (nature) — a deploy never reads where a suite sits; it builds and ships
- package × deploy: impossible (nature) — a package publishes, it does not deploy; its publish meets #785 via its own `provision.yml` (main ci row)
- D9 yes × any step but the commit hook: impossible (nature) — only the timestamp scan reads file content for clocks
- reviewer × any local step: impossible (nature) — the reviewer meets the pr, never the adopter's host
- D10 shared × local commit hook (index, lock): impossible (nature) — each clone holds its own worktree, so its index and hooks have one tenant
- D7 × adopter or reviewer: impossible (nature) — only the sender reads a task's outcome
