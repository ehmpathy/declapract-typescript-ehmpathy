# 🌙 dream: repair the `old-acceptance-dir-location` clamp, which exceeds its jest timeout

- kind  = fix
- owner = this repo (`ehmpathy/declapract-typescript-ehmpathy`)
- caught 2026-09-20

## .the cue that fired

a full-suite integration run (`--thorough`) on the #613 hotfix reported 5 failures. 1 was the
expected snapshot move; the other 4 all came from one suite that had no relation to the change:

```
FAIL src/practices/tests-any/bad-practices/old-acceptance-dir-location/.declapract.integration.test.ts
  ● … [t1] declapract fix is applied › fix is applied
    thrown: "Exceeded timeout of 90000 ms for a test."
  ● … then: somefile.ts is moved to blackbox/              → Received: undefined
  ● … then: .rhachet/manifest.json is moved to blackbox/   → Received: undefined
  ● … then: .agent/config.yml is moved to blackbox/        → Received: undefined
```

the last three are downstream of the first: `executeApply` never finished, so the files it was
meant to move are absent.

## .the gap, precisely

- **it predates this change, and it is NOT load.** measured three times: 114s inside the 67-suite
  run, 162s alone, and 164s alone with the hotfix's new clamp file moved out of `src/`. the new
  file changes it by 2s, which is noise — so the cause is prior.
- **CI has never run it.** `test:integration` passes `--changedSince=main` unless `THOROUGH=true`,
  so the suite is selected only when a diff touches `tests-any`. PR #605's `test-integration`
  job went green in 1m40s — the whole suite, because this one was never picked.
  ⇒ the clamp is red and has been invisible. it is not a flake; it is an unrun test.
- **the timeout is real work, not a hang.** `executeApply` runs against a temp dir that symlinks
  the repo's whole `src` in (`symlink: [{ at: 'src', to: 'src' }]`), so the apply walks a tree
  that has grown since the clamp was written. 90s was enough then and is not now.

## .the shape of the fix

diagnose before you reach for the timeout knob — a raise makes the red go away and leaves the
cause. two candidates, in order:

1. **the apply got slower** — profile `executeApply` against that fixture. if the symlinked `src`
   is what it walks, the cost scales with this repo's own growth, so every future practice makes
   it worse. narrow what the fixture symlinks, or scope the walk.
2. **the apply broke** — confirm the three `blackbox/` moves still happen at all when given
   unlimited time. if they do not, the timeout is a symptom and the move logic is the defect.

only once (1) or (2) is settled, size the timeout to the measured cost.

⚠️ and close the blind spot that hid it: a clamp that CI never selects is a clamp that does not
exist. either run the integration suite `--thorough` on some cadence, or give this one a home
CI reaches.

## .why it is not done in this round

the round is a 🔴 hotfix for #613 — every adopter of `persist-with-rds` has a broken `pnpm fix`
and no published version carries a cure. this repair is neither SAFE nor CLEAN to ride along:
it needs a profile of `executeApply` and likely a change to fixture scope or declapract's walk,
which ripples well past the one template comment the hotfix touches. a wrong guess here would
delay a release that adopters are blocked on.
