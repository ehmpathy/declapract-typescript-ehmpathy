wish =

the declapract upgrade of `ahbode/svc-gateway` (2026-08-11 → 08-21) hit a wall of practice defects.
every one was found by a repo that ran `declapract fix` and then read the result — so each is a defect
a consumer hits on **arrival**, not a hypothetical.

**fix all of them, and fix them forward** — repair the practices themselves so the next traveler never
meets this friction. eliminate the friction at its source in this library, not in any one consumer repo.

the full roster + priority is the index issue **#571** (~96k chars of evidence, split across sub-issues
because it exceeds GitHub's body limit). this wish carries the roster so the vision can work from it
directly; the deep evidence lives in the linked issues.

## the shape of the friction

three flavors recur, and the meta-lesson from #571 names why:

> a practice that emits a **value** cannot verify its own output, while a practice that emits an
> **identifier** is verified by `tsc` for free. so the value-shaped rewrites are where the defects
> concentrate — and they are exactly the ones no gate can see.

- **silent breaks** — a check reports clean, a fix never lands, a formatter never runs
- **non-idempotent / one-way fixes** — a `fix` converts one violation into another, permanently
- **caller-without-callee** — a practice stamps a caller and never supplies its callee

## the north star — eliminate the `stage` axis

**status: proposed, direction locked, specifics await approval. hold the mechanism loosely, the
goal firmly.**

a whole tier of the roster is one disease in many costumes: the upgrade split one fact —
*which deployment* — into two words that **disagree below prod** (`access=prep ⟺ stage=dev`).
`access` is the tier a runtime may reach (`test|prep|prod`); `stage` is the slug baked into
resource names. two words for one fact is an ambiguity trap, and this one is fault-prone in the
worst way: **every fault it spawns is compiler-invisible** — both axes type as `string`, so a
wrong-axis reference fails only at runtime, against a deployed resource.

the goal is not to *tame* `stage` — it is to **retire the concept**. one axis, `access`, names
every resource; `stage` survives only where a third-party tool literally demands the word
(serverless's `--stage`), pinned `= access`, never a divergent value, never remapped, never in
app code. once the last divergence is gone, so is the whole silent fault class.

these roster rows are all instances of the one disease:

| row | the silent, compiler-invisible fault |
|---|---|
| **D27** (#572) | cache targets a DynamoDB table the lambda has no IAM for |
| **D31** (#573) | our acceptance suite invokes a lambda fleet no deployment publishes |
| **D52** | 88 blackbox files target a `-prep-` fleet no peer publishes |
| **D53 · 4b · 4 · D55** | the access/stage rename, half-applied — casts, remaps, `as any` placeholders |

collapse the two axes onto `access` and **all of them dissolve at once** — no cast, no
`accessByStage` remap, no second axis for a regex to guess.

### the proposed path to that deletion — dual-publish + an ancient/contemp ledger

⚠️ **the specifics below are proposed, not settled — carry them with a grain of salt.** the
*direction* is locked; the numbers, the exact sequence, and the absolutism of "delete `stage`
in one move" are best-guesses that a fulcrum review must ratify before code lands.

1. **dual-publish through the transition.** each service publishes its fleet under **both** slugs
   (`svc-x-dev-*` **and** `svc-x-prep-*`), so neither an ancient (dev-slug) nor a contemp
   (prep-slug) caller ever hits a 404. no lockstep — each service migrates on its own clock.
2. **an `access`-aware target helper names the ledger.** adopt sdk-aws-lambda's **own** canonical
   `ancient`/`contemp` pair — verified as the dependency's word (113 matches; the
   `ancient-vs-contemp-callers` invariant), so this **adheres** to `rule.forbid.domain-term-synonyms`,
   it does not coin a synonym. the homograph (sdk uses it on the payload-format axis; we use it on
   the slug axis) is disambiguated by the `EnvAccess` qualifier in the name:
   - `sdkAwsLambdaEnvAccessAncient` → emits `dev` — a call to a peer published `-dev-` only
   - `sdkAwsLambdaEnvAccessContemp` → emits `prep` — a call to a `-prep-` peer, or to self
   - `env.access` **direct** — no deployed name across the wire
   the helper choice **is** the ledger: `grep AccessAncient` = the live list of unmigrated peers;
   a migration is a one-line `Ancient → Contemp` flip.
3. **stateless double-publishes; stateful ALIASES, never copies.** a lambda under two names is
   safe duplication. a stateful store (RDS, DynamoDB, S3, SQS) under two names must be **one store
   with two pointers** — a Route53 CNAME, an SSM pointer, an ARN — never two copies, or a write-to-dev
   / read-from-prep split-brain. (this is why the RDS layer needs **no data migration**: the config
   host is already an opaque `access`-keyed value; a CNAME makes it read `-prep-` with zero data moved.)
4. **self migrates first.** self becomes `Contemp` only once we publish our own `-prep-` fleet, so:
   dual-publish self → self is `Contemp` → our own suite (D31) clears → then flip outbound callers
   peer-by-peer.
5. **the endpoint IS the deletion.** once `grep AccessAncient` → 0 org-wide, delete the `Ancient`
   helper, drop the `-dev-` publish, and retire `stage` as a divergent concept in one move. the
   helper and the dual-publish are scaffold built to be torn down.

### where this lands — upstream, by necessity

the pattern **must** land in this library, not per-repo: `serverless.yml` + `.deploy-sls.yml`
(cicd-service), and `environment.ts` + the acceptance template (environments / tests-service) are
all declapract-hosted, so a local edit is reverted by the next `declapract fix`. that is exactly why
stage-elimination belongs in *this* wish.

### the honest costs (proposed figures — verify before commit)

- **CloudFormation resource limit — a design constraint, not a cost.** each `sls deploy --stage <slug>`
  already produces its **own** CF stack (`svc-x-dev`, `svc-x-prep`), so dual-publish is **two stacks
  of ~75 resources each**, both well under the per-stack 500 cap — never one stack of ~150 near it.
  the requirement is simply: **keep the two slugs as two stacks**; the cap bites only if someone
  collapses both into one. no `serverless-plugin-split-stacks` needed by this design.
- **the residual `--stage`** — serverless requires the field; "delete `stage`" operationally means
  `--stage ${access}` with no remap. whether the field can be dropped entirely is **open — verify**,
  not asserted.
- **transition-only scaffold** — dual-publish, the `Ancient` helper, and every cast are built to be
  deleted at the endpoint; the plan includes its own teardown.

### the guard this yields

a practice-level check that **forbids a divergent stage** — any `accessByStage` remap, or any
`stage`-keyed resource name that is not simply `access` — becomes a blocker. that guard is what keeps
the axis from a re-split once collapsed, and it is the durable "fix forward" for this whole tier.

`persist-with-rds`), same files (`.deploy-sls.yml`, `serverless.yml`, `environment.ts`), same axis.

## the standalone sub-issues — highest consequence, already filed

fix each; this wish owns the drive to done.

### #572 · D27 — `old-stage-enum` guesses the axis of `Stage.DEVELOPMENT`
the only **silent infrastructure break** found; survives every gate, breaks only below prod.
`old-stage-enum` resolves `Stage.DEVELOPMENT` (value `'dev'`) to `'prep'` — but the member was
overloaded across two axes (access tier vs deploy stage). a stage-axis occurrence is silently
corrupted, so a prep deploy grants IAM on `infrastructure-dev-…` while code requests
`infrastructure-prep-…` → no permission, no table, surfaced as latency. **fix:** a regex that cannot
know the axis must emit a `@declapract:review` marker and leave the file in violation — never guess.

### #573 · D28 · D29 · D31 — a practice stamps a caller without its callee
one root, three grains:
- **D28** — `cicd-service`'s 4 rds jobs reference files `persist-with-rds` owns; guard them behind
  `persist-with-rds`. today no repo on 2 of 3 service use-cases can pass its own `provision` workflow.
- **D29** — `deploy.yml` must pass `pagerduty-integration-key` to `.deploy-sls.yml`; today prod alerts
  are dead in every repo this practice stamps, and the failure is a **skipped** step (silent).
- **D31** — `.deploy-sls.yml`'s acceptance step must translate access→stage, as its deploy step already
  does; fails as `ResourceNotFoundException` (misattributed to deploy/creds).
**the durable ask:** a caller↔callee reconciliation guard — reconcile every `uses:` against the
callee's declared `inputs:`/`secrets:`, and every multiply-consumed input against each consumer.

### #574 · D51 — the `domain` practice requires a file `directory-structure-src` forbids
every repo in `typescript-project` carries a contradiction no state satisfies: `domain` requires
`src/domain/objects/index.ts`; `domain-dir` forbids every file under `src/**/domain/**`. `domain-dir`
ships a rename `fix`, so a pre-migration repo is **walked through** the conflict into a terminal,
unrepairable state. **fix:** migrate the `domain` practice to the `src/domain.objects/` layout its kin
enforces, plus a lint that fails when a `best-practice/` path is matched by a `bad-practices/` glob in
the same use case.

- **#547** — `.dpdmrc.yaml` template clobbers repo excludes with `exclude: []` instead of a merge.

## the durable guards — worth more than the point fixes

these are the "fix forward" that stops the whole class from a repeat. prefer to build these over a patch
of each row in isolation, where the effort is justified:

1. **caller↔callee reconciliation** (unifies D28 · D29 · D52 · D34's second half) — when a practice
   emits a reference (a workflow input, a job name, an import path, a secret), assert that some practice
   in the resolved set supplies the referent.
2. **a fix must not create a violation** (from #574) — evaluate a proposed `fix`'s output path against
   every other declaration in the use case; refuse or warn when the repair lands the file in a state
   another practice forbids. today a fix is checked only against the check that invoked it.
3. **a rewrite that emits a value must not guess** (from #572) — an enum→string-literal rewrite destroys
   the very type-check that would catch a wrong axis; emit a `@declapract:review` marker instead.
4. **make check polarity explicit** (from #574) — `FileCheckType.EXISTS` means opposite things under
   `best-practice/` vs `bad-practices/`; surface the sign in the declaration (`ABSENT`, or a `polarity`
   export) rather than derive it from a path segment.
5. **`declapract plan` should report "this check could not fire"** separately from "this check passed"
   — surfaces most of the silent roster (D39 · D41 · D50 · D54) at once.
