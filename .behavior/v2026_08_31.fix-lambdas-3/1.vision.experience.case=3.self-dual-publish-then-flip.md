# case=3 — self-dual-publish-then-flip

**actor** operator · **feel** happy · **care** critipath · the operator's migration arc

> ⚠️ `[tn]` demos are illustrative sketches — no code exists yet.

## narrative

vlad operates `svc-gateway`. its own acceptance suite (D31) calls `svc-gateway-prep-*`, but the
deploy names the fleet `svc-gateway-dev-*` — so the suite cannot pass against a real prep deploy. the
fix is not to patch the suite; it is to make self publish its own `-prep-` fleet.

vlad flips the transition-mode flag in `serverless.yml`. the next deploy publishes both
`svc-gateway-dev-*` and `svc-gateway-prep-*`. self is now `Contemp`. the acceptance suite, which
addresses self with `sdkAwsLambdaEnvAccessContemp`, lands on `svc-gateway-prep-getX` — and clears.
only then does vlad start the outbound flips to peers.

the aha: **self migrates first.** you cannot honestly ask a peer to publish `-prep-` until your own
suite proves the pattern against your own `-prep-` fleet.

## bdd

```
given svc-gateway, self not yet dual-published (only svc-gateway-dev-* live)
  and its acceptance suite addresses self with `sdkAwsLambdaEnvAccessContemp` (→ prep)

when [t0] the suite runs against the prep deploy, pre-dual-publish
  then it fails `ResourceNotFoundException: svc-gateway-prep-getX`                             # D31, today
  and the failure is loud and names the exact absent function

when [t1] vlad enables transition-mode dual-publish and deploys
  then `sls deploy --stage dev` and `--stage prep` each produce their OWN CF stack             # ✅🟡 per-stage stacks
  and both svc-gateway-dev-* and svc-gateway-prep-* are live
  and each stack is ~75 resources, under the per-stack 500 cap (not one stack of ~150)

when [t2] the acceptance suite re-runs against prep
  then it addresses `svc-gateway-prep-getX` and clears                                         # self is Contemp
  and D31 is green out of the box, no per-repo patch

when [t3] vlad audits self's endpoint readiness
  then self appears as Contemp, never in `grep AccessAncient`
  and vlad may now flip outbound peer calls (case=2)
```

## the fail-safe (sharp edge inside a happy arc)

`[t0]` is the sharp moment, and it fails safe: the suite does not silently skip the deployed grain —
it fails **loud**, names the exact `-prep-` function that is absent, and points the operator at the
fix (dual-publish self). contrast the pre-wish world where the same suite defaulted to `-test-` and
failed even more confusingly. the demo shows the loud-and-teaches property `rule.require.failfast`
demands.
