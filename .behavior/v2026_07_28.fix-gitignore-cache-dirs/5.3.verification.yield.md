## the known gaps, and why they are not closable here

**three, and they share one root:** `defineExpectedGitignoreContents` models a `.gitignore` as a
list of pattern strings, while a real one also has line endings, comments, and a tail whose order
carries load. all three are collected in `5.4.followon.crlf.md`.

| # | gap | how it bites |
|---|---|---|
| 1 | **CRLF** — the tail is matched by exact string equality, so CRLF-split lines miss it | a duplicated `node_modules` block with an inert hoisted negation — the exact defect class this behavior exists to prevent, reached by a different route |
| 2 | **a comment sorts away from its subject** — a `#` line is neither ordered nor empty, so it is sorted like a pattern; `#`(35) < `*`(42) < `.`(46) puts it at the top of the file | the annotation survives but now annotates the wrong region (`rule.forbid.surprises`) |
| 3 | **the emitted tail carries no signal that its order carries load** — ⚠️ **maintainer half FIXED this round** | invites the tidy-up that hoists a negation above its target — gap 1's failure mode, by a human edit rather than a parse bug |
