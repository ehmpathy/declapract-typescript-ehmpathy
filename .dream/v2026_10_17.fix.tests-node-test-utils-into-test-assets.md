# 🌙 dream: move the tests-node test utils into `src/.test/assets/`

| | |
|---|---|
| kind | fix |
| owner | `ehmpathy/declapract-typescript-ehmpathy` — `src/practices/tests-node/` |
| caught | 2026-10-17 |

## .the cue that fired

`rule.forbid.test-assets-in-src` names `src/.test/assets/` as the home of a test-only asset. the
persist-with-rds testdb utils moved there this round, since they had never shipped. the tests-node
utils have shipped, so they stayed where they were.

## .the gap, precisely

- `best-practice/src/.test/useKeyrack.ts`, `useWakeOfLivedb.ts`, `useWakeOfTestdb.ts` sit directly
  under `src/.test/`, not `src/.test/assets/`
- `best-practice/jest.integration.env.db.ts` (`probeTestDb`) sits at the template root, outside
  `src/`
- all four are imported only by `jest.*.env.ts` / `jest.*.prepare.ts`; no prod path ships them
- shipped: the last commit to touch them is `b8d4803`

## .the shape of the fix

1. move the four into `best-practice/src/.test/assets/` (e.g. `assets/keyrack/`, `assets/livedb/`,
   `assets/testdb/`), and update every import in `jest.*.env.ts` and `jest.*.prepare.ts`, plus the
   `after:` anchors in `jest.integration.env.ts.declapract.ts`
2. add a tests-node bad-practice that deletes each old path in an adopter: `contents: null` where
   the file still matches the shipped template, a `@declapract:review` marker where it was edited
3. clamp it with an integration test: an adopter on the old paths applies, lands on the new paths,
   the old files are gone, and a second apply changes zero (`rule.require.idempotent-fixes`)
4. resnap the suites that snapshot the env templates (persist-with-dynamodb, tests-node)

## .why it is not done in this round

safe, but not clean. each move rewrites declared paths in every adopter and owes a migration
bad-practice and its own integration test. that ripples beyond this round's diff. the deferral
is recorded as fulcrum F108.
