# 🌙 dream: git.release names a review wait, and exits fast on it

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy · caught 2026-11-15

## .the cue that fired
the require-main-review vision needed the release-pr pause to fail safe. a read of
`git.release._.emit_transport_watch.sh` (1.42.0) showed it does not.

## .the gap, precisely
once checks pass with automerge on, the watch polls `await automerge` (line ~229) until its
15-minute timeout, then prints `⏰ timeout` and exits 2. `git.release.operations.sh` reads
`mergeStateStatus` but never `reviewDecision`. on a repo whose main requires a review, every pr
and every release pr hits a 15-minute wait that ends in a false timeout, with no word that a
human approval is owed.

## .the shape of the fix
- add `reviewDecision` to the `gh pr view --json` fields in `get_pr_status`
- in the watch: checks done + `reviewDecision == REVIEW_REQUIRED` → print
  `🫧 await review: a human with write must approve` plus the pr url, and exit 2 at once
  (constraint), rather than poll to timeout
- `--into prod`: the same at the release pr step
- snapshot the new stdout

## .why it is not done in this round
it lives in another repo. it should land before a commander applies the review rule fleet-wide.
