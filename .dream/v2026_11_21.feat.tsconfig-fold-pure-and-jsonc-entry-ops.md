# 🌙 dream: make the ts7 tsconfig fold pure; lift the jsonc entry ops; guard template `types` deps

kind: feat · owner: declapract-typescript-ehmpathy · caught 2026-11-21

## .the cue that fired
a peer review of the ts7 pr (r011, i007) named three structural gaps, each graded `better`. fulcrum F19 holds the first.

## .the gap, precisely
- `src/utils/asTsconfigWithTs7OptionsFolded.ts` carries an `as*` name but reads disk (`getAllBaseUrlEntries`) for a nested `baseUrl`, and `root` threads through to feed it. an org read found 65 `baseUrl` repos, all at `"."`, so the nested branch (about 150 lines) serves no known adopter.
- `asSplicesToRemoveEntry` and `asContentsWithEntryRemoved` are generic jsonc entry ops, but sit private in a ts7-specific file.
- the `types: ["node", "jest"]` → `tests-any` dep invariant is pinned for one pair, inside `cicd-app-react-native-expo/.declapract.integration.test.ts`.

## .the shape of the fix
- either cut the nested branch (the fold becomes pure and takes no `root`; a nested `baseUrl` gets a check-only practice with a notice, like `imports-not-used-as-values-kept`), or split the seam: an orchestrator reads the value, a communicator lists the dir, and a pure `as…Folded({ contents, entries })` takes the dir entries
- lift `asSplicesToRemoveEntry` + `asContentsWithEntryRemoved` to their own files in the jsonc cluster, each with a caselist test (ride with `v2026_11_21.feat.lift-span-splice-fold.md`)
- beside `practiceTemplateImportsDeclared`, assert that each `types` entry of every tsconfig template maps to a package declared by a practice in the same usecase; drop the pair test

## .why it is not done in this round
the fold is correct on 95 real tsconfigs, and its disk-read test now sits at integration grain. each move reshapes practices, fixtures, or a cross-practice suite: its own reviewed change, not a rider on a compiler upgrade.
