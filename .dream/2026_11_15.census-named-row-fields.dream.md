# 🌙 dream: census rows with named fields, and a sound rollout check

- kind: refactor
- owner: declapract-typescript-ehmpathy
- caught 2026_11_15

## .the cue that fired

the execution review of `feat-require-main-review` found three seams in
`rhx github.main-review.census`:

- the row schema is positional in three places (`emit_row`, `render_table_rows`, `count_rows`)
- `get_one_pr_decision` returns a tab-packed string the verdict ladder parses back
- a rerun after a rollout reads `inferred` rows that lag the gate

## .the gap, precisely

a new field needs three coordinated edits, and a missed one miscounts the tally with no loud
failure. the verdict ladder decodes a string where a named value would serve. a push token cannot
verify a rollout with `certain` rows.

## .the shape of the fix

- declare the column order once (`ROW_COLS=(slug release verdict signal perm basis)`), and look up
  each index by name in the render, the sort and the count
- have the pr reader return a verdict word plus the pr number as named outputs
- probe whether graphql `branchProtectionRules` is readable with a push token; if so, read
  `requiresApprovingReviews` there and mark those rows `certain`
- the play test already pins the output, so each step proves itself

## .why it is not done in this round

the review lanes ran dry, and the pr has one commit of quota left. the census tally is pinned by 36
hermetic cases today, so no miscount ships.
