# case=3: the release pr waits for a review

feel: sharp · care: critipath. the open question for the commander.

## .narrative

a feature pr merges. please-release opens `chore(release): v0.7.3 🎉` as the rhelease app.
the mechanic runs `rhx git.release --into prod --apply`. before, the release pr merged once
green, the tag was cut, and prod deployed. now the release pr waits for an approval like any
other. a human glances at the version bump and the changelog and approves. the release merges,
the tag is cut, prod deploys.

## .does it fail safe? not yet, legibly

the gate itself fails safe: github refuses the merge, so no unreviewed release ships. the
**watch** does not teach the fix. `git.release` (rhachet-roles-ehmpathy 1.42.0) never reads
`reviewDecision`. once checks pass with automerge on, it polls `await automerge` for 15 minutes,
then prints `⏰ timeout` and exits 2 (`git.release._.emit_transport_watch.sh`, ~line 229). the
mechanic sees a timeout, not "a review is owed".

the fallback is workable: `gh pr view <n> --json reviewDecision` reads `REVIEW_REQUIRED`, the pr
page says the same, and the timeout exits 2, so the run never reports a false success. that makes
the watch's legibility a sharp **alterpath** layered over the critipath (the refusal), not a
critipath of its own.

the fix lives upstream (dream `2026_11_15.reseed-git-release-names-review-wait`): read
`reviewDecision`, print `await review`, exit fast. it should land before a commander applies the
review rule fleet-wide.

the release pr is the merge that triggers a prod deploy (`production-on-main` declares
`reviewers: null — PR merge is the gate`). a review there makes that gate a real one.

an exemption is not expressible in this practice today:
- declastruct-github 1.4.0 classic protection has no `bypass_pull_request_allowances` field
- its rulesets carry no `pull_request` rule type
- `enforceAdmins: true` closes the admin path

an exemption needs an upstream declastruct-github change first.

## .bdd sketch

```
given main requires one approval
  given a release pr by the rhelease app
    when [t0] its checks pass and `git.release --into prod --apply` watches
      then the release pr does not merge
      then github refuses the merge (the gate holds)
      then today: the watch polls `await automerge`, then `⏰ timeout` after 15m (illegible)
      then after the upstream fix: the watch prints `await review` and exits at once
    when [t1] a human approves
      then the release pr merges
    when [t1b] another pr merges to main before the release pr does
      then release.yml rewrites the release pr, and the rewrite drops its approval
      then the release pr waits for a fresh approval (approve after the last merge to ship)
    when [t2] release.yml runs on main
      then the v* tag is cut and the prod deploy runs
```
