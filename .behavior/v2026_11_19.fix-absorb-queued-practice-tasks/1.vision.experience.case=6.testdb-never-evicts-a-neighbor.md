# case=6 — `start:testdb` never evicts a neighbor (e8, chosen alterpath)

## .narrative
two clones share one grove. one works in svc-notifications, the other in svc-jobs; both repos declare testdb port 7821, as the template does for every rds repo.

on 0.50.0, the svc-notifications clone runs `start:testdb`, applies its schema, and starts its integration suite. minutes later the svc-jobs clone runs `start:testdb`. its clear step runs `docker rm -f` on every container that publishes 7821, and the svc-notifications testdb vanishes mid-suite. the svc-notifications clone sees only `password authentication failed`, a message that points at its config, not at its neighbor. it spends an hour on credentials that were never wrong.

after the upgrade, the svc-jobs clone runs `start:testdb`. its clear step removes only its own compose project. the port is still held, so `start:testdb` halts before `up`: `✋ ConstraintError`, the holder named (the svc-notifications container and its project), and two fixes (stop that container, or move this repo's declared port). the svc-notifications clone's suite never notices. the svc-jobs clone picks a fix in one read.

## .timeline
```
given('a clone in svc-notifications with a live testdb on 7821, mid-suite')
  given('a clone in svc-jobs, whose repo also declares 7821')
    when('[t0] the svc-jobs clone runs npm run start:testdb')
      then('the svc-notifications container is untouched; its suite passes')
      then('the svc-jobs clone reads exit 2: ConstraintError names the holder of 7821 and the fix')
given('a clone in svc-jobs whose own stale container, under its current compose project, holds 7821')
  when('[t0] it runs npm run start:testdb')
    then('clear removes its own project; up starts a fresh testdb; the schema applies; exit 0')
given('a clone in svc-jobs whose own testdb, under an older compose project name, holds 7821')
  when('[t0] it runs npm run start:testdb')
    then('exit 2: ConstraintError names the holder and its project; the first fix offers docker rm -f on that one container')
given('a clone whose port 7821 is held by a container in no compose project')
  when('[t0] it runs npm run start:testdb')
    then('exit 2: ConstraintError names the holder (no compose project); no docker rm -f is offered')
```

the three held-port answers are clamped by `testdb-per-worktree` [case8] ([t5] bare holder, [t6] own older-project holder) and [case10] (a real neighbor container under a real docker daemon).
