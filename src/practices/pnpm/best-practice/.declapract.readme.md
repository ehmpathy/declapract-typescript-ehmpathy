# pnpm best-practice — what this practice owns, and what it does NOT

this practice owns the pnpm **adoption** signal: the `packageManager` exact pin
(`pnpm@10.31.7`, an intentional org-convergence requirement — see the `.declapract.ts` note).

## where the hoisted-linker `.npmrc` lives — NOT here

the pnpm-only `.npmrc` directives an expo repo needs (`node-linker=hoisted`,
`public-hoist-pattern[]=*expo*`, …) are declared by the **`node`** practice, not this one. the
`node` practice owns the whole `.npmrc` (it is the package-manager-config file), and its declaration
is usecase-aware: it findserts the hoist block only when the `cicd-app-react-native-expo` usecase is
present.

so an auditor of all that pnpm needs should also read:

- `src/practices/node/best-practice/.npmrc.declapract.ts` — the usecase-aware `.npmrc` declaration
- `src/utils/defineExpectedNpmrcContents.ts` — the shared base + expo-hoist line source
- `.agent/repo=.this/role=any/briefs/howto.pnpm-expo-hoisted-linker.md` — why the flat linker is
  required for metro/expo, and the transitive-skew gotcha it exposes

the split is deliberate: the `.npmrc` is one file with one owner (`node`), so a repo gets a single
coherent `.npmrc` rather than two practices that fight over it.
