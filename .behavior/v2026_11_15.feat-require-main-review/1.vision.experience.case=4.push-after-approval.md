# case=4: a push lands after the approval

feel: sharp · care: critipath. common (the bot fixes nits after a reviewer approves), and its cost
is the harm the wish targets: unread code on main, with no way back once merged.

## .narrative

a human approves a bot pr, with two nits. the bot pushes a commit that fixes them. with
`dismissStaleReviews: true`, github dismisses the approval: the pr reads "review required" again,
and automerge holds. the human reads the new commit and re-approves. it merges.

the cost of the fail-safe: github's docs name **Update branch** among the changes that dismiss an
approval, and `strict: true` forces an update each time main moves. a pr open across a main merge
needs a second click. that is friction with a workable route; the alternative, `false`, lets the
nit-fix commit merge unread.

## .bdd sketch

```
given main requires one approval, dismissStaleReviews = true
  given a bot pr a human approved, automerge on
    when [t0] the bot pushes a new commit
      then the approval is dismissed
      then reviewDecision = REVIEW_REQUIRED and the merge is refused (fails safe)
    when [t1] the human re-approves
      then automerge merges

  when [t2] main moves and the pr is updated (strict)
    then the approval is dismissed again; a human re-approves (the accepted friction)

given dismissStaleReviews = false (the alternative, rejected)
  when [t0] the bot pushes after approval
    then the pr merges with the new commit unread
```
