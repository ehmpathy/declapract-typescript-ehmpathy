# 🌙 dream: keep an adopter's relative `extends` base; read the typescript6 pin from one place

kind: feat · owner: declapract-typescript-ehmpathy · caught 2026-11-21

## .the cue that fired
a peer review of the ts7 pr (r011, i006) named two gaps in the typescript-node declarations that it graded `better`.

## .the gap, precisely
- `typescript-node/best-practice/tsconfig.json.declapract.ts` swaps `extends` whole. so an adopter's own relative base, e.g. `./tsconfig.local.json`, vanishes on apply. the swap is deliberate: a prior package base kept after the template's would override it. but a relative base is the adopter's local layer, not a rival package base.
- `compiler-api-from-typescript/src/**/*.ts.declapract.ts` hard-codes `@typescript/typescript6@6.0.2` in its notice and its test. no declared file holds that pin, so a bump must edit both by hand.

## .the shape of the fix
- in the best-practice fix: keep each found `extends` entry that leads with `./` or `../`, placed after the template bases. still swap every package specifier. a unit case covers `["@tsconfig/node18/tsconfig.json", "./tsconfig.local.json"]` → template bases + `./tsconfig.local.json`.
- declare the typescript6 pin once (a const beside the declaration, or the typescript-node `best-practice/package.json` if a dep is ever declared there). the notice and its test read it.

## .why it is not done in this round
the relative-base keep changes what every adopter's tsconfig resolves to, which is its own reviewed behavior change. the pin is cosmetic until the next typescript6 release. neither ships harm today.
