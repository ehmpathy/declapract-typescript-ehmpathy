# case=6: the census reads the fleet, read only

feel: happy · care: critipath

## .narrative

the commander wants to know which repos would gain a review gate. the mechanic runs
`rhx github.census.main-review`. it lists each non-archived, non-fork repo across ehmpathy,
ahbode, whodisio, and uladkasach, and verdicts each: requires, lacks, or unknown. every call is a
GET. the table lands in the pr body.

the token holds push, not admin, so the classic protection endpoint 404s. the census reads two
signals a push token can read instead:
- an active ruleset `pull_request` rule on main
- the graphql `reviewDecision` of the latest pr into main, which github leaves empty when no
  review is required

## .bdd sketch

```
given a push-scoped token
  when [t0] `rhx github.census.main-review` runs
    then it issues GET calls only
    then each repo gets one verdict and the signal behind it
    then the table is kept at .log/github.census.main-review/census.md
  when [t1] a repo's main is unprotected
    then its verdict is `lacks` (main unprotected)
  when [t2] a protected repo has no pr into main
    then its verdict is `unknown`, never a guess
```
