## defect

`persist-with-rds`'s testdb preflight probe hid the real cause of a preflight failure. three faults in one probe:

1. it swallowed psql stderr with `> /dev/null 2>&1`, so the true cause never surfaced.
2. it printed one hardcoded line on timeout (the "postgres too long" message), so a bad password, a port conflict, and an image build failure all read identically.
3. it passed the secret inline in the connection string (`password=$POSTGRES_PASSWORD`), which leaks it to `ps`.

folds → case=6 (silent-check / failhide fail-safe): a probe that reports one hardcoded cause regardless of the true one is a failhide.

## fix

`best-practice/provision/docker/testdb/wait-for-postgres.sh`:

- export `PGPASSWORD="$POSTGRES_PASSWORD"` and drop the inline `password=` from the connection string.
- capture the probe stderr into `lasterr=$(psql "..." -c '\l' 2>&1)`, break on `$? -eq 0`.
- on timeout, echo the captured `$lasterr` to stderr alongside a "did not accept connections after ${maxcounter}s" line, then exit 1.

## clamp

`src/practices/persist-with-rds/testdb-preflight-failloud.declapract.test.ts` — 5 assertions across 3 `when`s: no `/dev/null` swallow, stderr captured (`lasterr=$(psql` + `2>&1`), captured error echoed on timeout, the single hardcoded line gone, secret via `PGPASSWORD` not inline.

teeth confirmed: revert the fix (restore `> /dev/null 2>&1`, the inline password, the one hardcoded line) and each assertion goes red.
