# case=4 · drifted tsconfig meets typescript 7

feel: sharp · care: critipath · actor: adopter (catalog row 3; dev and ci collapse here, rows 11–12)

## .narrative

a repo hand-edited its tsconfig years ago: `"baseUrl": "./src"`, `"paths": { "~/*": ["*"] }`, `"moduleResolution": "node"`. the `CONTAINS` check never saw the extra keys. the upgrade raises typescript to 7.0.2. without help, `test:types` would die on removed-option errors, and the maintainer would hunt the release notes.

instead, `declapract plan` flags the bad-practice `tsconfig-options-removed-in-ts7`, and one `declapract apply` lands the whole tsconfig on the shape 7 accepts:
- the bad-practice fixes first. it rebases each of the repo's own `paths` values onto `baseUrl` (`"~/*": ["./src/*"]`), adds one key per top-level entry of `./src` (`"logic/*": ["./src/logic/*"]`) so bare imports keep the lookup `baseUrl` gave them, then drops `baseUrl` and `importsNotUsedAsValues`
- the best-practice then adds the template's `paths` on the tsconfig dir, adds `types`, and sets `moduleResolution` + `module` to `node16`, as it did before this pr

no part is manual. `node16` is not new to the repo: the best-practice already forced it, so a deep import a package's `exports` map blocks was already a break of the prior upgrade, and tsc names each one.

the lookup keys are named, never a `"*"` catch-all: tsc-alias skips a key with no prefix, so `require("logic/x")` would ship in `dist` and fail at runtime. a named key is rewritten to `require("../logic/x")`. a `baseUrl` with no `paths` folds to a `paths` block of the same keys. a root `baseUrl` (`"."`) gets none: its aliases map the same files once led with `./`, and no adopter imports bare from the repo root (an org-wide search for `from 'src/` finds none in code). (F7, F14)

## .timeline

```
given('a node repo whose tsconfig keeps baseUrl ./src, its own paths, and moduleResolution node')
  when('[t0] the maintainer runs `declapract plan`')
    then('the bad-practice tsconfig-options-removed-in-ts7 is flagged, with an automatic fix')
  when('[t1] the maintainer runs `declapract apply`')
    then('the repo's own paths gain the ./src/ prefix, one key per dir of ./src keeps bare imports; baseUrl + importsNotUsedAsValues are gone')
    then('the template paths land on the tsconfig dir, never rebased onto ./src')
    then('moduleResolution lands on node16, set by the best-practice')
    then('a re-run of `declapract apply` is a no-op')
  when('[t2] the maintainer runs `npm run test:types` and `npm run build` on typescript 7')
    then('bare imports and aliases each find their file, as they did under baseUrl')
    then('tsc-alias rewrites both to relative paths in dist')
  when('[t3] the repo's baseUrl roots bare imports with no paths')
    then('the apply swaps baseUrl for a paths block of lookup keys, so bare imports still find their files')
```

proof: `src/practices/typescript-node/tsconfig-options-removed-in-ts7.declapract.integration.test.ts` [case2] `[t0]` for `[t1]`, `[t1]` for `[t2]` (tsc 7.0.2 + tsc-alias on the folded fixture); the bad-practice integration test [case3] for `[t3]`.
