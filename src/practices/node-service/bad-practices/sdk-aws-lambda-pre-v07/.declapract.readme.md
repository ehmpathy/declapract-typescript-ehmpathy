# sdk-aws-lambda-pre-v07

## what

moves a repo already on sdk-aws-lambda below 0.7 onto the `0.7.2` floor the node-service practice
declares (#646, #670).

## transforms

| before 0.7 | 0.7.2 |
|---|---|
| `genLambdaEndpoint(…)` | `genLambdaEndpoint.forAsk(…)` |
| `genLambdaEndpoint.for.apiGateway(…)` | `genLambdaEndpoint.forApiGateway(…)` |
| `invoke: async ({ event }) => … event.x …` | `invoke: async ({ payload }) => … payload.x …` |
| `pnpm.patchedDependencies["sdk-aws-lambda@0.7.0"]` or `["sdk-aws-lambda@0.7.1"]` + its patch file | deleted (the floor ships the fixes) |

a shorthand property in the body keeps its key: `{ event }` becomes `{ event: payload }`.

a patch at or above the floor is the consumer's own choice and stays.

## what to expect on 0.7.2

on sdk-aws-lambda >= 0.7.2, a cors-configured `forApiGateway` endpoint lists `x-trail-exid` in
`Access-Control-Allow-Headers`. a test that pins the old list goes red; append `x-trail-exid`, or
assert with `toContain`.

## limitations

an sqs handler built on `extractTaskParcelFromSqsEvent` gets a `@declapract:review` marker, never a
rewrite: its move onto `genLambdaEndpoint.forSqs.perRecord` needs a `z.custom` task-parcel schema
and a `batchSize: 1` event source, which is a design call.
