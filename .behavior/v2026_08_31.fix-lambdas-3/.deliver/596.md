## the fix — key the deployment bucket by stage, so each deploy's bucket sits in its role's account

`serverless/best-practice/serverless.yml` hardcoded a single stage-suffixed bucket
(`deploymentBucket: serverless-deployment-<ns>-${self:provider.stage}`). the deployment bucket is
ACCOUNT-scoped, not merely service-scoped: it must live in the same account the deploy role assumes.
a prod deploy assumes the prod-account oidc role (`ahbode-prod-oidc-for-apply`), which has no
cross-account grant to the prep-account `-dev` bucket, so `sls deploy --stage prod` fails at bucket
lookup (`s3:GetBucketLocation ... not authorized`). found live on a prod deploy of svc-gateway
(v0.73.5), on `main`.

mirrored the extant `accessByStage` pattern with a `custom.deploymentBucketByStage` map:
- **dev + prep** → the shared prep-account `-dev` bucket (self dual-publishes both fleets into the one
  prep-account bucket, so no separate `-prep` bucket need exist).
- **prod** → a prod-account `-prod` bucket.

and changed the provider line to reference it:
`deploymentBucket: ${self:custom.deploymentBucketByStage.${opt:stage}, '...-dev'}`. so every deploy's
bucket sits in the account of its role. added a readme section + a provider-line comment that names
the provision requirement: the `-prod` bucket must be provisioned in the prod account (e.g. via the
terraform under `provision/aws/environments/prod/`), or the fix trades a cross-account-deny for an
absent-bucket error.

this is the deploy-bucket facet of the same prep→dev account divergence as #577 / the D27 cache-IAM
dual-grant; it collapses with the rest at the north-star `stage`→`access` endpoint.

## bounds / not-done

- **no fix transform added, by design.** the `deploymentBucket` line has NO transform in the
  serverless declaration's 16-transform fold — it is, and stays, a CONTAINS-declared line (a legacy
  consumer that lacks the new map leaves `declapract plan` RED, a visible signal, never a silent
  pass). that matches the line's status quo; a value-emit transform that captured the namespace and
  rewrote two locations (custom map + provider reference) across partial-migration states is a larger,
  fragile build, not warranted by this ticket (which asks for the template shape). flagged as a clean
  rework if the wisher wants auto-migration for the bucket line.
- **the `-prod` bucket provision** is an account-side terraform step (a human-gated live apply), not a
  declapract concern — named in the readme + the provider-line comment, out of this template's reach.
