# 🌙 dream: an absent `serverless.yml` names what to do, or is created

- kind = fix
- owner = ehmpathy/declapract-typescript-ehmpathy
- caught 2026-10-16, on route `.behavior/v2026_09_29.fix-absorb-recent-upgrade-reports`

## .the cue that fired

the 5.3 ergonomics review walked `lambda-service-with-rds` on a fresh repo. five of the six
absent-file `FIX_MANUAL` rows now name what to author (`src/utils/asPresenceCheck.ts`). the sixth
still reads:

```
  * [FIX_MANUAL] serverless.yml
    ✕ practice:serverless.best-practice
      - Expected file to exist
      + Received file does not exist
```

## .the gap, precisely

- `serverless/best-practice/serverless.yml.declapract.ts` checks `CONTAINS` and its `fix` returns
  an absent file unchanged (`if (!contents) return { contents }`)
- `CONTAINS` owns the message, so the presence-check swap used for the five other rows does not
  apply here without a hand-rolled contains
- an adopter on a fresh service sees a row that does not say a serverless template exists, nor how
  to get it

## .the shape of the fix

pick one, with a test either way:

1. **create it** — when `contents` is null, the fix returns the declared contents (the template,
   runtime from `.nvmrc`), so a fresh service gets a whole `serverless.yml` on apply; prove it with
   an `executeApply` integration test on a bare repo, plus a twice-applied no-op
2. **name it** — keep the skip, and wrap `check` so a null file throws
   `expected serverless.yml; copy the serverless practice template, then apply again`, and else
   defers to the `CONTAINS` comparison

## .why it is not done in this round

safe, but not clean: option 1 changes what `apply` writes for every lambda-service adopter that
lacks the file, and option 2 needs a contains comparison this repo does not yet own. neither was
raised by a report in the wish. fulcrum F100.
