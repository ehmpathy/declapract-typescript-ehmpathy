# case=4 — value-rewrite-refuses-to-guess

**actor** practice-maintainer · **feel** SHARP · **care** critipath · D27, the worst roster row

> ✅ the value-rewrite-refuses-to-guess mechanism SHIPPED in this wish —
> `environments/bad-practices/old-stage-enum` leaves `Stage.DEVELOPMENT` in place and inserts a
> `// @declapract:review:` marker rather than guess a value (D27). the `[tn]` demos trace that fix.

## narrative

D27: the `old-stage-enum` bad-practice rewrites `Stage.DEVELOPMENT` → a string. today the enum
member is overloaded across two axes that **disagree** below prod — the access tier wants `'prep'`,
the deploy stage wants `'dev'`. a regex cannot know which, so it guesses `'prep'` uniformly and
silently corrupts the stage-axis occurrences (a prep deploy grants IAM on `infrastructure-dev-…`
while code requests `infrastructure-prep-…`).

the north star dissolves the ambiguity at its root. once the `stage` axis collapses onto `access` —
every resource keyed by `access`, every deploy run as `--stage ${access}` — `'prep'` is the one
correct value everywhere the enum appears in app code. there is no second axis left to be wrong
about, so the rewrite emits `'prep'` uniformly and it is right by construction.

the one `-dev-` string that survives the collapse is a cross-service call **target** — a peer still
published under its `Ancient` name. that value is NOT a blind enum-rewrite; it lives in the typed
`sdkAwsLambdaEnvAccessAncient` helper — `tsc`-checked, ledger-counted (`grep AccessAncient`). so the
sole place that must still think in `dev` is explicit, typed, and countable, never a regex guess.

the aha: **you do not teach a regex to guess the axis — you delete the axis.** after the collapse
the enum has one answer (`'prep'`); the lone `-dev-` survivor is quarantined in a typed helper, where
a wrong value is a compile error, not a silent runtime break.

## bdd

```
given a consumer file with `Stage.DEVELOPMENT` in app code (an access-tier concern)
  and the north-star collapse applied (resources keyed by access, --stage ${access})

when [t0] the rewrite runs
  then it emits `'prep'` uniformly
  and 'prep' is correct because every resource is now access-keyed             # the collapse designed out the divergence
  and no wrong-axis value can be emitted — there is no second axis to reach for

when [t1] the same file holds a cross-service lambda TARGET name
  then that value is NOT rewritten to a bare string literal
  and it is authored via `sdkAwsLambdaEnvAccessAncient` (emits 'dev' for an unmigrated peer)  # ✅ tsc-checked helper
  and `grep AccessAncient` counts the debt — one line to flip once the peer migrates

when [t2] the peer dual-publishes its `-prep-` name
  then the call flips `Ancient -> Contemp` (one line)
  and `grep AccessAncient -> 0` marks the exit
```

## the fail-safe

this is a fail-safe by **contract**, the same shape as case=7. the sharp edge — a silent wrong-axis
IAM grant (D27) — is made **unreachable**, not merely warned against: the axis collapse leaves
`'prep'` as the one representable value in app code, so the wrong value cannot be written. the lone
genuine `-dev-` survivor is quarantined in the typed `sdkAwsLambdaEnvAccess{Ancient|Contemp}` helper,
where `tsc` guards it and the ledger counts it. the pit-of-success: the easy path (emit `'prep'`, or
call the typed helper) is the only correct path, and the dangerous path (a guessed divergent value)
is not expressible.

> **a note on #572, and the wish item it supersedes.** the wish proposed a general guard — *a
> value-rewrite that cannot know its axis must emit a `@declapract:review` marker rather than guess*
> — and named D27 its poster child. the collapse removes D27's ambiguity entirely: with one axis,
> the rewrite has one answer, so there is no guess to refuse. so this row no longer needs the marker,
> and #572 drops from a load-bearer guard to an optional note that may still serve OTHER
> value-rewrites. the stronger fix is to design the ambiguity out, not to defer it to a human.
>
> **the assumption this rests on** (flag for the wisher): every app-code `Stage.DEVELOPMENT` is an
> access-tier concern → `'prep'`. the sole deploy-slug/target concern lives in the SDK helper. if a
> non-target deploy-slug occurrence exists in app code, it must move to the helper too — it is never
> a bare rewritten string.
