a tsconfig that sets `importsNotUsedAsValues` to `"preserve"` or `"error"`.

the typescript-node floor is typescript 7.0.2, which removed the option: any value fails with TS5023.
`"remove"` is the default elision, so the `tsconfig-options-removed-in-ts7` fix drops it with no change.
these two values ask for more than the default, so a drop would change the repo silently:

- `"preserve"` emits a `require` for each import used only as a type. a module that leans on that
  side effect (a registration, a polyfill) would stop to load
- `"error"` fails the build on an import used only as a type. the drop loses that check

to fix, by hand, then delete `importsNotUsedAsValues`:

1. for `"preserve"`: add a side-effect import beside each type import whose module must load,
   `import './register';` next to `import type { X } from './register';`
2. for `"error"`, or `"preserve"` on an esm module: set `"verbatimModuleSyntax": true`, which keeps
   each import as written and asks for `import type` on type-only imports. in a commonjs module it
   fails each esm `import` (TS1286), so it fits only an esm module

no automatic fix is declared: which modules lean on a load is a read of the code, not of the tsconfig.
the rest of the typescript-node tsconfig edits still apply around it (the `baseUrl` fold, `types`);
the option stays as written, so typescript 7 fails loud with TS5023 until the move above is made.
