# 1.vision — absorb the recent upgrade reports

## .the outcome world

every repo that upgrades after this lands meets the latest best practices on the next apply, and
none of the walls its predecessors already reported. every report filed 2026-09-15 onward is closed
by the commit that fixed it, or held open with one comment that names the shipped work outside
this repo it waits on.

### .day in the life — svc-quotes, mid-route

- **before.** `apply` rewrites uni-time imports to `iso-time` and installs no `iso-time`; drops
  `simple-leveled-log-methods` while a wrapper imports it; ships templates that two practices fight
  over, so a second apply still rewrites files. lint passes a stray `.only`; `test:format` needs a
  terraform binary; `test:lint:cycles` needs `yq`. a test run on a dev box borrows the ec2 instance
  role in silence. each wall costs a stone to rediscover, and svc-quotes files the same issue
  svc-chat already filed.
- **after.** those walls are gone, or turned loud. a second apply changes zero files. where a move
  needs a human (an input→context arity change, a param copy), `plan` names the file and `apply`
  stamps a `// @declapract:review:` line that names the move — `plan` itself can name only practice
  and file, never a remedy. the gates run on any box with node. an absent credential fails loud.
  the lambda handlers move to `sdk-aws-lambda@0.7.1` in the same apply. a retired template
  (`getDatabaseConnection.ts`, a hand-written `Config.ts`) leaves, and its importers move with it.

### .the aha

a report filed upstream is answered upstream — fixed for every repo after, or told exactly what it
waits on.

## .the contract of the round

1. every open upgrade report on this repo as of 2026-10-14 (seeds S7, S8, S9, S12, S13) is fixed
   this round, closed with the commit that already fixed it, or held open with one comment that
   names work outside this repo it waits on (seeds S3, S5). none is deferred
   for size or taste (seed S2). a call that would have gone to the wisher is best-guessed and
   itemized as a fulcrum with its rework (`.fulcrums/`, F3–F87).
2. each fix lands with a test that goes red on the pre-fix template (`rule.require.clamp-edge-cases`)
   and, for any fix fn, a twice-applied idempotency case (`rule.require.idempotent-fixes`); a fix
   with logic gets an `executeApply` integration test with before/after snapshots
   (`rule.require.declapract-integration-tests`).
3. one branch, one commit for the whole round, made after the peer reviews pass, so it holds the
   reviewed tree (S17). the pr body lists `closes #NNN`, one line per fixed issue, so every fixed
   issue closes from one release. #613 closes with a comment that cites d372808 / v0.49.13.
4. this repo only (seed S5): every floor names an already-published release; no work is performed or
   filed in another repo. each upstream follow-up is a caught dream in `.dream/`, symlinked at
   `dreams/` (the table in `case=_` § caught dreams).
5. no fix narrows a practice a service relies on; no practice runs a terraform formatter (seed S1).

## .mental model

- an adopter would say: *"the upgrade brings me the latest shape, and no longer breaks my build in
  the places it used to."*
- the reporter would say: *"they took my report and shipped the fix — or told me what it waits on."*
- the metaphor: a river guide who clears every snag the last rafts hit, before the next raft
  launches — and ties a flag only where a rock must be walked around by hand.
- their words vs ours: they say "the upgrade broke X"; we say "a fix fn left the tree unbuildable"
  (B2). they say "lint is red on my laptop only"; we say "local-friction, C1 delivery".
