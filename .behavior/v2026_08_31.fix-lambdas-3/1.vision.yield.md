# 1.vision — the practices stop shipping a two-word lie, and the `stage` axis dies

> ground read on **2026-08-31**. claims marked ✅ were read from a cited file+line in this repo;
> claims marked 🟡 are inferred and named as such. no `npx declapract plan` was run (outside the
> allowlist), and no AWS account was measured (no creds this session) — those are named as open.

this vision covers three coupled deliverables of the wish:
1. **the north star** — retire the `stage` axis so one word (`access`) names every resource.
2. **the roster** — fix the svc-gateway practice defects, each forward, in the templates.
3. **the in-repo companions** — the deploy-runtime, vpc-tunnel, config-param, and codegen-client
   clusters (#551/#552/#553, #519/#523/#539/#562, #544, #549, #532).

they are one vision because most of the roster's worst rows are instances of the `stage`/`access`
split (D27, D31, D52, D53, 4b, 4, D55) — and the companions are more costumes of the same
meta-lesson (*a practice that emits a value cannot verify its own output*). kill the split and fix
the value-emit class, and whole tiers dissolve at once. only the genuinely cross-repo halves (#544's
sdk-config derive via **sdk-config#13**, and **sdk-aws-lambda#18**) stay named companions — a repo
boundary, not a scope choice.

## the outcome world

### the before

it is today. a repo runs the declapract upgrade, then reads the result. the templates hand it a
world where **one fact — which deployment — wears two disagreeing words**:

- ✅ `environments/best-practice/src/utils/environment.ts:7-8` exports `stage = envStatic.access`
  **and** `serviceClientStage`, a dead value (a grep across a real consumer finds zero `src/`
  usages — #579).
- ✅ `serverless/best-practice/serverless.yml:12-14` remaps `accessByStage: { dev: prep }` — so a
  `prep` access deploys under stage `dev`. the template's **own comment** at `:13` states the two-axis
  split verbatim: `# stage=dev deploys to $service-dev but uses ACCESS=prep (config/prep.json)`. so
  the divergence is not my read — it is documented in the template itself.
  - 🟡 the lambda function name `svc-x-dev-*` is **inferred from serverless convention**
    (`${service}-${stage}-${fn}`, and `:21` sets `stage: ${opt:stage}`), not read from a `functions:`
    block — the file I read ends at `:35`. named as inferred, not asserted.
- ✅ that same file names the cache table `infrastructure-${self:provider.stage}-…` (`:90`) and the
  glue db `${databaseName}_${self:provider.stage}` (`:114`) — resources keyed by **stage**, while
  the app reaches them by **access**.

the fault this spawns is the worst kind: **compiler-invisible**. both axes type as `string`, so a
wrong-axis reference is green at build and red only at runtime, against a deployed resource. the
roster is the receipt:

- **D27** — a regex resolves `Stage.DEVELOPMENT` (`'dev'`) to `'prep'`, so a prep deploy grants IAM
  on `infrastructure-dev-…` while code requests `infrastructure-prep-…`. no table, surfaced as
  latency, and a **prod smoke test cannot see it** (prod: access=stage). ✅ the IAM grant is
  directly read: `serverless.yml:90` grants
  `table/infrastructure-${self:provider.stage}-table-domain-driven-cache` — **stage-keyed**, while
  the code addresses the cache by **access** (D27's cited `cacheStage`). so a prep deploy (stage=dev)
  grants `-dev-` and the code requests `-prep-`. the mismatch is not inferred from the issue — it is
  the byte on line 90 against the access-keyed code.
- **D31** — the acceptance suite invokes `svc-x-prep-getX`; the deployed lambda is `svc-x-dev-getX`.
  fails as `ResourceNotFoundException` — misread as a deploy fault.
- **D52** — 88 blackbox files address a `-prep-` fleet no peer publishes.

### the after

the same repo runs the upgrade. now:

- `environment.ts` exports one axis — `access` — and, for the transition, an `access`-aware target
  helper pair whose name says exactly what it is: `sdkAwsLambdaEnvAccessAncient` (emits `dev`, for a
  peer still published `-dev-` only) and `sdkAwsLambdaEnvAccessContemp` (emits `prep`, for a `-prep-`
  peer or self). `serviceClientStage` is gone.
- each service dual-publishes its fleet under **both** slugs through the transition, so no
  cross-service call ever 404s while the org migrates peer-by-peer.
- `grep AccessAncient` across a repo is the **migration ledger** — a reliable *presence* signal (any
  hit = migration not done; zero imports = zero unmigrated peers = the exit) and an *approximate*
  per-peer count (a caller that aliases or wraps the helper still imports it, so occurrences need not
  be 1:1 with peers). the blueprint reads the ledger as import-presence, not occurrence-count. a
  migration is a one-line `Ancient → Contemp` flip.
- when the org's last `Ancient` is gone, the `-dev-` publish, the helper, and the `stage` word all
  delete together. one axis remains: `access`.

a fresh scaffold ships this way on day one and never meets the silent break.

### the "aha"

the click is not "we renamed stage to access." it is:

> **the whole silent fault class exists only because two words disagreed. collapse them to one word
> and the class cannot be written — a wrong-axis reference is no longer expressible, because there
> is no second axis to reach for.**

and the sharper half, the part that makes the transition safe rather than a flag-day gamble:

> **the code is the ledger. `grep AccessAncient` names every unmigrated peer, and the count reaching
> zero IS the exit. the scaffold announces its own teardown.**

## the mental model

- **how a consumer describes it to a friend**: "the upgrade used to name my lambdas `dev` but call
  them `prep`, so no lookup could find anything. now it's just `access` everywhere, and there's a
  transition where both names exist so a call never breaks while we switch."
- **the analogy**: a **postal address change with mail forwarding**. you do not knock down the old
  house the day you move — you forward mail from both addresses until every sender has your new one,
  then drop the forward. dual-publish is the forwarding; `grep AccessAncient` is the list of senders
  who still use the old address.
- **their words vs ours**:

| the concept | a consumer says | we say (canonical) | the forbidden synonym |
|---|---|---|---|
| the tier of resources reached | "environment", "stage" | **`access`** (`test\|prep\|prod`) | `stage` (as a second axis) |
| the deploy slug baked into names | "the stage" | **`access`**, pinned via `--stage ${access}` | a divergent `stage` value |
| a peer still on the old name | "the old one" | **ancient** (sdk-aws-lambda's word) | `legacy`, `old`, `v1` |
| a peer on the new name / self | "the current one" | **contemp** | `new`, `current`, `v2` |

`ancient`/`contemp` is **not our coinage** — ✅ 🟡 it is sdk-aws-lambda's own pair (the wish cites
113 matches + an `ancient-vs-contemp-callers` invariant; unverified from this session, named as a
wish claim to re-check). so adopting it **adheres** to `rule.forbid.domain-term-synonyms`. the
homograph (the sdk uses it on the payload-format axis; we use it on the slug axis) is disambiguated
by the `EnvAccess` qualifier in the helper name.

## evaluation

### how well it solves the goals

- **eliminate the silent fault class** — ✅ addressed at the root: one axis makes the wrong-axis
  reference unrepresentable. the durable guard (forbid a divergent `stage`) keeps it collapsed.
- **fix the roster forward** — every stage-tier row maps to a critipath above; the non-stage rows
  (joi→zod, jest, husky, silent-check tier) are carried in the wish roster and demoed by case 6 +
  the reconciliation guard.
- **no consumer left to hand-patch** — the fixes land in the templates, so a consumer inherits them
  from one `declapract apply`.

### pros

- collapses the stage-tier roster rows into one coherent objective rather than a point-patch each.
- the transition needs **no lockstep** — each service migrates on its own clock; a call never 404s
  between.
- the migration state is legible from code (`grep AccessAncient`), not tribal.
- the scaffold includes its own teardown — no permanent 2× tax.

### cons / costs (honest)

- **a real migration, not a rename** — the stateful layers (RDS, SSM) need human-gated live steps
  (a CNAME cutover, a decrypt-reseed). declapract does codegen + static verification; it **cannot**
  run the live apply.
- **a transition window with 2× lambdas** — see the open groundwork on account limits.
- **the `--stage` field survives** — serverless requires it; "delete stage" operationally means
  `--stage ${access}`, no remap. whether it can be dropped fully is open.
- **the absorbed deploy-runtime gate adds a docker dependency to `npm test`** (case=8, #553) — the
  price of a gate that runs the artifact on its deploy node rather than a second command a human must
  remember. the alternative (fall back to the build node when no daemon is present) is the exact
  silent-green failure the gate exists to remove, so the cost is paid deliberately.
- **the config-param migration (#544) is sequenced and half-upstream** — the declapract fixer moves
  params then rewrites config bare, but the derive convention it targets lands in sdk-config#13. a
  bare rewrite before the move breaks `getConfig()`, so the move-then-rewrite order is a hard
  sequence rule, not a preference.

### edge cases + how the contracts keep a pit of success

| edge case | the pit-of-success guard |
|---|---|
| a rewrite cannot know the axis | the collapse deletes the second axis, so `'prep'` is the one answer; the sole `-dev-` survivor is the typed SDK helper — a wrong value is a compile error, not a guess (case 4) |
| a `fix` would land the file in a state another practice forbids | declapract refuses/warns on the output path — the one-way door is closed (case 5) |
| a check's glob matches zero files | `plan` reports "could not fire" ≠ "passed" (case 6) |
| the axis re-splits after collapse | the divergent-stage guard blocks any new `accessByStage` remap |
| a stateful store gets two names | alias/pointer, never a copy — the write-dev/read-prep split-brain is forbidden by contract |
| a dep skews the syntax floor below the deploy node | the acceptance suite runs the artifact on the deploy node major with a real request — the break fails a gate, not prod (case 8) |
| a template shallow-merge clobbers a repo's config shape | the fix's output is checked against the repo's extant shape; a non-convergent merge is refused (case 5, #539) |
| a config param goes bare before its value is moved | the fixer verifies the derived param is present before it rewrites config bare — else fail loud (case 4, #544) |

## the settled design

these are decided. downstream stages build on them directly.

1. **the north-star mechanism is dual-publish + the ancient/contemp ledger.** each service publishes
   its fleet under both slugs through the transition, so no cross-service call 404s while the org
   migrates peer-by-peer; `grep AccessAncient` is the ledger. this solves both directions — a
   self-only invoke-time middleware would rewrite our outbound targets but cannot stop an *inbound*
   404 from an unmigrated peer that addresses us by `-dev-`, so dual-publish is the mechanism.

2. **`stage` deletes in one move at the endpoint.** once `grep AccessAncient → 0` org-wide, the
   `-dev-` publish, the `Ancient` helper, and the `stage` word retire together — the scaffold's
   teardown is a single step, not a phased retire.

3. **the in-repo companions are a FOLLOW-ON wish — descoped at execution.** ⚠️ this reverses the
   claim first drafted here ("first-class deliverable, land in the templates alongside the north
   star"). the execution stone settled the opposite, and this states the current truth per
   `rule.forbid.chronological-accretion`: the deploy-runtime (#551/#552/#553), vpc-tunnel
   (#539/#519/#523/#562), config-param (#544 declapract half), gerund (#549), and codegen-client
   (#532) clusters are more costumes of the same meta-lesson (below), so they inherit this wish's
   demos — but each is its own incident with its own fail-safe, and to fold them into this drive would
   unbound it. they land in a follow-on wish, not this one's templates. the full descope rationale is
   in `5.1.execution.from_vision.yield.md` (the round-2 convergence section). two halves additionally
   cross a repo boundary: `#544`'s sdk-config derive depends on **sdk-config#13**, and
   **sdk-aws-lambda#18** (the v1-guard 500) ships from `ehmpathy/sdk-aws-lambda`.

   **#532 is the north star's client-side home.** it establishes `access/svcs/*` as the generated-sdk
   location (codegen from live lambda contract introspection) and deprecates the hand-maintained
   `data/clients/svc*.ts` pattern. the generated `<svc>.mechanisms.ts` clients wrap `askLambdaEndpoint`
   with the target function name — which is exactly the `dev`-vs-`prep` slug the
   `sdkAwsLambdaEnvAccess{Ancient|Contemp}` helper resolves (case=2). so the generated client layer is
   the natural home for the Ancient/Contemp target-resolution, and `grep AccessAncient` reads across
   `access/svcs/` as the migration ledger. how the per-peer Ancient→Contemp flip sits in a *generated*
   file (a codegen input, an override, or a hand-edited call site the codegen preserves) is a blueprint
   fork — flagged, best-guessed toward a per-peer override the codegen honors, not a hand-edit it would
   clobber on the next re-gen.

   **the through-line that makes this one wish, not many.** the companions are not a second disease —
   they are more costumes of the wish's own meta-lesson: *a practice that emits a **value** cannot
   verify its own output.* the stage/access split emits a stage-value; deploy-runtime skew emits a
   runtime-value (`nodejs14.x`) no gate runs; the vpc-tunnel template emits a config-shape value its
   shallow-merge fix clobbers; the config-param template emits a param-path value no single repo can
   reproduce; the hand-maintained lambda client emits a contract-shape value that drifts from the
   upstream it transcribes. each is the same silent, self-unverifiable value-emit, so each maps onto a
   family the vision already demos:

   | cluster | issues | maps onto |
   |---|---|---|
   | deploy-runtime skew | #551/#552/#553 | **new demo** `case=8` — distinct incident + distinct fail-safe (run the artifact on the deploy node) |

## what is awkward?

1. **the transition asks every service to double-publish, org-wide.** that is real coordination
   cost, and it fights the instinct "just rename it." the honest defense: a rename IS the flag-day
   gamble that 404s every cross-service call in between. the 2× publish is the price of no-lockstep,
   and it is transition-only. it remains the heaviest part of the design.

2. **`stage` cannot be fully deleted — the word survives as serverless's `--stage`.** so "eliminate
   stage" is slightly aspirational: the *axis* dies, the *field* remains pinned to `access`. a
   reader who takes "delete stage" literally will be confused when `--stage ${access}` stays. named
   plainly rather than hidden.

3. **the RDS/SSM finish-line is human-gated and per-env.** declapract can declare the go-forward and
   forget the old, but the CNAME cutover and the SSM decrypt-reseed are live steps a human runs from
   a runbook. the vision cannot promise a one-command migration for the stateful layers — and to
   pretend otherwise would be the exact over-claim the roster punishes.

4. **the `ancient`/`contemp` homograph.** it means one thing in sdk-aws-lambda (payload format) and
   another here (slug). the `EnvAccess` qualifier disambiguates at a read site, but a maintainer who
   knows only the sdk sense may misread. worth a one-line comment at the helper's declaration.
