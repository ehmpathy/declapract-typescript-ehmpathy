# deliver: #584 — the tests-expo jest-expo/rtr major is gated on the repo's OWN expo/react major

## what shipped

the `tests-expo` practice's `package.json` declaration now **gates the SDK-coupled majors on the
repo's own expo + react majors** rather than floors them at a fixed baseline.

- **`package.json.declapract.ts`** — a custom `check`/`fix` that reads the repo's `expo` and
  `react` majors from `contents` and requires:
  - `jest-expo` major **== expo** major (jest-expo tracks the SDK 1:1)
  - `react-test-renderer` major **== react** major (rtr ships lockstep with react), only when a
    `react` dep is present
  - `@babel/core` >= 7.24.0, `babel-preset-expo` >= 12.0.0, `isomorphic-fetch` >= 3.0.0 — kept as
    plain MINIMA (not the crash; each a floor the pre-gate template already declared)
- the old static `best-practice/package.json` CONTAINS template + its five
  `@declapract{minVersion(...)}` markers is **deleted** — a fixed `minVersion('54.0.0')` floor
  cannot express "match the repo's own major", which is the whole point.
- a repo with no `expo` dep is not a gate-able expo repo: `check` returns and `fix` leaves it
  untouched, so a non-expo `package.json` is never falsely reddened.

## why this is the right fix — gate on the repo's major, not a fixed floor

jest-expo's preset pokes react internals of the SDK it targets. a fixed `minVersion('54.0.0')`
floor forces jest-expo 54 (a react-19-era preset) onto an expo-51 / react-18 repo, and every unit
suite throws `TypeError: Object.defineProperty called on non-object` at jest-expo's preset setup
(#584 / defect D1). the two SDK-coupled deps each track a major 1:1, so the gate reads the repo's
OWN expo + react majors and requires a match — which holds jest-expo at 51 on an expo-51 repo and at
54 on an expo-54 repo, **with no version table to rot as new SDKs ship**.

`@babel/core` / `babel-preset-expo` / `isomorphic-fetch` stay minima because they are not the crash
and are not react-coupled — each is a plain floor. `babel-preset-expo` also tracks the SDK, but
backward-compatibly; its floor is left as a residual (see the fork below).

## idempotency

after `fix`, `check` passes on the output, so `declapract fix` reaches a fixed point:
`fix(fix(x)) === fix(x)`. proven at both the unit grain (case6) and the pipeline grain (a second
`executeApply` is a no-op).

## the caller-without-callee fix

the old CONTAINS template only FLAGGED the five deps; a repo that lacks them stayed in violation
with no repair. the new `fix` **supplies** them — jest-expo at the expo major, rtr at the react
major (when react is present), and the three minima when below. so the practice now stamps its
callee, not just its caller (the wish's caller-without-callee class).

## the intended rtr-drop for react-less repos

when a repo declares no `react` dep, the gate emits no `react-test-renderer` — there is no react
major to match, so rtr is not owed. the graceful-migration fixture is exactly this shape (expo, no
react), so its `after` snapshot correctly drops rtr. this is intended: a repo that later adds react
gets rtr gated to its react major on the next apply.

## the fork — the babel-preset-expo residual minimum

`babel-preset-expo` ALSO tracks the SDK major (like jest-expo), but backward-compatibly — a
preset-expo 12 does not crash on an expo-51 repo the way jest-expo 54 does. so it is left as a plain
`>= 12.0.0` MINIMUM rather than gated to the expo major. this is a best-guess: the minimum is
correct for every expo major >= 12's floor, and it never crashes. if a future expo major needs
preset-expo gated the same way jest-expo is, the clean rework is to move it from the minima block to
the major-gated block beside jest-expo — flagged here, not decided.

## a ride-along fix — depcheck false positive on a template env

`test:lint:deps` flagged `@jest/globals` and `isomorphic-fetch` as absent deps, imported by
`tests-expo/best-practice/jest.acceptance.env.ts` — a best-practice TEMPLATE whose imports are
consumer-runtime deps (jest globals + a fetch polyfill), never this library's own executed src.
depcheck reaches the template file and mis-attributes them. added both to `.depcheckrc.yml` ignores,
which matches the established precedent for `test-fns` / `@swc/jest` and the lint bad-practice
`ignorePatterns`. safe + clean: it only relaxes depcheck for template-only consumer imports, and it
unblocks the shared lint gate.
