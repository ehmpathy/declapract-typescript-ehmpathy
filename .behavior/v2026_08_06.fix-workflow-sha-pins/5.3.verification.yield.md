## ⚠️ the gap this gate caught — constraint 2 was unproven

### what was absent

the wish states three constraints. two were clamped:

| constraint | clamped by |
|---|---|
| 1 — every SHA has verifiable upstream provenance | the derivation docblock + the committed pin tables |
| 3 — no flag-gated rollout | the templates carry literal pins; there is no flag |
| **2 — the template's reach ends at the refs it owns** | ❌ **no test at all** |

every case i had built proved the pin **arrives**. not one proved it **stops**. the wish's own
words are the test i never wrote:

> *"the template's reach ends at the refs it owns. do not silently rewrite what the practice does
> not own."*

⚠️ **and `[case1]`/`[case2]` could not have caught it even by accident**, because both pass
`file:` to `executeApply`. a scoped apply leaves a consumer's file alone because it was **told
to** — never because the practice declines to own it. the scope detail is the whole point: those
two cases prove delivery, and a delivery proof is structurally blind to over-reach.

### what i built

`[case3]` of `src/practices/cicd-common/.declapract.integration.test.ts`:

- a new fixture, `.test/assets/repo-with-unpinned-workflow/.github/workflows/consumer-owned.yml`
  — a workflow **no practice declares**, whose `actions/checkout@v4` and `actions/setup-node@v3`
  are deliberate. the file carries a ⚠️ note that they must not be "corrected" to a pin.
- an `executeApply` over the **whole practice, unscoped** — no `file:` filter, so the practice
  gets its full reach and the assertion means what it claims.
- three assertions:

| assertion | catches |
|---|---|
| the consumer's own workflow is byte-identical | a practice that rewrites a file it does not own |
| **and the template-owned file DID change in the same run** | a vacuous first assertion (an apply that reached no file) |
| the consumer's own tag refs survive | a partial rewrite that pins one ref and leaves the file otherwise intact |

**proven to bite:** i added a template at
`cicd-common/best-practice/.github/workflows/consumer-owned.yml`, which makes the practice
genuinely own that path → 🔴 **2 red**, both consumer-file assertions, with the anti-vacuity
assertion **green** (the template-owned file still changed). removed → green.

that red/green split is the evidence the pair is honest: the injection moved exactly the two
assertions it should, and left the third alone.

## snapshots — coverage and change rationale

| integration | **10 passed, 10 total** — 0 obsolete, 0 written |

`git diff --stat origin/main...HEAD -- '*.snap'` → **empty**. every snapshot this behavior adds is
a **new** file; not one extant snapshot moved.

⚠️ **that check was nearly wrong, and the reason is worth the record.** `git diff main...HEAD`
first reported **8** changed snaps. `git log main..HEAD` then showed local `main` sat **20 commits
behind** `origin/main` — so the 8 were already-merged work from other branches, dragged into scope
by a stale local ref. re-run against `origin/main`: empty.

that is the exact trap `rule.require.clamp-edge-cases` carries as its own worked example, met
live. the rule's remedy — compare against `origin/main`, the true fork point — is what settled it.
