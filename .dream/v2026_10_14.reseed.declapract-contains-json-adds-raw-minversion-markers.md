# 🌙 dream: declapract's CONTAINS json fix adds an absent dep as a raw `@declapract{check.minVersion(...)}` string

- kind = reseed
- owner = ehmpathy/declapract
- caught 2026-10-14

## .the cue that fired

a new executeApply integration test for `environments/bad-practices/old-dev-scripts` snapshotted the
consumer `package.json` after ONE apply, and its `dependencies` held
`"sdk-environment": "@declapract{check.minVersion('0.1.5')}"` — a string npm cannot install. only a
second apply turned it into `0.1.5`. `logs/.declapract.integration.test.ts` already notes the same
behavior as a "marker quirk".

## .the gap, precisely

`fixContainsJSONByReplacingAndAddingKeyValues` (declapract 0.13.26,
`dist/.../fixMethods/fixContainsJSONByReplacingAndAddingKeyValues.js`), inside
`deepReplaceOrAddCurrentKeyValuesWithDesiredKeyValues`:

```js
if (currentValue === undefined || currentValue === null) {
  if (typeof desiredValue === 'string' && hasIfInstalledModifier(desiredValue)) return undefined;
  return desiredValue; // ← raw: a check.minVersion expression is never expanded here
}
```

so a key absent from the consumer file is added verbatim. the same holds one level up: an absent
`dependencies` object is copied whole, markers and all. the file-absent path
(`deepReplaceAllCheckExpressionsFromDeclaredContentsString`) does expand them, so only the
partial-file path leaks.

harm: any consumer that lacks a dep a practice declares gets an uninstallable `package.json` after
one `declapract apply`. a second apply converges it, so the defect hides from anyone who reruns.

witnesses (each a plain `check = CONTAINS` package.json declaration, no fix of its own):
- `environments/bad-practices/old-dev-scripts` — `sdk-environment`
- `provision-github/best-practice/package.json` — `declastruct`, `declastruct-github`, `sdk-logs`
  land as `@declapract{check.minVersion('1.9.2')}` etc. in `devDependencies` on a repo that lacks
  them (seen by the `implicit-package-privacy` integration fixture, which carries the deps to stay
  isolated). 36 practices declare package.json the same way, so every one shares the leak

upstream `ehmpathy/declapract` `origin/main` still carries the branch unchanged (line 108 of
`fixContainsJSONByReplacingAndAddingKeyValues.ts`), so no released version has fixed it.

## .the shape of the fix

in the absent-current branch, return the desired value with every check expression expanded — the
same `CHECK_MIN_VERSION_REGEX_GLOBAL` → `$1` replace (and `.ifInstalled()` filter) the file-absent
path applies, recursively for an object value. clamp: a fixture with a present `package.json` whose
`dependencies` lacks a declared `check.minVersion` dep; assert one apply yields the bare version.

## .why it is not done in this round

the defect lives in `ehmpathy/declapract`, another repo (S5: no work in other repos). this route's
tests that hit it assert the rule they own and note the two-apply settle beside the logs precedent.
