# 🌙 dream: declapract's project glob stays bounded under symlinks and gitignored dirs

- kind: reseed (owner: declapract)
- caught: 2026-11-02

## .the cue that fired

`declapract apply --practice git --file .gitattributes` on declapract-typescript-ehmpathy ran 25 minutes, then died: `JavaScript heap out of memory`. the practice declares two files.

## .the gap, precisely

- `evaluateProjectAgainstFileCheckDeclaration` calls globby with `gitignore: true` and `dot: true`, per check
- globby's `gitignore: true` first globs `**/.gitignore` with fast-glob defaults: symlinks followed, and no `.gitignore` honored by that walk. the only skips are declapract's name list (`**/node_modules/**`, `**/.git/**`, `**/dist/**`, `**/build/**`, `**/coverage/**`)
- so a gitignored dir with symlinks is walked in full, on every check. measured on this repo: 1923 `.gitignore` files in 77s with symlinks followed, 73 in 0.2s without; ~1850 of them under `.temp/genTempDir.symlink/` (test-fns temp repos, each with symlinks into declaration trees)
- a symlink cycle (`.temp/loop -> ..`) fails the apply with `ELOOP`, and the walk enters `node_modules/.pnpm` through the loop path, past the name skip
- every ehmpathy repo that runs `genTempDir` accumulates `.temp/`; an adopter's `declapract apply` slows and can crash as it grows

## .the shape of the fix

in declapract, either or both:
1. pass `followSymbolicLinks: false` to the project globs (declapract never needs to follow a link to find a declared file)
2. compute the ignore set once per project, with the walk itself bounded by `.gitignore` (e.g. tracked files plus `git ls-files --others --exclude-standard`, or an `ignore` built from the root `.gitignore` before the walk)

clamp: a fixture repo with `.temp/loop -> ..` under a gitignored `.temp/`, which today fails `apply` with `ELOOP`.

## .why it is not done in this round

the defect lives in declapract, another repo. this repo's `declapract.self.apply` now applies in an isolated root outside the repo, with a `.temp/loop` clamp in `src/repoSkills.declapract.acceptance.test.ts` `[case4]`.
