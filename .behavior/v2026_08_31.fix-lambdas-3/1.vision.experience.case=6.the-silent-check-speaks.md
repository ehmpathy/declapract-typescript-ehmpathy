## narrative

a whole tier of the roster is checks that report clean when they are blind:

- **D54** — `projectPractices.includes('terraform')` names no practice (the real names are
  `terraform-common` / `terraform-aws`), so the terraform formatter never runs — silently absent.
- **D50** — a dependency-presence check written as `CONTAINS` against `devDependencies` is blind to a
  dep in `dependencies` — reports clean.
- **D41** — a `serverless.yml` insert anchored before an inline comment never lands; the check never
  says so.
- **D39** — a `CONTAINS` with no `fix` opens a divergence no mechanism ever closes.

each is worse than a red check, because a red check tells the truth. a check that **could not fire**
looks identical to a check that **passed** — so the drift is invisible.

after this wish, `declapract plan` distinguishes the two: a check whose glob matched zero files, or
whose predicate could not evaluate, reports **"could not fire"** — separately from "passed". the
consumer and the maintainer both see the difference. the individual defects (D54's practice name,
D48's literal-path→glob, D41's anchor) are fixed too, but the durable win is the report itself.

the aha: **"passed" and "could not run" are different facts, and a plan that conflates them is the
silent-defect factory.** name them apart and most of the silent tier surfaces at once.

## bdd

```
given a practice check whose glob matches zero files (D54: includes('terraform') — no such practice)

when [t0] the pre-wish `declapract plan` runs
  then the check reports as PASSED (0 blockers)                                                # today — silent
  and the terraform formatter never ran, and no output says so

when [t1] the post-wish `declapract plan` runs the SAME check
  then it reports `could not fire — glob matched 0 files` — a DISTINCT status from PASSED
  and the summary tallies "N checks could not fire" separately from "N passed"

when [t2] the D54 practice name is corrected (terraform → terraform-common/terraform-aws)
  then the check fires, and the formatter runs
  and `plan` reports it under PASSED/FAILED, never under "could not fire"

when [t3] D48's `own-implementation` literal path is made a glob
  then a file one directory segment away is now matched and checked
  and a whole class of miss-by-one-segment silent passes closes

when [t4] a maintainer audits the plan for blind checks
  then every "could not fire" line is a candidate defect, surfaced in one report
  and the silent tier (D39/D41/D50/D54) is visible at a glance, not one painful repo at a time
```

## the fail-safe

this is the silent-defect tier's fail-safe: the fault (a blind check) is converted from **invisible**
to **named in the plan output**. `[t1]` is the general mechanism (the wish's durable guard #5 — a
plan that reports could-not-fire); `[t2]`/`[t3]` are the specific roster fixes carried on it. the
pit-of-success: the maintainer no longer has to *know* a check went blind — the plan tells them, so
recognition replaces recall (`rule.require.discoverability`).

## the absorbed instances (rows 13, 14, 20, 21)

case=6's cell also hosts the **suite-on-arrival** siblings — a suite that fails on its first run
because a practice emitted a value it could not verify. each is a new costume of the silent-check
class, itemized rather than re-demoed:

- **row 13 (#564)** — `jest.integration.env` demands `AWS_PROFILE`, which `keyrack.yml` never declares.
- **row 20 (#586)** — the `tests` practice sources keyrack for the sso profile only; an aws-sdk **v2**
  caller (`simple-lambda-testing-methods` → `aws-sdk@^2`) ignores the profile and needs static creds,
  so the acceptance suite auths against no reachable target. the fix ships `useKeyrack` as a practice
  artifact that exports static creds and drops `AWS_PROFILE` — one guard at the v2 boundary, inherited
  by every repo that invokes lambdas in tests.
- **row 14 (#547) + row 21 (#581)** — the dpdm exclude. ⚠️ **row 21 corrects row 14's remedy**: the
  `.dpdmrc.yaml` `exclude: []` is **deliberate** org policy (`rule.forbid.dpdm-exclude-change` — check
  `node_modules` for cycles on purpose), NOT a clobber to merge away. the honest fix makes the empty
  state deliberate (drop the `// "^$"` fallback, comment the intent) so a future tidy-up cannot
  silently render dpdm's own `node_modules` default and disable the policy across every repo. the 71
  cycles a real gate reported are a **true** signal (64 prod-dep, 57 from aws-sdk v2) — work owed, not
  a template defect.
