sql-schema-control@1.8.0 renamed a change entry's natural key from `id:` to `exid:`. the tool still
reads `id:`, with a deprecation nudge on every plan and apply.

this fix renames `id:` to `exid:` on each `type: change` entry under `provision/schema/`. the value
stays the same, so the change hashes still match. an `id` key outside a change entry is left alone,
and an entry that already declares `exid` is left alone.
