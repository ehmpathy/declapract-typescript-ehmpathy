# 🌙 dream: sql-schema-control accepts an `ssl` option for its pg client

kind: reseed · owner: ehmpathy/sql-schema-control · caught 2026-09-29

## .the cue that fired

#652 makes every pg client that declapract-typescript-ehmpathy emits verify rds tls. but the schema
provision runs through sql-schema-control, whose client connects with no tls.

## .the gap, precisely

`connectToDatabase.ts:46-52` builds `pg.Client` with no `ssl`, and `ConnectionConfig` has no field to
pass one.

## .the shape of the fix

- add an optional `ssl` to `ConnectionConfig`, passed straight to `pg.Client`; release it.
- then in the persist-with-rds practice, pass `asDatabaseClientSsl(...)` into the schema-control
  config and raise the floor.

## .why it is not done in this round

it is another repo's work, and seed S5 forbids that work this round. #652 still lands for the app's
own clients.
