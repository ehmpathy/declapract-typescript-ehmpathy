a tsconfig that sets `baseUrl`, or `importsNotUsedAsValues` to `"remove"`; typescript 7 removed both.

the typescript-node floor is typescript 7.0.2, where `baseUrl` fails with TS5102 and
`importsNotUsedAsValues` fails with TS5023. the best-practice tsconfig check adds keys and never
deletes one, so neither option leaves without this fix.

the fix drops `importsNotUsedAsValues` only where it reads `"remove"`, the default elision, so emit
is unchanged. a `"preserve"` or `"error"` value carries emit or a check the drop would lose; the
manual bad-practice `imports-not-used-as-values-kept` flags it for a human instead. it folds
`baseUrl` into `paths`: each `paths` value is rebased onto the tsconfig dir with a `./` lead
(`"src/*"` under `"baseUrl": "."` becomes `"./src/*"`). it fixes before the best-practice adds the
template `paths`, so only the repo's own `paths` are rebased. each result is valid on typescript
5.4.5 too.

a `baseUrl` other than the tsconfig's own dir also let bare imports (`'logic/x'` under `"./src"`)
look up there, beside the aliases. so the fold adds one key per top-level entry of that dir, at the
head of `paths`: `"logic/*": ["./src/logic/*"]` for a dir, `"config": ["./src/config"]` for a module
file. a key the repo already declares keeps its own targets. tsc's TS5102 hint names a `"*"`
catch-all instead, but tsc-alias skips a key with no prefix, so a bare import would typecheck and
then ship unrewritten in `dist`, and fail at runtime. a dir added later has no key: its bare import
fails loud with TS2307, so add its key, or import it through `~/` or `@src/`. a repo that declares its
own `"*"` gains no key, since it already chose its lookup. entries no import names get no key: dot
entries, `node_modules`, `__dunder__` dirs, test and spec files, and the dir's own `index`.

a dir key covers its files (`'utils/x'` via `"utils/*"`), not the dir itself: a bare `'utils'` import
of `utils/index.ts` fails loud with TS2307. add `"utils": ["./src/utils"]` by hand, or import
`'utils/index'`.

the fold reads only the top-level `compilerOptions` of `tsconfig.json`, the one tsc reads; a
`ts-node.compilerOptions.baseUrl` is left as written. it edits text so each value lands exact, but
the best-practice fix then writes the file as plain json, so comments do not survive a full apply.

out of reach: a `baseUrl` in a file the tsconfig `extends` (a monorepo `tsconfig.base.json`) is not
`tsconfig.json`, so this fix never sees it, and typescript 7 still fails with TS5102. fold it by hand
the same way: rebase each `paths` value onto that file's dir with a `./` lead, then drop `baseUrl`.
