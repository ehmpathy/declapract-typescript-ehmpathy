## getConfig and oidc grants

`src/utils/config/getConfig.ts` loads `config/*.json` plus the aws parameter-store supplier, under
one of two grants:

- `apply` (the default) parses with `schema.apply`, so every secret is required and `Config` holds
  no `| undefined`
- `plan` parses with `schema.plan`, which tolerates the secrets the plan role may not read. a caller
  opts in with `getConfig({ grant: 'plan' })`, or with `GRANT=plan` in the env — the latter lets a
  caller that passes no args (e.g. the ghlitch vpc tunnel) pick the plan scope with no code change

each grant has its own loader and its own cache, so a plan miss never poisons the apply cache.

`getConfig` keeps sdk-config's name: every consumer calls `getConfig()`, so a rename would break
each call site.

the two `as` casts in `getConfig` exist because ts cannot relate the runtime grant to the caller's
type parameter `TGrant`; a per-grant overload of `genGetConfig` would let both go.
