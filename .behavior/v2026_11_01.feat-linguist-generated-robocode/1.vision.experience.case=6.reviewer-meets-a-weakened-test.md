# case=6: reviewer meets a weakened test

cells: rv6 (M = collapse-line × K = snap-proven × N = weakened) and rv15 (K = test-no-snap; [t0] + [t2] only) — sharp · critipath (clone-driven prs loosen tests to go green; cost: a defect ships behind a green suite)

## .narrative

a pr fixes a flaky lambda. to get green, the author deletes one `expect(...)` in `getJob.integration.test.ts` and leaves the code bug in place.

before the practice: the test file renders open. the reviewer may still skim past a one-line deletion in a 300-line test.

after: the test file renders collapsed. what keeps it from silence:

1. **the file list still names it, with its counts.** the collapsed row reads `getJob.integration.test.ts  +0 −1`. a deletion-only change to a test is a visible tell; the reviewer clicks "load diff".
2. **the snapshot stays open.** where the dropped assertion fed a snapshot, the `.snap` diff shows the removed or changed output, open, in the main flow.
3. **the change is never hidden from tools.** collapse is a render hint only. `git diff`, ci, and any reviewer bot read every line as before.

the fail mode is "one click deeper", never "gone". the residual risk is named in the yield's awkward section: a reviewer who reads only the open files and ignores counts on collapsed rows can miss a test that was weakened. the practice cannot open a file conditionally (linguist has no "open if lines deleted" rule), so the counts are the signal.

## .bdd sketch

```
given('[case6] a pr that deletes one assertion from a test file', () => {
  when('[t0] the reviewer opens the files tab', () => {
    then('the test file row renders collapsed')
    then('the row shows its `+0 −1` counts')
    then('one click on "load diff" shows the deleted assertion')
  })
  when('[t1] the dropped assertion fed a snapshot', () => {
    then('the .snap diff renders open, with the change visible')
  })
  when('[t2] `git diff` runs locally or in ci', () => {
    then('every line of the test change is present; linguist has no effect')
  })
})
```
