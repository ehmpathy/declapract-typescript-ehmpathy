# 🌙 dream: the foreman seat must not inherit the driver's stop hooks

kind = reseed (rhachet / rhachet-roles-bhrain) · owner = rhachet · caught 2026-10-14

## .the cue that fired

a foreman, hired into the same worktree as its driver, had every turn end held by two stop hooks
it cannot answer:

- `rhx route.drive --when hook.onStop` — demands the driver's stone be set. the foreman must never
  set it (only the driver passes its stone)
- `rhachet roles cost --all --when hook.onStop` — `boot.yml` over budget, a file in the driver's
  in-progress diff

so each foreman turn loops: hook fires → foreman declines (correctly) → stop → hook fires again.
each loop burns tokens and adds to the route's stuck streak (`stepRouteDrive.js`, 21-block cutoff),
which then escalates a false "stuck, tell a human" against the driver's stone.

## .the gap, precisely

hooks are read per worktree, never per seat. `@:foreman` and `@:mechanic` share
`.claude/settings.json`, so the foreman boots with the driver's route hooks.

## .the shape of the fix

- `route.drive --when hook.onStop` exits 0 when the session is not the route's bound driver (a
  seat other than `@:mechanic`, read from the crew seat)
- or `git.crew.seat hire --who foreman` boots the foreman with a seat-scoped settings file that
  omits route-drive + budget stop hooks
- either way, a foreman stop never increments the drive-blocker streak

## .why it is not done in this round

it lives in rhachet / rhachet-roles-bhrain, not this repo — a tree adopts only what is scoped to
itself. and the foreman seat may not edit the shared hooks its driver runs under.
