# 🌙 dream: the `@/` alias into src ships unrewritten from a `rootDir: src` build

kind: fix · owner: typescript-node practice · caught 2026-11-21

## .the cue that fired

the ts7 pr's build seam test imported through each template alias and ran the shipped build
(`tsc -p tsconfig.build.json && tsc-alias -p tsconfig.build.json`). `@src/` rewrote to
`../logic/x`; `@/src/logic/x` stayed `require("@/src/logic/x")` in `dist/`.

## .the gap, precisely

- the template declares `"@/*": ["./*"]` (the repo root) and `tsconfig.build.json` sets `rootDir: src`, so `dist/` holds
  `contract/…`, never `src/contract/…`
- tsc-alias 1.8.10 maps an alias target to a file in `outDir`; `src/logic/x` has no twin there, so its default replacer
  leaves the import as written and exits 0 (`dist/replacers/default.replacer.js`)
- the same tree emits under typescript 5.4.5 and 7.0.2 (`rhx typescript.probe --what emit --rungs '7.0.2 5.4.5'`: 0
  files differ, 1 unrewritten specifier under each), so this is not a typescript 7 break. a module that imports
  `@/src/…` fails at runtime from `dist/` today

## .the shape of the fix

pick one, then pin it with the seam test in `typescript-node/tsconfig-options-removed-in-ts7.declapract.integration.test.ts`:
- a bad-practice that flags `from '@/src/` in `src/**/*.ts` and swaps it for `@src/` (automatic, a pure specifier swap)
- or drop `@/*` from the template, if no adopter reads a root file through it in prod code (`rootDir: src` already
  rejects a non-src import with TS6059, so `@/` only ever served tests)

## .why it is not done in this round

it predates typescript 7 and holds on every compiler, so it sits outside the ts7 wish; the fix is a new bad-practice
or a template change with its own org read of `@/src/` imports.
