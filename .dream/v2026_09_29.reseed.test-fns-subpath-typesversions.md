# 🌙 dream: test-fns ships its subpath types via `typesVersions`

kind: reseed · owner: ehmpathy/test-fns · caught 2026-10-14

## .the cue that fired

the F88 clamp of `v2026_09_29.fix-absorb-recent-upgrade-reports` failed `tsc` on the expo usecase:
`TS2307 Cannot find module 'test-fns/autoprune.setup.jest'`.

## .the gap, precisely

test-fns 1.17.0 and 1.17.1 expose `autoprune.setup.jest` only through package.json `exports`, with
no `typesVersions`. a consumer on `moduleResolution: "node"` ignores `exports`, so tsc never finds
the subpath. expo's `tsconfig.base` uses `node` in expo 51, 52, and 53 (only 54 moved to `bundler`).

## .the shape of the fix

add `typesVersions` for each subpath in test-fns' package.json (`"*": { "autoprune.setup.jest":
["dist/…/autoprune.setup.jest.d.ts"], … }`). a test: compile an import of every subpath under
`moduleResolution: "node"` and `"bundler"`.

then this repo retires `src/practices/tests-expo/best-practice/src/.test/assets/test-fns.autoprune.d.ts`
(an ambient declaration that stands in meanwhile), drops the triple-slash reference from both
`jest.*.prepare.ts` templates, floors test-fns at the fixed version, and adds a bad-practice that
deletes the stand-in from adopters.

## .why it is not done in this round

it lives in another repo (route seed S5: no work in other repos).
