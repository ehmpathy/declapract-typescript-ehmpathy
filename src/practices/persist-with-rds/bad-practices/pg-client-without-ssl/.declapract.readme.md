a pg `Client` built with no `ssl` option connects in plaintext. a postgres 17 cluster forces ssl
by default, so that client fails to connect at all once the cluster is upgraded.

this fix gives each such client `ssl: asDatabaseClientSsl({ clusterEndpoint })`, which verifies the
cluster certificate against the rds us-east-1 roots and connects plain to the local testdb.

the fix names the endpoint as `config.database.tunnel.lambda?.host`, so it applies only where the
file already reads `config.database.tunnel`. any other file gets a review pointer at its top, since
a human must pick the endpoint there.
