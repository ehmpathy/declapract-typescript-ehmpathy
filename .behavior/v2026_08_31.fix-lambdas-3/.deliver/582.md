## the defect — a declared `.gitignore` line is inert for an already-tracked file

git consults `.gitignore` for UNTRACKED paths only. a path a consumer already tracks stays
tracked, so a `*.local.json` (or any) ignore added by the `git` practice AFTER a consumer already
committed a match reads as enforcement and enforces none — silently, with every gate green.

## what landed — ask (3), the ticket's "at minimum"

added a `.note` to `src/practices/git/best-practice/.gitignore.declapract.ts`'s docblock that
states the untracked-only scope outright: every declared line governs an untracked path only, the
`fix` is a pure contents transform with no seam to the index, so a consumer that committed a match
before the pattern was declared keeps it committed — and the reconcile is `git rm --cached <path>`
by hand.

this is DECLARATION-side (the `.declapract.ts` module is executed here, never emitted to a
consumer), so it teaches a maintainer who reads the declaration; it does not ship to consumers.
behavior is unchanged — `check`/`fix` are byte-identical. verified: the `gitignore practices`
integration suite runs 40 passed / 0 failed after the edit.

no clamp: the change is a doc comment with no behavior edge case to pin (per
`rule.avoid.hazard-pitch-prose` / `rule.require.clamp-edge-cases` — a clamp that asserts comment
text is low-value). the pipeline-intact check above is the confidence.

## what is HELD — ask (2)/(1), a flagged fulcrum

the ticket's preferred fix (ask 2: a check that REPORTS a tracked-but-ignored path with the
`git rm --cached` remedy; ask 1: a `fix` that reconciles the index) requires a git-subprocess
inside a check in the FOUNDATIONAL `git` practice — the multi-declarer convergence system with a
`[case3]` self-check. the concrete design would be a report-only bad-practice under
`git/bad-practices/tracked-ignored-paths/` whose `check` runs `git ls-files` + `git check-ignore`
in `context.getProjectRootDirectory()`, returns (detected) on any tracked-ignored path, and skips
on a non-git dir (a fresh repo is unaffected, per the ticket).

## the general shape, recorded (from the ticket)

a `.gitignore` line is a claim about the FUTURE; it says none about the index, and the index is
where the file lives. so EVERY declared ignore carries this latent gap, not merely `*.local.json`.
ask (2) is the mechanism-level fix for the whole class; ask (3) (landed) makes the scope legible to
the next maintainer of the declaration.
