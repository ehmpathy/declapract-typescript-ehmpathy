## the fulcrum, best-guessed — a marker, NOT a smarter regex

⚠️ the ticket's ask #1 reads "fix the codemod to unwrap the `body:` key into schema and thread
headers through rawEvent." i did NOT implement that literal AST rewrite, and here is why:

the rich transformation the ticket describes (`forApiGateway`, `z.looseObject`, `invoke: ({ event })`,
the authored `authorization?` note) lives in `ahbode/svc-gateway`'s LOCAL branch codemod — NOT in
this practice library. this repo ships two conservative BLIND REGEXES:
- `runtime-schemas/bad-practices/joi` — `Joi.*` → `z.*`, strips `.required()`
- `node-service/bad-practices/simple-lambda-handlers` — renames the handler call only; its readme
  already declares the schema/invoke contract as a MANUAL limitation it will not attempt

to teach either regex to unwrap `body` and thread `rawEvent` would be to build the exact
"blind regex that GUESSES a value it cannot verify" the wish's meta-lesson (#571) and its guard #3
forbid — a regex cannot know which value a schema describes, and every guess typechecks. so the
forward fix is the guard's own prescription: **make the silent guess LOUD**, not smarter.

if the wisher wants a full AST codemod that safely unwraps the contract, that is a separate, larger
build — a clean rework on top of this, not a teardown of it.

## what landed

**both codemods now prepend a `@declapract:review` marker** at the point where they make an
un-verifiable value-rewrite, so the consumer sees the manual follow-up in-code instead of only in a
readme they may never open.

- **joi→zod** (`runtime-schemas/bad-practices/joi`): the marker names the THREE silent semantic
  changes the shape-for-shape rewrite makes — optionality flip (a joi-optional field becomes
  zod-required by default), unknown-key policy (`.object()` errored, `z.object()` strips), and date
  coercion (`z.date()` rejects a string). wish row "2" — no longer a silent regex.
- **simple-lambda-handlers** (`node-service`): a handler CALL gets a marker naming the contract
  edits — the sdk input schema describes the request BODY (unwrap the `body` key), and the handler
  reads headers off a separate `rawEvent` (`invoke: async ({ event, rawEvent }) => …`,
  `rawEvent.headers`). this is the literal #594 defect (a rename-only migration answers 400 to every
  request yet typechecks). a standard-handler call gets the lighter schema-split + invoke-context
  marker (no rawEvent). the marker attaches only to a CALL, never an import-only file.

both are idempotent: the marker prepends once (guarded by `!includes('@declapract:review')`), and the
check no longer fires post-rewrite (the joi/slh import is gone), so a second `declapract fix` is a
no-op.
