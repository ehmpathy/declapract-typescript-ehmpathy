### round i009 — the one new nitpick, and why the repair differs from the one proposed

**r6 `arch-hazards-maintenance`:** *"in-place `.sort()` mutates a const array … the fix is to sort a
copy: e.g. `[...items].sort()`"*.

**took the hazard, declined the proposed repair — a better one was available.** the `.sort()` at both
declaration sites was **redundant**, not merely unsafe: `defineExpectedGitignoreContents` already
sorts the union of those lines with the repo's own, so the declaration-site sort fed a second sort
whose result the first re-derives. it changed no output; it only mutated an array on the way past.
(in the rhachet declaration it was a `.sort()` on a **one-element array**.)

so instead of a defensive copy, both were **deleted** and both lists typed `readonly string[]`:

- `[...items].sort()` is a *discipline* — it holds while every future author remembers to spread
- `readonly string[]` is a *constraint* — `.sort()` / `.push()` / `.reverse()` are now compile
  errors (`rule.prefer.prevent-over-correct` ranks "make it impossible" above "catch it early")
- one fewer code path beats one safer code path

this also makes both declarations match `ignoresOrderedForGitignore`, so a reader meets one rule for
all three lists rather than two.

**proof the deletion changed no emitted output** (it is a sort removal, so this is the question that
matters, and it is measured not read): unit **461/461** ✅ — which includes the full-content
snapshots of every declared/settled `.gitignore` variant, so any reorder would have reddened them —
plus integration **64/64** ✅, types ✅, format ✅, lint ✅.

full articulation: `…r006._.taken.by_self.arch-hazards-maintenance.md`.

   which regresses `rule.require.errors-name-the-fix`

   the repo throw a helpful-error class

`UnexpectedCodePathError`) is the **inverse** case: in `bad-practices/` a throw means *skip, no user
reads it*; in `best-practice/` the throw's message **is** the output.

## notes for the next reader

- **git reports the LAST rule that matched.** `git check-ignore -v .agent/.cache/x` still names
  `.gitignore:7:.cache/`, not the explicit line at 5. both match; `.cache/` sorts later, so it
  wins the report. the explicit line is insurance against a `.cache/` re-scope, and its value
  does not show in that output — which is precisely why the integration test asserts **path
  coverage** rather than which rule did the work.
- **the integration test runs in ~5s, not the 90s+ the exemplar warns of.** the `file: '.gitignore'`
  filter narrows the apply. the 10-minute cap is kept anyway: it exists so a future reader is
  never tempted to delete an apply to fit a budget, and the reruns ARE the idempotency proof.
- **`useBeforeAll` hands back a proxy.** a bare string proxy compares as a char-indexed object,
  so `toEqual` fails in a way whose diff is unreadable. wrap the value in an object and reach it
  through a property. this cost one red run.
- **`git check-ignore` needs no file to exist.** it matches a path in a wholly absent tree, dir
  patterns included — verified: `zzz-absent-tree/.cache/x.json` → `.gitignore:7:.cache/`. so a
  gitignore probe must **never** write a scratch file first. an earlier draft did, which made an
  `is*` query mutate the filesystem and let a probe under the symlinked `node_modules` write
  OUTSIDE the temp repo (a stray file was found on disk and removed). the write is now gone and
  the util is a pure, sync query. caught across `r5` → `r7`; the root-cause fix retired both the
  write and the guard i had first built around it.
- **the temp repo's `node_modules` is a SYMLINK to the real one**, so git refuses a pathspec that
  traverses it (*"beyond a symbolic link"*). probe at depth instead — `packages/demo/node_modules/…`
  exercises the same pattern without the symlink in the way.
- **`git check-ignore` CONSULTS THE INDEX by default** — measured, because i first assumed the
  opposite and wrote the assumption into a `.why`:

  | query | result |
  |---|---|
  | tracked `.route/.bouncer.cache.json`, default | exit 1 — **NOT ignored** |
  | the same path, `--no-index` | ignored, by `.route/.gitignore:2:*` |

  so a **tracked** path reports *not ignored*, and the suite's `isPathIgnored(...) === true`
  assertions go **red** on it. that means the #514 case — `.cache/` debug files already committed
  — is covered, and needs no clamp of its own. do not add one.
- **`check-ignore` and `git status` are not interchangeable, but not for the reason you might
  guess.** the real difference is that `isPathIgnored` is a **pure query** about paths that do not
  exist, while `a role boot leaves no trace in git status` materializes the scratch and asks about
  the tree as it stands. both are needed; the second is the wish's own instrument.
- **the test-local operations split across two name regimes, on purpose.** `runGit` and `askUnder`
  sit OUTSIDE the sanctioned verb vocabulary, which mirrors the repo's own precedent in the husky
  and persist-with-rds integration tests (`runGuard`, `read`, `applyForget`); the rule scopes itself
  to `domain.operations/` and dao methods. `getAllStatusLines`, `getAllLinesDuplicated` and
  `isPathIgnored` sit INSIDE it, and so carry the full contract — the `All` cardinality marker
  `get*` demands among it. **an exemption you qualify for is forfeited the moment you opt in.** do
  not "unify" these two halves without that distinction in hand.
- **`[case4]` is the one fixture with NO symlinks, and that is deliberate.** every other case here
  calls `executeApply`, which needs `declarations` and `node_modules` mounted at the temp root.
  `[case4]` never calls it — it runs git alone. and a copied-in `node_modules` link would be worse
  than idle in *this* case specifically: it is the case whose whole subject is git pathspec
  behavior, and that link is the trap the note two bullets above documents. the **clone** stays,
  because the oracle this case guards is the one every other case uses, and they use it inside a
  cloned repo that carries its own `.gitignore`.

### ⚠️ the gerund hook false-positives on plain nouns

`forbid-gerunds` matches **any** word that ends in `-ing`, so it blocks ordinary nouns and
prepositions that carry no gerund sense at all. it blocked me on `thing`. the guidance from the
human: **reword around it, do not fight it.**

| blocked word | not a gerund — it is… | what worked instead |
|---|---|---|
| `thing` | a plain noun | `item`, `piece`, `one` |
| `nothing` | a pronoun | `not one`, `none` |
| `during` | a preposition | `across`, `through`, `over` |
| `warning` | a noun (the notice) | `caution`, `the note` |
| `finding` | a noun (the result) | `the catch`, `the result` |
| `bearing` | a noun (the direction) | `the direction` |
| `coupling` | a noun (the joint) | `the seam`, `the join` |
| `being` | a copula form | recast the clause |
| `anything` | a pronoun | `one line`, `a thing` (also blocked), `any of it` |
| `including` | a preposition | `among them`, `namely`, `such as` |
| `doing` | a verb form, not a noun | recast — `carried`, `at work` |

the separate `forbid-terms.blocklist` hook is a distinct list — it blocks `existing` (use
**extant**), `helpers` (use **utils**), `dryrun` (use **plan**), `script` (use **skill**).

these two hooks fired together often enough that a paragraph is faster to rewrite than to argue
with. budget one reword per artifact.

    top rung was available: one operation that applies the env internally and offers no way to opt
    out. **when the breach of an obligation is invisible, the obligation must become a shape.**

14. ***can this clamp go green for the WRONG reason?*** — r8 gap 16. i had been careful that every
    clamp goes red for the right defect, and never asked the mirror question. an absence-shaped
    assertion (`toEqual([])`, `not.toThrow`, `not.toContain`) is satisfied just as well by a world
    where the setup silently did no work at all. measured: with the role-boot scratch redirected to
    `.zzz-INJECTED/`, the wish's criterion-4 clamp went **✓ green vacuously**, and only its
    companion caught it. **an absence-shaped assertion owes a companion that proves the scenario
    actually happened.**

13. ***does my ORACLE inherit host state?*** — r8 gap 15. every path clamp here rests on
    `git check-ignore`, and git folds in `core.excludesFile` from the host's global gitconfig.
    `.cache/` is a very common entry there, so on such a machine the clamps pass no matter what the
    practice declares — a **false green**, which is worse than a false red because no one
    investigates it. **a clamp is only as hermetic as the oracle it asks.**

12. ***do i probe the happy configuration, or the hostile one?*** — the single root behind three
    separate failures this round. gap 6: an mtime proxy that stayed green under two injections.
    gap 13: a rationale that was the inverse of measured truth. gap 15: `askUnder(envGitHermetic)`,
    which could not fail on a clean host because the key it guards is absent there anyway. **a
    guard must be asked its question under the conditions it exists to survive**, or it measures
    the absence of the threat rather than its own strength.

11. ***would this rationale survive a reviewer who read it beside the diff?*** — r8 gap 12. i wrote
    an articulated non-issue that said the git declaration's bare `check`/`fix` were out of bounds
    per the vision's move-1 fence. by then i had already edited that file four times. **an
    articulated absence is where a rationalization hides best**, because the guard asks me to
    justify absences and a fluent justification reads exactly like diligence. a scope fence bounds
    new behavior; it does not exempt a file from a blocker once you are inside it.

10. ***does this `.why` assert how a TOOL behaves? then it owes a command.*** — r8 gap 13. i wrote
    that `check-ignore` and `git status` diverge on a tracked path, reasoned rather than measured,
    and it was the exact inverse of the truth (`check-ignore` consults the index). an assertion
    owes an injection; **a rationale that makes a factual claim about tooling owes a run.** the
    same discipline, applied to prose instead of code.

9. ***what obligation does this clamp create, and where does that obligation live?*** every clamp
   tells some future maintainer *"you must now do X."* r8 gap 7 said *"self-apply every line you
   add"* and documented it nowhere — so it would surface as a red test in a file the author never
   touched, and the cheapest response to a puzzling red is to delete it. **a clamp that changes a
   workflow ships with the sentence that explains the workflow.**

8. ***when a new axis appears, re-run the whole sweep along it.*** gap 9 turned up the step axis
   by accident and the reflex was to patch the one cell exposed — which is how gaps 1–3 happened
   in miniature. the deliberate sweep (gap 10) found two more empty cells at once. **a new axis is
   owed a sweep, not a patch.**

7. ***is the check placed where it can observe what the fixture does?*** — the grid is
   **subject × grain × step**, not two axes. r8 gap 9: `[case1]`'s leak check was present, named
   right, at the right grain — and sat at `[t1]`, one step before the second practice applies. it
   stayed green under an injected leak that turned `[case2]`'s red. **presence is not placement.**
   a check on a produced artifact belongs after each step that produces it, not once per fixture.

6. ***what defect does this test go red for?*** — not *"is there a case for this?"*. r8 gap 8
   found a pre-extant case named `should not duplicate node_modules negations if already present`
   that **passes with `dedupe` deleted**: the ordered tail is filtered out before the sort and
   appended after, so it never reaches `dedupe`. every review round had read that name as dedupe
   coverage. **a test whose name describes a property it does not exercise is worse than an absent
   test**, because it answers the coverage question wrongly and the sweep moves on.

and the sharpest correction of the whole pass, from r8 gap 6: **a lesson recorded is not a lesson
applied.** question 2 above — *does the assertion ask the oracle, or a stand-in for it?* — was
authored in r5. two rounds later i answered a gate-clause claim with a filesystem proxy (mtime)
instead of the oracle (`check` itself), and it stayed green under two separate injected defects.
only the teeth run caught it. so the teeth pass is not a formality at the end of the work; **it is
the step that audits the work, above all the parts you were most confident about.**

and one correction to how i use the teeth rule. gap 3's `.note` was authored from prediction
(*"this assertion is the only one that goes red"*); the injection produced **five** failures. the
run is not merely a check that the clamp bites — **it audits what you believed about the clamp**.
a prediction recorded as an observation is a defect with no line number of its own.
