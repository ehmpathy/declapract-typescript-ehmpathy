# bad-practice: stale-patched-dependency

## .what

a `pnpm.patchedDependencies` entry (and its `patches/<name>@<version>.patch` file) whose pinned
version the lockfile no longer resolves.

## .why it is bad

a patch pins one exact version. the next upgrade of that dependency orphans it: the patch
applies to no install. without `pnpm.allowUnusedPatches` pnpm refuses the whole install
(`ERR_PNPM_UNUSED_PATCH`); with it, pnpm warns on every install. either way the patch is dead
weight that a human must notice and retire by hand.

## .the fix

drop each stale key from `pnpm.patchedDependencies` (and an empty map left behind), and delete
the patch file. the verdict keys off the lockfile-resolved version, so:

- no `pnpm-lock.yaml` → no verdict; no patch is judged stale
- a range key (`name@^1.0.0`) or a bare name key (`name`) → never judged stale
- the fix is a fixed point: once the stale keys are gone, the check no longer detects the pattern
