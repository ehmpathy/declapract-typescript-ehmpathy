# 🌙 dream: sql-schema-control connects with verified TLS

kind: reseed · owner: ehmpathy/sql-schema-control · caught 2026-10-14

## .the cue that fired

lane L1a of `v2026_09_29.fix-absorb-recent-upgrade-reports` gave every runtime pg `Client` a
verified-TLS `ssl` option (#652: `asDatabaseClientSsl` + the us-east-1 RDS CA bundle). schema
provision runs through sql-schema-control, which takes no `ssl` option, so it alone still connects
without verified TLS.

## .the gap, precisely

sql-schema-control's connection config has no `ssl` field to pass through to its pg client. a
cluster that enforces `rds.force_ssl` refuses the provision run, and one that does not lets the
provision run go unverified.

## .the shape of the fix

accept an `ssl` object (pg's `ConnectionOptions['ssl']`) in the connection config of
`sql-schema-control.yml` and pass it to the pg client; a test against a TLS-required postgres.
then the persist-with-rds practice passes `asDatabaseClientSsl` output into its schema config.

## .why it is not done in this round

it lives in another repo (route seed S5: no work in other repos).
