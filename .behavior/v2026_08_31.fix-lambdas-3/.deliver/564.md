## the defect — a guard demands AWS_PROFILE, its error blames the wrong place

both aws jest envs (`jest.integration.env.ts`, `jest.acceptance.env.ts`) throw when an
awsAccountId repo runs tests without `AWS_PROFILE` in env. keyrack.source is meant to set it from
the consumer's `.agent/keyrack.yml`. when that manifest never declares AWS_PROFILE, keyrack sets no
key and the guard fires — with the error `'AWS_PROFILE not set. keyrack.source() should have set
it.'` that error names NO fix and blames keyrack.source (which did its job). a consumer reads it and
has no path forward but to grep kin repos.

## the scope realization — no keyrack.yml template ships here, so the fix is the message

the ticket's proposed fix is "declare AWS_PROFILE in the aws-scoped practice's keyrack fragment."
that fragment has no home in this library:

- `glob src/practices/**/keyrack*` → 0 files. no practice ships a keyrack.yml template.
- `.agent/keyrack.yml` at the repo root is GITIGNORED (a consumer-local file, 219B, absent from
  `git ls-files`). the guard reads it at the CONSUMER's cwd
  (`join(process.cwd(), '.agent/keyrack.yml')`), never from a shipped template.

so the practice cannot ship the consumer's manifest. the fix-forward is `errors-name-the-fix`: the
guard tells the consumer PRECISELY which key to declare, where, and under which env — so every aws
consumer inherits one coherent guard+message instead of re-deriving it from an opaque credential
miss.

## the fix — extract a pure, clamped reader whose error names the key (both envs)

matches the #586/#589 pattern (extract → pure injectable → clamp → wire both envs):

- added `getOneAwsSsoProfileFromEnv({ env })` to `best-practice/useKeyrack.ts`, beside the #586
  aws-creds operations. it reads `env.AWS_PROFILE` or throws a `ConstraintError` (exit 2,
  caller-must-fix) whose message NAMES the fix: *"declare it in .agent/keyrack.yml (under env.test,
  and env.all so every tier sources it), so keyrack.source() can set it."*
- wired BOTH `jest.integration.env.ts` and `jest.acceptance.env.ts` to it — the inline
  bare-`Error` throws are gone. one guard, one message, both envs (the #586 "guard once" principle).
- `env` is injected, so both the present and absent paths are clamped without a real process.env
  read.

## clamp — useKeyrack.declapract.test.ts (+4 tests, 7 → 11)
