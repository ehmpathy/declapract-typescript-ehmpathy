# 🌙 dream: a practice-scoped `executeApply` costs minutes, so integration tests time out under load

- kind = reseed (owner: `ehmpathy/declapract`)
- caught 2026-10-14, route `v2026_09_29.fix-absorb-recent-upgrade-reports`

## .the cue that fired

`tests-any/bad-practices/old-acceptance-dir-location/.declapract.integration.test.ts` timed out at
240s in a full `--thorough` integration run (125 suites in parallel), yet passed alone in 158s.

## .the gap, precisely

- one `executeApply({ practice: 'tests-any' })` over a 6-file demo repo takes ~2-3 min alone
- a move of the `src` symlink to a dot dir (so adopter-file globs skip this repo's tree) cut only
  ~20% (158s → 124s), so the tree walk is not the bulk; the whole-practice evaluation is
- every apply-pipeline test in this repo pays that cost, so the suite's wall-clock and its
  timeout margins both scale with it

## .the shape of the fix

profile `executeApply` in declapract: where a `file` or `practice` filter is given, evaluate only
the declarations that can match it, and cache the parsed practice tree across calls in one process.

## .why it is not done in this round

the cause lives in `ehmpathy/declapract`, another repo (S5: no work in other repos this round).
this round raised the one test's bound to 480s, with the measured times in its comment.
