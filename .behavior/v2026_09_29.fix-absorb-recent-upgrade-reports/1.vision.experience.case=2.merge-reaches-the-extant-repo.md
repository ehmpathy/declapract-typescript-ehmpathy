# case=2 — a merge fix reaches the repo that filed it

critipath · feel: happy · cells: A=reporter × B5 × C2 × D1, A=adopter × B1 × C3 × D1, A=system × B5 × D1 · issues: #639, #608, #657, #685, #689 (and #647 by C1; #665 restates #639 + #647)

## .narrative

rhachet-brains-fireworksai filed #639: `test:lint` fails on every laptop with an enrolled actor,
since depcheck walks `.agent/.actors/` and finds a plugin cache that imports `claude-code`.

the trap: `.depcheckrc.yml` is a CONTAINS check whose fix fn merges only `ignores`. a template edit
alone reaches new repos and never the reporter — whose file already exists.

after: the fix fn merges `ignorePatterns` the way it merges `ignores` — seeds the key if absent,
adds each absent entry, keeps comments. the reporter runs its next upgrade; its extant
`.depcheckrc.yml` gains `.agent/.actors` beside its own entries — that entry is the fix. ci's lint
job also runs `prepare:rhachet` first, so ci lints the linked `.agent/repo=*` role tree a laptop
carries; that closes a neighbor gap, not this one — `.agent/.actors/` is made by a live session, so
ci still never holds it, and only the ignore entry guards it.

the jest half (#647) needs no merge: the six jest configs are whole-file templates, so the next
apply lands the `!**/.agent/.actors/**` negation for free.

the same trap, at the job grain (#608): the expo usecase carried provision-github's migration and no
`provision.yml` caller to run it. an EQUALS template would reach the expo repo, and delete any other
provision job it holds. so the expo practice declares `provision.yml` with a fix that replaces only
the `github` job, drops only a job that still points at `provision/github/`, and keeps every other
job as it stands.

the service usecase had the same hole and a sharper symptom (#685). its `provision.yml` caller was
CONTAINS with no fix, so `apply` reported automatic and changed no byte. the callees went oidc-only,
so a pre-oidc caller failed at github with `startup_failure`, which `gh pr checks` does not show. now
the same merge-by-job helper replaces each declared job and keeps the repo's own.

and the rhachet boot.yml (#689): a repo that moved the glossary variants to `not:` met a check that
reverted them to `ref:`. now the findsert seeds `not:`, moves a declared glob out of `ref`, and keeps
the repo's own `ref` entries, at the rhachet floor that reads `not:`.
