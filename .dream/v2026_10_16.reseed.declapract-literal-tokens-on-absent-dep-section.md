# 🌙 dream: declapract writes a declared dep block as literal tokens when the repo lacks the section

- kind = reseed
- owner = ehmpathy/declapract
- caught 2026-10-16, on route `.behavior/v2026_09_29.fix-absorb-recent-upgrade-reports`

## .the cue that fired

`rhx declapract.walk --usecase lambda-service-with-rds` failed at `pnpm install` on a bare repo:
its `package.json` held `"@declapract{check.minVersion('x').ifInstalled()}"` as a literal version.

## .the gap, precisely

- a consumer `package.json` with NO `dependencies` / `devDependencies` key
- the apply of a best-practice `package.json` (CONTAINS) writes the whole declared section verbatim
- so every `ifInstalled()` floor, which should be omitted when the dep is absent, lands as a literal
  `@declapract{...}` token, and the install fails
- with the section present but empty (`"dependencies": {}`), the engine omits each `ifInstalled()`
  floor and writes each `minVersion()` floor as its check expression, as designed

the walk fixture and `src/.test/assets/typecheck-templates/repo-bare/package.json` both declare
empty sections to avoid it.

## .the shape of the fix

in declapract's package.json fix (the `check.minVersion` / `ifInstalled` evaluation), treat an
absent section as `{}` before the merge, so an absent section and an empty one produce the same
output. a unit case: declared `{ devDependencies: { a: "@declapract{check.minVersion('1.0.0').ifInstalled()}" } }`
against `{ name }` must emit no `a`.

## .why it is not done in this round

it lives in ehmpathy/declapract, and this route does no work in other repos (S5). safe, but not
clean: it ripples into another repo's release.
