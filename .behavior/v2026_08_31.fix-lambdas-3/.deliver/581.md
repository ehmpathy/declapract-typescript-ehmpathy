## the ask, and why the original #547 framing was wrong

#547 asked `.dpdmrc.yaml` to MERGE repo excludes rather than clobber with `exclude: []`. #581
corrects that: `exclude: []` is DELIBERATE org policy, not an oversight. per
`rule.forbid.dpdm-exclude-change` (in rhachet-roles-ehmpathy), an empty exclude means dpdm checks
ALL files for cycles — node_modules INCLUDED — because a prod-dep cycle ships to consumers. adding
`node_modules` to the exclude is a BLOCKER in every governed repo. so the template is behaviourally
correct today; the defect is that the empty state reads as accidental.

## the hazard — an accidental-looking empty list invites a silent-disable tidy-up

the lint command renders `--exclude "$(yq -r '.exclude | join("|") // "^$"' .dpdmrc.yaml)"`. with
`exclude: []`, `join("|")` yields `""` (dpdm's include-all value) — the right result, reached by a
path no one wrote down. the old comment read "excludes are rarely needed", which suggests its
author believed the empty list was a no-op. it is not — it IS the policy. a future maintainer who
"fixes" the empty list toward dpdm's own `/node_modules/` default would silently disable the org's
cycle policy across every consumer repo.

## the fix — make the empty state deliberate (behavior unchanged)

rewrote the `.dpdmrc.yaml` comment to state the policy outright: `exclude: []` means all files
checked, node_modules included, ON PURPOSE (`rule.forbid.dpdm-exclude-change`); a ⚠️ note forbids
adding `node_modules`/`^node_modules` or "fixing" toward dpdm's default; a devDep MAY be an escape
hatch, a prod dep MUST NOT.

the lint command's `// "^$"` fallback is KEPT — it protects the null/absent-file case (jq's `//`
catches the `null | join` error and renders `--exclude "^$"`, which also excludes no path). the
ticket's option-1 "drop the fallback" was declined: keeping it is strictly safer, and behavior is
identical either way. no repo-specific devDeps were seeded (they differ per repo; the empty default
is universal).

## the clamp — dpdmrc-exclude-policy.declapract.test.ts (lint root, 3 tests)

parses the shipped `.dpdmrc.yaml` (via `yaml`) and asserts the `exclude` VALUE is an array, is
empty (the policy), and holds no `node_modules` entry. it parses the value rather than the file
text, so the ⚠️ `node_modules` mention in the comment does not false-match.

teeth confirmed: add `^node_modules` to `exclude` in the template and the "empty" + "no
node_modules" assertions go RED (2 failed). restored → 3 GREEN. the clamp sits at the practice
ROOT, so declapract never emits it.

## bounds

- this makes the empty state deliberate + guarded; it does NOT change what dpdm checks (still all
  files, deps included). the 71-cycle red gate the ticket describes is a TRUE report of real
  prod-dep cycles (57 of 64 trace to aws-sdk v2) — that eradication is a consumer's dep-migration
  work, not a template defect, and is out of scope here.
- #547's merge-excludes ask is superseded by this correction: the empty list must stay empty.
