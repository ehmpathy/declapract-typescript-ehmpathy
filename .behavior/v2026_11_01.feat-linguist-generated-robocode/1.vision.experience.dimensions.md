# 1.vision.experience.dimensions

the experience space of linguist-generated entries, factored into orthogonal axes. every value set is closed.

## .actors

| actor | encounter |
|---|---|
| `reviewer` | reads a pr's diff on github |
| `adopter` | runs `declapract apply` in a consumer repo |
| `measurer` | runs the pilot (the wish's two numbers) |
| `author` | pushes the pr; reads diffs locally |
| `maintainer` | keeps this repo on its own practices, via its repo skills (`rhx declapract.self.apply`, `rhx git.attr.get`) |

## .reviewer axes

one value decides the fold: the **effective attribute** git computes for the path (`set` → folded; `unset` / `unspecified` → open). that value is a function of axis M alone. axes K and N do not change the fold. they decide whether the fold is safe.

| axis | values (closed) |
|------|--------|
| **M. matched line** (last line that matches the path) | `collapse-line` (a line that sets `linguist-generated`: managed, or a repo-own line that folds the repo's own generated code) · `exception-line` (a managed `-linguist-generated` line: route yields, route radio) · `repo-override` (a repo-own `-linguist-generated` line that negates a managed path, last in the file) · `no-line` (no line matches: snapshots, domain source, all paths outside every declared glob) |
| **K. companion** (does an open file prove what this one changed?) | `derived` (the file derives from an open source: dao output from the domain object, route trail from route templates + the open yields) · `snap-proven` (an open `.snap` shows its effect: a test whose assertions feed a snapshot) · `test-no-snap` (a test with no snapshot: no open proof of its effect) · `hand-src` (hand-written source under a folded glob: a hand-written dao query, a route's `0.wish.md`) |
| **N. change nature** | `additive` (new lines, intent kept) · `regen` (a mechanical rewrite: generator rerun, codemod) · `weakened` (a deletion that drops a guarantee: an assertion, a where-clause) |
| **F. surface** | `pr-view` (files tab and compare view: one renderer, Q9) · `local-git-diff` · `language-stats` · `github-code-search` |

## .adopter axes

| axis | values (closed) |
|------|--------|
| **C. repo-own content** (what the file holds beside managed lines, before the run) | `absent` (no file) · `git-block-only` (managed lines only, as any version shipped them: the untagged prior template, a legacy header with its typo, or the current tagged sections) · `repo-own-lines` (plus repo lines that negate no managed path, incl a repo-own fold of its own generated code) · `repo-override` (plus a repo line that negates a managed path) · `hand-dup` (plus a repo line identical to a managed one) · `repo-tag` (plus a section the repo heads with a `# [tag]` of its own) |
| **C′. override layout** (a sub-axis of C = `repo-override` only) | `own-block` (the override sits in a repo-own block, after a blank line: the layout every apply emits) · `glued` (a human wrote the override under a foreign tagged section, no blank line between, so it reads as part of that section) |
| **L. line ends** | `lf` · `crlf` (the file was saved with windows line ends) |
| **D. declarer set** | `all-declarers` (git, tests-any, rhachet, persist-with-rds) · `no-persist` (git, tests-any, rhachet: npm-package, expo, this repo) · `dynamodb` (persist-with-dynamodb in place of rds) · `rds-and-dynamodb` (both) |
| **E. run** | `first` (managed sections absent or behind; incl a usecase change that adds a declarer, whose section is then absent) · `re-apply` (managed sections current) · `upgrade` (a declarer adds a line) · `declarer-dropped` (a usecase change removes a declarer) |
| **H. fix order** | `one-pass` · `interleaved` (declarers fix the file in turn) |

## .measurer axis

| axis | values (closed) |
|------|--------|
| **P. method** (how the pilot samples a review) | `same-diff-twice` (one pr, read before and after) · `two-prs` (two prs of similar shape, one per render) · `two-reviewers` (one pr, one reviewer per render) |

## .maintainer axes

| axis | values (closed) |
|------|--------|
| **S. skill** | `self.apply` (apply one practice to one file of this repo) · `attr.get` (ask git which value an attribute takes per path) |
| **O. outcome** | `success` · `constraint` (bad input, no repo, no config: the caller fixes it, exit 2) · `malfunction` (a git, build, apply, or diff step failed, exit 1) |

## .orthogonality

- **reviewer:** M, K, N vary freely. a test (`snap-proven` or `test-no-snap`) can sit under `collapse-line` or under a `repo-override`. a weakened change can land in any file. M alone sets the fold; K × N grade the risk of the fold. F is orthogonal to all three: each surface reads the same effective attribute.
- **adopter:** C, D, E vary freely. a declarer that joins later is E = `first` for its own section, by definition: the util emits every section from the declarer set alone, so a joined declarer's section lands as on a first apply. so `declarer-added` is merged into `first` deliberately, not left unwalked. H is orthogonal by construction: one shared util emits the whole file, so the order of declarer fixes must not change the result. that is invariant inv1, not a free axis.
- **maintainer:** S and O vary freely; each skill has every outcome. the maintainer walks the adopter path on this repo itself (dd2), so the two products meet in one cell and stay walked apart.
- **reviewer ↔ adopter:** the adopter's C (a `repo-override`) feeds the reviewer's M. the link is one-way and lives in one value (`repo-override`), so each product walks on its own, and case=4 demos the link.

## .the walked product

### reviewer — M (4) × K (4) × N (3) × F (4) = 192 cells

- **open values of M** (`exception-line`, `repo-override`, `no-line`): the file renders open, so the reviewer reads every line whatever K and N are. K × N cannot change the experience; merged deliberately into one row per M value. 3 rows.
- **M = `collapse-line`**: K × N = 12 cells, each its own row, since here K and N decide whether the fold is safe.
- **F**: `pr-view` carries the 15 rows above. `local-git-diff` folds no cell (git ignores linguist): one row. `language-stats` excludes every `collapse-line` cell, whatever K × N: one row; it counts every open-M cell as before: one control row. `github-code-search` may drop every `collapse-line` cell, and the cost depends on K: 4 rows; it finds every open-M cell as before: one control row.

= 15 + 1 + 2 + 5 = 23 reviewer rows, each a verdict.

### adopter — C (6) × E (4) × D (4) × L (2) = 192 cells

- **C × E** = 24 rows, each its own verdict.
- **L** changes only how the file is read: the util splits on either line end and emits `lf`. so each C × E verdict holds for both values (merged deliberately); `crlf` gets one row of its own.
- **D** changes which sections the file holds; the util's order and convergence logic does not read which sections exist. so each C × E verdict holds for every D (merged deliberately, argued here). D gets 4 rows of its own for section content.
- **C′** splits only C = `repo-override`. `own-block` is ad13–ad16. `glued` behaves as `own-block` for `first`, `re-apply`, and `upgrade` once the owner runs (merged into one row, ag1); only `declarer-dropped` of the owner differs (ag2). 2 rows.
- **H** is one invariant across all 192 cells (inv1).

= 24 + 4 + 1 + 2 rows + 1 invariant.

### maintainer — S (2) × O (3) = 6 cells

6 rows, each a verdict.

### measurer — P (3)

3 rows. the lines-open proxy is computed under every method, so it is no axis.

### author

one cell: the author's surface is local git, which cannot fold (rs1).

every row is verdicted in `1.vision.experience.case=_.md`.
