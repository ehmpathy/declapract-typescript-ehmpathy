# bad-practice: npm-overrides

## .what

a package.json that keeps its dependency pins under a top-level `overrides` (npm) or
`resolutions` (yarn) key.

## .why it is bad under pnpm

pnpm reads **neither** `overrides` nor `resolutions` — it reads `pnpm.overrides`. a repo
migrated from npm/yarn that leaves its pins under the old keys silently loses them. under
the hoisted linker (flat `node_modules`) that lets a mismatched transitive version hoist
over the intended one — the skew hazard documented in
`.agent/repo=.this/role=any/briefs/howto.pnpm-expo-hoisted-linker.md`.

## .the fix

relocate both top-level keys into `pnpm.overrides` and drop them. on a key collision the
precedence is: npm `overrides` beats yarn `resolutions` beats any pre-extant
`pnpm.overrides`. idempotent — once relocated, the check no longer detects the pattern.
