## the defect (as filed) — a case-mismatched grep that never matches

the ticket reported `.declastruct.yml`'s apply-gate greps a capital-lead `Everything is in sync`,
while declastruct emits the marker LOWERCASE (`🎉 everything is in sync!`,
`planChanges.ts:159`). grep is case-sensitive, so the in-sync fast path was dead code — every plan
fell to the has-changes-planned=true arm. it fails SAFE (over-gates), so no alarm ever fired.

## the ground read — the case-bug is already ABSENT in this repo, but the grep was loose

⚠️ verified against the current tree: `.declastruct.yml` is now practice-managed (cicd-common ships
it, per define.declastruct-goforward), and its grep already read `grep "in sync"` — which MATCHES
the lowercase marker (the phrase `in sync` occurs in it). so the "never matches" defect the ticket
names is not present here. what remained was the ticket's recommended fix.

## the fix — apply the ticket's `-qF` + full-phrase form, tied to the tool's marker

`.github/workflows/.declastruct.yml`:

```yaml
if grep -qF "everything is in sync" ./plan.log
```

- `-F` fixed-string (no char read as regex)
- `-q` quiet (the exit code is the whole signal — no matched line sprayed to stdout)
- the FULL phrase (not the bare `in sync` fragment), so an unrelated line that holds `in sync`
  cannot false-match
- lowercase, to match what declastruct actually emits
