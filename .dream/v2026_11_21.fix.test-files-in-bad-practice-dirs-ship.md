# 🌙 dream: keep integration tests and their snapshots out of bad-practice dirs

kind: fix · owner: declapract-typescript-ehmpathy · caught 2026-11-21

## .the cue that fired
the 5.3 snapshot review of the ts7 pr read an adopter's plan snapshot. it listed `[NO_CHANGE] tsconfig.json.declapract.integration.test.ts` and `[NO_CHANGE] __snapshots__/…snap`: test files of a bad-practice dir, read as declared files. the ts7 pr moved its own three to the practice root. extant ones remain.

## .the gap, precisely
- declapract reads every file in a declaration dir as a declared file. compile strips only `.declapract.test.ts` and its `.snap` (`define.declapract-test-files`), so a `.declapract.integration.test.ts` and its `.snap` in a bad-practice dir ship in `dist/`, and every adopter plan lists them
- extant: `bottleneck/bad-practices/bottleneck/package.json.declapract.integration.test.ts` (+ its `__snapshots__`), `pnpm/bad-practices/package-lock-json/package-lock.json.declapract.integration.test.ts`
- `src/practiceTestFileLocation.declapract.integration.test.ts` scans `best-practice/` only, so no clamp catches the bad-practice case

## .the shape of the fix
- move each extant integration test (and its snapshot) to its practice root, named `<bad-practice>.declapract.integration.test.ts`, its import pointed back into the dir
- widen `practiceTestFileLocation` to redden on any `.declapract.integration.test.ts` or un-stripped `__snapshots__/` file under `bad-practices/` too
- once `ehmpathy/declapract#109` strips the integration variant at compile, the clamp may relax for both dirs

## .why it is not done in this round
the extant files belong to the bottleneck and pnpm practices, which this pr does not touch. their noise is `[NO_CHANGE]` lines, which ship no harm. the ts7 pr fixed only its own files.
