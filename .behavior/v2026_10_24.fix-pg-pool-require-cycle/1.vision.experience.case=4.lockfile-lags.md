# case=4: an adopter whose lockfile pins an older pg-pool

covers inventory #4, #5, #6, #32.

proof: `pg-pool-patch.declapract.integration.test.ts` `[case2]` installs each of the 24 stable releases in
`^3.2.1` with the shipped patch, and asserts no `require('pg')` lands. the "cycle check exits 0" steps below follow
from that content: `[case6]` proves a pg-pool with no `require('pg')` passes the shipped check. no test runs
`test:lint:cycles` per release.

## narrative

sam owns a service whose `pnpm-lock.yaml` still pins pg-pool 3.6.0; nobody re-locked in a year. sam upgrades the
practice and runs `npx declapract apply`, then `pnpm install`. the lockfile keeps 3.6.0, where the `this.Client`
line sits at another line number than in 3.14.0. pnpm applies the hunk at that offset, with no warn. `npm run
test:lint:cycles` exits 0. sam never learns the lockfile lagged.

sam's teammate owns a second service with the same lag. its map already holds `"other@1.0.0"` (#5): the apply keeps
it, and the outcome is sam's. a third service holds its own `"pg-pool@3.6.0"` key from an old hand patch (#6): pnpm
picks that exact key first, it fits 3.6.0 by construction, and lint is green; the shipped bare-name key waits, unused,
for the next re-lock.

if pnpm cannot apply the shipped hunk at the offset, #4 and #5 take case=3's path: a warn that names
`patches/pg-pool.patch`, a red lint, and the file's header names the fix. #6 does not, since its own exact patch
applies. the vision owes a check in execution of which path 3.6.0 takes.

## bdd sketch

```
given('[case4] an rds repo whose lockfile pins pg-pool 3.6.0, with an empty patch map')
  when('[t0] declapract apply, then pnpm install (lockfile kept)')
    then('the install exits 0 with no patch warn')
    then('node_modules/pg-pool/index.js holds no require(\'pg\')')
  when('[t1] npm run test:lint:cycles')
    then('the cycle check exits 0')

given('[case4.other] the same repo, whose map holds "other@1.0.0"')
  when('[t0] declapract apply, then pnpm install')
    then('"other@1.0.0" is untouched, and the outcome matches [case4]')

given('[case4.own] the same repo, whose map holds "pg-pool@3.6.0" with its own patch')
  when('[t0] declapract apply, then pnpm install')
    then('pnpm applies "pg-pool@3.6.0" first; the bare-name key is outranked')
    then('stale-patched-dependency leaves "pg-pool@3.6.0" in place, since the lockfile still holds 3.6.0')
  when('[t1] npm run test:lint:cycles')
    then('the cycle check exits 0')

given('[case4.own+other] the same repo, whose map holds "pg-pool@3.6.0" and "other@1.0.0"')
  when('[t0] declapract apply, then pnpm install')
    then('both repo keys are untouched; pnpm applies "pg-pool@3.6.0" first')
  when('[t1] npm run test:lint:cycles')
    then('the cycle check exits 0')
```
