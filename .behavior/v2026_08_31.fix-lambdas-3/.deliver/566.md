## the defect — the timestamp hook halts on iso durations, which cannot permadrift

`.husky/check.timestamps.sh` halts a commit on any match of
`T?HH:MM:SS(Z|±HH:MM)?`. that pattern is too broad: it also fires on iso-8601 DURATIONS
(`PT12:30:00`, `P1DT02:15:30`, `P3Y6M4DT12:30:05`), which are fixed spans, not instants — they do
not change between runs, so they cannot permadrift and are legitimate, stable values to assert on
in a snapshot. a false halt on durations trains folks to bypass the hook, which guts the real
timestamp rule.

## the fix — matcher precision only: strip durations before the scan

added a `DURATION_PATTERN` and strip iso durations from the staged content BEFORE the timestamp
scan (via `sed -E`, which is line-by-line so grep's line numbers are preserved):

```sh
DURATION_PATTERN='P([0-9]+[YMWD])*T([0-9]+[HMS])*[0-9][0-9]:[0-9][0-9]:[0-9][0-9]'
match=$(printf '%s\n' "$content" | sed -E "s/$DURATION_PATTERN//g" | grep -nIE "$TIMESTAMP_PATTERN" | head -n 1)
```

the distinct signal: a duration carries a lead `P` designator and a `T` with NO date part; a
timestamp carries a date (`2026-08-08Thh:mm:ssZ`) or is a bare `HH:MM:SS`. so a duration-only line
loses its `HH:MM:SS` run to the strip and falls through; a line that ALSO holds a real stamp still
matches (the stamp survives the strip — it has no `P` to strip).

per the ticket's scope guard, this is a MATCHER-PRECISION change only — the file scope is unchanged
(every staged file except `*.ts`/`*.sh`); no snapshot-dir or `.md` exemption was added.

## clamp — check.timestamps.play.declapract.integration.test.ts (+4 cases, 11 → 15 tests)

the play-based integration clamp spawns the real hook against a temp git repo. added:
- `[case9]` `PT12:30:00` → exit 0 (allowed)
- `[case10]` `P1DT02:15:30` → exit 0 (allowed)
- `[case11]` `P3Y6M4DT12:30:05` → exit 0 (allowed)

the extant halt cases (real iso stamp, bare time, tz-offset) and exempt cases (.ts/.sh, masked
placeholder, date-only, clean) stay green — the fix narrows only durations.
