# 5.2.followon — the pin has no bump path

> **filed as #556** — `ehmpathy/declapract-typescript-ehmpathy#556`
>
> filed per **Q10** of `1.vision.yield.md`: *"the absent bump path leaves as a filed follow-on, not
> a paragraph."* the wish asks that the pin/CVE tradeoff be **recorded, not solved** — this is the
> record, shaped as a deliverable rather than as prose.

## .what

this behavior pins every third-party action ref to an immutable 40-hex SHA. that reopens CI under
the org's `sha_pinning_required` control. it also, by construction, **freezes** those actions at the
commit each was derived from on 2026-08-06 — and neither this repo nor any template it ships carries
a mechanism that will ever move them again.

## the tradeoff, stated plainly

the honest sentence to a consumer:

> *"your CI works again, and the day one of these actions patches a CVE, no mechanism here will
> tell you."*

before the pin, `@v4` floated: a patched `v4` arrived on the next run, for free and unasked. after
the pin, it does not. that is the whole point of a pin — and the whole cost of one.

## why it does not cure itself

contrast with the pin's **own** staleness hazard. as people touch repos and re-run
`npx declapract apply`, the templates' pins propagate outward on their own. that hazard erodes under
normal work.

this one does not. a frozen SHA stays frozen until someone deliberately moves it. a paragraph in a
vision decays into no one's problem, which is exactly why Q10 was answered **file it**.

## task 1 — the `[research]` question (Q5)

**does dependabot read a `uses: owner/repo@<40-hex> # <tag>` pin and bump BOTH parts — the SHA and
the tag tail?**

⚠️ this is unverified, deliberately. the vision left it open because it steers no decision in *that*
behavior, and the honest place to spend the check is here, where it would actually steer a design.
that deferral expires the moment this wish is picked up.

if the tail is **not** bumped alongside the SHA, the tail turns into a lie on the first automated
bump — and the tail is the whole reason the pin is legible (wish acceptance (c)).

## task 2 — the scope question (Q5, `[wisher]`)

✅ measured: there is **no** `dependabot.yml` and no renovate config anywhere in this repo or in any
template. so an automated-bump path is not a config tweak — it means **a new file shipped into every
consumer repo**.

that is a template-surface decision, not a mechanic's call. it belongs to the wisher.

## the bound this behavior accepted (Q8)

CI does **not** verify each tag tail against upstream. the tail records **provenance** — which
mutable tag this immutable SHA was derived from, on the day it was derived — not a live claim. once
the tag moves, a "version" read of the tail turns false while the provenance read stays true.

an automated-bump path changes that calculus, and should revisit the bound rather than inherit it.

## what this follow-on must NOT quietly absorb

**Q9 is a bigger question and a separate one:** a repo drifted from a practice cannot safely take a
security fix from that practice, because declapract's grain is per-practice, never per-concern — so
"take the security fix only" is not a move the tool offers.

Q9 is routed to the wisher on its own. do not fold it in here; a bump path for *this* repo's
templates does not answer it, and to merge them would bury the larger one.
