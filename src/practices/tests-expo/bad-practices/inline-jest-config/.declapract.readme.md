# bad-practice: inline-jest-config

## .what

a top-level `jest` key in a consumer's `package.json`.

## .why it is bad

an expo app that migrated to jest-expo by hand often carries the jest-expo preset INLINE in
`package.json` AND a `jest.*.config.ts` file at the same time — a dual source of truth. `tests-expo`
declares the jest config as its own `jest.*.config.ts` files (the go-forward home), so an inline
block is redundant and the two configs can fight over the same run.

## .the fix

drop the inline `jest` key. the `jest.*.config.ts` files that `tests-expo` drops are the one home,
so no jest settings are lost — they move to (or already live in) the config files.
