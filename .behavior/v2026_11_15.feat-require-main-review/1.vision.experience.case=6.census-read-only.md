# case=6: the census reads the fleet, read only

feel: happy · care: critipath

## .narrative

the commander wants to know which repos would gain a review gate. the mechanic runs
`rhx github.main-review.census`. it lists each non-archived, non-fork repo across ehmpathy,
ahbode, whodisio, and uladkasach, and verdicts each: requires, lacks, or unknown. every call is a
read: rest GETs and graphql queries. the table lands in the pr body.

the token holds push, not admin, so the classic protection endpoint 404s. the census reads two
signals a push token can read instead:
- an active ruleset `pull_request` rule on main
- the graphql `reviewDecision` of the latest pr into main, which github leaves empty when no
  review is required

a read that fails for any cause but absence halts the census loud, so a rate limit never reads as
a verdict.

## .bdd sketch

```
given a push-scoped token
  when [t0] `rhx github.main-review.census` runs
    then it issues read calls only
    then each repo gets one verdict and the signal behind it
    then the table is kept at .log/github.main-review.census/census.md
  when [t1] a repo's main is unprotected
    then its verdict is `lacks` (main unprotected)
  when [t2] a protected repo has no decisive pr into main
    then its verdict is `unknown`, never a guess
  when [t3] a read fails with a cause other than absence (a 500, a rate limit)
    then it exits 1 with a MalfunctionError that names the repo, the read, and the cause
  when [t4] an owner's repo list comes back empty, or at the list cap
    then it exits 1 with a MalfunctionError, never an undercount
  when [t5] the tally prints
    then each verdict splits by basis: certain vs inferred from a pr's reviewDecision
```

## .proof

`src/practices/provision-github/github.main-review.census.play.declapract.integration.test.ts`
runs the skill against a `gh` stub: [t0] through [t5], plus `--help` and each bad input.
