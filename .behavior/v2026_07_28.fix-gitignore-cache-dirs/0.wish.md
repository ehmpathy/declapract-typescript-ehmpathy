# wish: gitignore the two cache dirs, so `git tree del` can fell a worktree

radio task: ehmpathy/declapract-typescript-ehmpathy#535

## .what

findsert two lines into the declapract-managed `.gitignore` template, so every
ehmpathy typescript repo inherits them:

- `.cache/`
- `.agent/.cache/`

a repo that already carries a line stays untouched — no duplicate line.

## .why

neither dir is tracked nor gitignored today, and both hold pure scratch state:

| dir | written by |
|-----|------------|
| `.agent/.cache/` | rhachet role boots |
| `.cache/` | scratch / debug output |

two costs follow.

**teardown snags.** untracked cruft shows up in every worktree, and `git tree del`
refuses to fell a worktree that holds untracked changes. so every dispatched tree
stalls at teardown on a directory nobody meant to keep. this recurred across the
2026-07 teardowns — it is the single most frequent snag in the dispatch loop.

**secret exposure.** because `.cache/` stayed trackable, debug files under it were
committed and pushed to a PR branch in rhachet-roles-ehmpathy — two held a plaintext
`FIREWORKS_API_KEY`. that is the same root cause #514 documents.

the per-repo workaround (hand-clean before the fell) does not scale, and it
re-appears the next time a role boots. the fix belongs in the template.

## .acceptance

- the declapract-managed `.gitignore` template carries both lines
- an upgrade run against a repo that lacks a line adds it
- an upgrade run against a repo that already carries a line leaves the file byte-identical
  (idempotent — prove it, do not assert it)
- a fresh worktree in an upgraded repo shows a clean `git status` after a role boot

## .scope

gitignore template only.

`#514` covers `.cache/` plus a husky secret-scan hook. this wish takes the **gitignore
half** and widens it to `.agent/.cache/`. leave the **secret-scan half** to #514 — do
not duplicate it here, and do not expand into husky.

## .note on the how

the shape above is the OUTCOME. how the findsert lands in the declapract template —
which file, which practice, the exact mechanism — is yours to settle in-repo. prefer
whatever pattern the template already uses for gitignore lines over a bespoke one.
